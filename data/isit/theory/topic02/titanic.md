# pandas: разбор Titanic

Третье занятие модуля. До сих пор мы работали с одним массивом чисел; теперь —
настоящая таблица пассажиров «Титаника» из лаборатории: 156 строк, 12 колонок,
имя, пол, возраст, класс, цена билета, каюта. Разбираем таблицу вопросами: кто
ехал, сколько их было, кто уцелел, — и отвечаем на них инструментами pandas.

## Зачем

После занятия вы сможете:

- отбирать строки по нескольким условиям сразу и объяснять, почему `and` между
  ними падает, а `&` работает;
- считать доли, средние и размеры групп методами pandas и знаете, чем `mean()`
  таблицы отличается от `mean()` массива из прошлого занятия;
- достать фамилию из поля `Name` и посчитать по ней семьи;
- найти самую частую комбинацию значений и не спутать её с `mode()`;
- написать `is_lucky`, применить её к колонке через `apply` и посчитать долю
  утонувших среди счастливых билетов.

## Отбор и группировка

### Главное

Отбор строк начинается с условия на одну колонку: `df["Sex"] == "male"` — это не
`True`/`False`, а столбец такой же длины, как таблица, с булевым значением на
каждую строку. Такой столбец-маску кладут в квадратные скобки, и таблица
оставляет только строки с `True`.

Условий обычно несколько, и здесь прячется главная ловушка занятия: **условия
соединяют `&` (или `|`), а не `and`, и каждое берут в скобки**. `and` просит у
каждой стороны одно значение истинности, а у столбца значений столько, сколько
строк, — pandas честно отказывается выбирать и падает с
`ValueError: The truth value of a Series is ambiguous`. Скобки нужны потому, что
`&` связывает операнды крепче, чем `==`: без них выражение читается как
`df["Sex"] == ("male" & df["Survived"]) == 1`.

Дальше считающие методы. `isna()` расставляет пропуски, `isna().any()` отвечает,
есть ли они в колонке, `isna().sum()` — сколько их. `value_counts(normalize=True)`
даёт доли значений, `groupby("Pclass").size()` — размеры групп, а
`groupby("Pclass")["Survived"].mean()` — среднее признака внутри каждой группы.

Отдельно стоит запомнить: **pandas пропускает пропуски сам**. На прошлом занятии
`matrix.mean()` по матрице с `nan` возвращал `nan` — пропуск портил сумму. Здесь
`df["Age"].mean()` спокойно считает среднее по известным возрастам (`skipna=True`
по умолчанию): у 30 пассажиров возраст неизвестен, но ответ получается числом.
Старое поведение никуда не делось, оно живёт в numpy: `df["Age"].to_numpy().mean()`
на той же колонке даёт `nan`.

Второй момент — порядок. `value_counts` сортирует по убыванию частоты, а не по
значениям: классы идут `[3, 1, 2]`, потому что третьим классом ехало больше
всего. Если задание требует порядок по классу, нужен `.sort_index()`.

### Пример

```python
import pandas as pd

df = pd.DataFrame({
    "Sex": ["male", "female", "male", "female", "male"],
    "Age": [22.0, 38.0, float("nan"), 27.0, 32.0],
    "Embarked": ["S", "C", "S", "S", "S"],
    "Fare": [7.25, 71.28, 35.5, 7.9, 40.0],
    "Survived": [0, 1, 1, 1, 1],
    "Pclass": [3, 1, 1, 3, 2],
})

chosen = df[(df["Sex"] == "male") & (df["Survived"] == 1)]
print(chosen["Age"].mean())                 # 32.0 — пропуск не мешает
print(df.columns[df.isna().any()].tolist())  # ['Age'] — колонки с пропусками
print(df["Pclass"].value_counts().to_dict())  # {3: 2, 1: 2, 2: 1} — по частоте
print(df["Pclass"].value_counts(normalize=True).sort_index().round(3).to_dict())

try:
    df[df["Sex"] == "male" and df["Survived"] == 1]
except ValueError as error:
    print(error)  # The truth value of a Series is ambiguous...
```

### Частые ошибки

- **`and` вместо `&`.** `df[df["Sex"] == "male" and df["Survived"] == 1]` падает с
  `ValueError: The truth value of a Series is ambiguous`: у столбца нет одного
  значения истинности. Меняйте `and` на `&`, `or` на `|`, `not` на `~`.
- **Скобки забыты.** `df[df["Sex"] == "male" & df["Survived"] == 1]` падает с
  `TypeError`: `&` выполняется раньше `==`, и pandas складывает строку с числами.
  Каждое условие — в своих скобках.
- **`value_counts()` без `normalize`.** Без него метод возвращает штуки, а не
  доли, — и «доля пассажиров третьего класса» превращается в 96 вместо 0.615.
  Заодно помните про порядок: он по частоте, а не по значению.
- **Среднее по массиву вместо среднего по столбцу.** `df["Age"].to_numpy().mean()`
  на данных с пропусками даёт `nan`, а `df["Age"].mean()` — число. Переносить
  привычки numpy в таблицу не нужно: pandas поступает по-человечески.
- **`df.mean()` по всей таблице.** Падает с `TypeError`: усреднять названия и
  порты отправления нельзя. Нужен `numeric_only=True` или — что обычно и нужно —
  конкретная колонка.

## Семьи и частые сочетания

### Главное

Семья в этой задаче — группа однофамильцев, а фамилия лежит в поле `Name` до
первой запятой: `"Braund, Mr. Owen Harris"` → `Braund`. Достаётся она строковым
аксессуаром: `df["Name"].str.split(",").str[0]` — `str` даёт методам строк
работать со всей колонкой сразу. Дальше семьи считаются не по строкам, а по
разным фамилиям: `df["Name"].str.split(",").str[0].value_counts()` — 141 фамилия
на 156 пассажиров.

«Семей, где больше k человек» — это `(value_counts() > k).sum()`. Для k = 0 такое
неравенство верно для всех фамилий, и получается 141; для k = 1 остаются фамилии,
встретившиеся больше одного раза, — их 13; для k = 2 — одна (Andersson, четыре
человека); для k = 4 — ни одной. Обратите внимание: k = 3 тоже даёт единицу —
та же семья Andersson, где людей больше трёх.

Самое частое сочетание значений колонок ищется по размерам групп:
`df.groupby(columns).size().idxmax()` — берём группировку, считаем размеры и
просим метку самой большой. Для `["Survived", "Sex"]` это `(0, "male")` — 86
невыживших мужчин против 40 выживших и 16 невыживших женщин (ещё 14 выживших
мужчин — самая маленькая из четырёх групп); для
`["Embarked", "Pclass"]` — `("S", 3)`, 67 пассажиров. Для одной колонки `idxmax`
возвращает не кортеж, а одно значение (`21.0` — самый частый возраст, 8 человек),
поэтому ответ приводят к кортежу: длина ответа должна равняться числу колонок.

### Пример

```python
import pandas as pd

df = pd.DataFrame({
    "Name": ["Braund, Mr. Owen Harris", "Andersson, Mr. Anders Johan",
             "Andersson, Miss. Sigrid Elisabeth", "Heikkinen, Miss. Laina"],
    "Survived": [0, 0, 1, 1],
    "Sex": ["male", "male", "female", "female"],
})

surname = df["Name"].str.split(",").str[0]
print(surname.tolist())            # фамилия — часть имени до запятой
counts = surname.value_counts()
print(counts.to_dict())            # {'Andersson': 2, 'Braund': 1, 'Heikkinen': 1}
print(int(counts.sum()))           # 4 строки — это число пассажиров, не семей
print(int(counts.size))            # 3 разные фамилии — это число семей
for k in (0, 1, 2, 3):
    print(k, int((counts > k).sum()))

columns = ["Survived", "Sex"]
best = df.groupby(columns).size().idxmax()
print(best if isinstance(best, tuple) else (best,))
```

### Частые ошибки

- **Считать семьи по строкам.** `len(df)` — это пассажиры (156), а не семьи
  (141). Семья — группа одинаковых фамилий, и считать её надо по частотам:
  `(surname.value_counts() > k).sum()`.
- **Взять `Name` целиком.** У каждого пассажира имя своё, так что «семьёй»
  окажется каждая строка: 156 семей из 156.
- **`mode()` вместо группировки.** `df[columns].mode()` ищет моду каждой колонки
  **отдельно**, а не самое частое сочетание; её ответ может в данных вообще не
  встречаться. Для `["Survived", "Sex", "Cabin"]` мода даёт `(0, "male", "C123")`
  — такое сочетание встречается один раз, тогда как самое частое —
  `(0, "male", "D26")`, два раза. Частое сочетание считают размерами групп:
  `groupby(columns).size()`.
- **Нестрогое неравенство в «больше k».** Условие строгое: `> k`, а не `>= k`.
  Разница видна на k = 1: `>= 1` вернуло бы все 141 фамилию вместо 13.
- **Однофамильцы.** Семьёй в задании названа любая группа одинаковых фамилий;
  два незнакомых человека с фамилией Andersson считаются «семьёй». Это
  определение из условия, а не свойство данных, — в отчёте об этом лучше сказать.

## Счастливые билеты

### Главное

Последняя задача — про номера билетов. Билет считается счастливым, если он
натуральное число (одни цифры, без букв, пробелов и знаков), цифр в нём чётное
число и суммы половин совпадают: `2671` счастливый (2 + 6 = 7 + 1), `935755`
тоже (9 + 3 + 5 = 7 + 5 + 5), а `123456` нет (1 + 2 + 3 ≠ 4 + 5 + 6), и `62869`
нет — в нём нечётное число цифр.

Пишется это вспомогательной функцией `is_lucky(ticket)`, а к колонке применяется
через `df["Ticket"].apply(is_lucky)`: pandas вызывает функцию на каждом значении
и собирает ответы в булев столбец. Цикл `for` с накопителем дал бы то же самое,
но длиннее и медленнее — задание лаборатории просит именно `apply`.

Ключевая деталь — проверка «натуральности»: в колонке `Ticket` лежат номера вида
`A/5 21171`, `PC 17599`, `STON/O2. 3101282`. Такие значения отсеиваются проверкой
`str.isdigit()` **до** любой арифметики: `int("A/5 21171")` падает с `ValueError`,
и функция, которая сразу лезет в `int`, вместо `False` вернёт исключение.

Доля утонувших среди счастливчиков — это среднее булева столбца: `Survived`
равен 1 у выжившего, так что `(lucky["Survived"] == 0).mean()` даёт долю
погибших. На данных лаборатории счастливых пассажиров четверо (`2662`, `2680`,
`347077`, `382652`), трое из них погибли — доля 0.75.

### Пример

```python
import pandas as pd

tickets = pd.Series(["2671", "123222", "935755", "123456", "62869", "568290", "A/5 21171"])


def is_lucky(ticket: str) -> bool:
    """Чётное число цифр и равные суммы половин."""
    if not ticket.isdigit() or len(ticket) % 2:
        return False
    half = len(ticket) // 2
    return sum(map(int, ticket[:half])) == sum(map(int, ticket[half:]))


print(tickets.apply(is_lucky).tolist())     # True у 2671, 123222, 935755
print(int(tickets.apply(is_lucky).sum()))   # 3 счастливых номера из семи

lucky = pd.DataFrame({
    "Ticket": ["2671", "123456", "382652", "A/5 21171"],
    "Survived": [1, 0, 0, 0],
})
dead = lucky[lucky["Ticket"].apply(is_lucky)]
print(len(dead))                          # 2 пассажира со счастливыми билетами
print((dead["Survived"] == 0).mean())     # 0.5 — доля погибших среди них
```

### Частые ошибки

- **Выбросить из номера всё, кроме цифр.** Соблазнительно: `"".join(ch for ch in
  ticket if ch.isdigit())`. Этот вариант **меняет ответ**: номер
  `SOTON/OQ 392086` после чистки даёт `392086`, а у него 3 + 9 + 2 = 0 + 8 + 6,
  то есть «счастливый» билет, которого в условии нет. Считаются счастливыми 5
  пассажиров вместо 4, и доля утонувших выходит 0.8 вместо 0.75.
- **`int(ticket)` без проверки.** На первом же номере с буквами —
  `ValueError: invalid literal for int() with base 10: 'A/5 21171'`. Проверка
  `isdigit()` должна стоять до арифметики.
- **Длина строки вместо числа цифр.** У номера `A/5 21171` длина 9, у
  `STON/O2. 3101282` — 16: чётность длины ничего не говорит о билете, пока в
  номере есть буквы и пробелы. Сначала «одни цифры», потом всё остальное.
- **Перепутать две доли.** `(dead["Survived"] == 0).mean()` — доля погибших
  **среди** счастливчиков (0.75 на данных лаборатории), а `len(dead) / len(df)` —
  доля счастливых билетов среди всех пассажиров (0.0256). Задание спрашивает
  первое, и числитель у него свой: утонувшие, а не все пассажиры.
- **Цикл вместо `apply`.** `for index in df.index` с ручным списком работает, но
  задание просит `apply(is_lucky)` — короче, без своего накопителя и без
  случайной правки таблицы по индексам.

## Итоги занятия

| Вопрос к данным | Инструмент | Что важно |
|---|---|---|
| Отобрать строки по условиям | `df[(...) & (...)]` | `and` падает, каждое условие в скобках |
| Где пропуски | `df.columns[df.isna().any()]` | `mean()` таблицы пропуски пропускает сам |
| Доли значений | `value_counts(normalize=True)` | порядок по частоте, нужен `sort_index()` |
| Среднее по группам | `groupby(col)[value].mean()` | группы задают колонкой, а не циклом |
| Фамилия | `.str.split(",").str[0]` | до первой запятой |
| Число семей | `(value_counts() > k).sum()` | по фамилиям, а не по строкам |
| Частое сочетание | `groupby(cols).size().idxmax()` | не `mode()`: она ищет моду по колонкам |
| Счастливый билет | `isdigit()`, `apply(is_lucky)` | буквы отсеиваются до арифметики |

Правило занятия: таблица отвечает на вопрос цепочкой методов, а не циклом.
Сначала маска — булев столбец условий, потом `groupby`, `value_counts` или
`apply`. И помните две вещи, которые легко перепутать: `&` вместо `and` и
`mean()` pandas вместо `mean()` numpy.
