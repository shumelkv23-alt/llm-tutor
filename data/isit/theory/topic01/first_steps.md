# Первая функция и проверка кода

Программа на Python — это набор функций, и почти вся работа в курсе сводится к
«напиши функцию, которая по входу даёт нужный выход». Первое занятие — про сам
договор: как выглядит функция, что она обещает и как убедиться, что обещание
выполнено.

## Зачем

После занятия вы сможете:

- писать функцию с именем, аргументами и возвратом и понимать, чем `return`
  отличается от `print`;
- читать аннотации типов и докстринг как часть договора;
- проверять свою функцию до сдачи: вызывать её и сравнивать результат с
  ожидаемым через `assert`;
- понимать, что такое проверки структуры — они в курсе тоже есть.

## Первая функция

### Главное

Функцию объявляют словом **`def`**: имя, список аргументов в скобках,
двоеточие. Тело — с отступом. **`return` возвращает значение** тому, кто
функцию вызвал; без `return` функция возвращает `None`.

`print` ничего не возвращает — он печатает на экран. Новичок пишет
`print(result)` там, где нужно `return result`, и потом удивляется `None` в
ответе: печать и возврат — разные вещи. Печать видна человеку, возврат — коду,
который функцию вызвал.

**Аннотации типов** (`def get_hello_world() -> str`) описывают договор:
что функция принимает и что обещает вернуть. Python их не проверяет во время
работы, но они читаются человеком и редактором, а в этом курсе по ним
проверяется, что вы не перепутали смысл задачи.

**Докстринг** — строка в тройных кавычках сразу после `def`. Это
документация, которую видит `help(функция)`; в учебных заданиях докстринг
приходит с заготовкой и его удалять нельзя. Имя функции — тоже часть договора:
`get_middle_value` обещает «взять среднее», а не «напечатать среднее».

Функцию можно вызвать много раз с разными аргументами, и она не должна
помнить предыдущие вызовы. Всё, что нужно для ответа, приходит через аргументы
или создаётся внутри.

### Пример

```python
def get_hello_world() -> str:
    """
    :return: hello world string
    """
    return "Hello world!"


def greet(name: str) -> str:
    """Приветствие по имени."""
    return f"Привет, {name}!"


print(get_hello_world())
print(greet("Аня"))
print(get_hello_world().upper())

# Функция, которая только печатает, возвращает None.
def show(value: int) -> None:
    print("значение:", value)


print(show(3))
```

### Частые ошибки

- **`print` вместо `return`.** Снаружи придёт `None`, и проверка не пройдёт,
  хотя на экране всё выглядит правильно.
- **Забытый `return` в одной из ветвей.** Функция возвращает значение только
  иногда — самая частая причина `None` в ответе.
- **Удалённый докстринг.** В заданиях курса докстринг проверяется наравне с
  ответом: это часть заготовки.
- **Переменная вместо возврата.** `result = get_hello_world()` оставляет в
  `result` то, что функция вернула, — а если функция печатала, там будет
  `None`.

## Проверка кода

### Главное

Функция считается готовой не тогда, когда «вроде работает», а когда её
поведение проверено на разных входах. Проверка — это вызов функции с
известным ответом и сравнение.

Основа проверки в Python — **`assert`**: он проверяет условие и падает с
`AssertionError`, если условие ложно. Второй аргумент `assert` — сообщение,
которое объясняет, что именно не так. Без сообщения упавшая проверка говорит
только «здесь что-то не так» — и вы ищете ошибку заново.

Проверка — это всегда три части: подготовить вход, вызвать функцию и сравнить
ответ с ожидаемым. Если сравнение не сошлось, `assert` останавливает работу и
показывает сообщение; если сошлось — идёт следующая проверка.

Тесты в проектах пишут на `pytest`: файл `test_public.py`, функции с именем
`test_...`, набор случаев. Каждый случай — это вход и ожидаемый выход; тест
прогоняет их по очереди. Проверять нужно **поведение на границах**: ноль,
отрицательные числа, пустой список, повторяющиеся значения — там ошибки и
живут.

Хороший тест проверяет то, что функция обещала, а не то, как она это делает:
если внутри `sum_two_numbers` есть цикл, а не `sum`, ответ всё равно верный.
Но иногда проверяют и структуру: в лабораториях курса библиотечка `testlib`
умеет смотреть в байт-код — например, требовать, чтобы запрещённая функция
`sum` не использовалась, а докстринг остался на месте.

В браузере роль `pytest` играют проверки `assert` задания: они выполняются
после вашего кода и объясняют, что не так. Локально те же проверки запускают
руками — так задание проверяют перед сдачей, а не после неё.

```python
def double(value: int) -> int:
    return value * 2


answer = double(3)
expected = 6
assert answer == expected, f"Ожидали {expected}, получили {answer}"
```

### Пример

```python
def sum_two_numbers(a: int, b: int) -> int:
    """
    :param a: first integer
    :param b: second integer
    :return: sum of a and b
    """
    return a + b


# Проверки: обычный случай, отрицательные числа, нулевая сумма.
assert sum_two_numbers(1, 1) == 2, "basic"
assert sum_two_numbers(-1, -1) == -2, "negative"
assert sum_two_numbers(1, -1) == 0, "zero_sum"

# Проверка «на будущее»: то же самое, но списком случаев.
cases = [(1, 1, 2), (-1, -1, -2), (1, -1, 0), (10, 5, 15)]
for a, b, expected in cases:
    assert sum_two_numbers(a, b) == expected, (a, b)

print("все проверки прошли")
```

### Частые ошибки

- **`assert` без сообщения.** Когда проверка упадёт, вы не поймёте, какой
  случай сломался, — пишите короткое сообщение или подставляйте вход.
- **Проверка одного удачного случая.** Функция, верная на `(1, 1)`, может
  врать на `(1, -1)`; границы проверяют отдельно.
- **Тест, который ничего не проверяет.** `assert sum_two_numbers(1, 1)`
  пройдёт всегда: результат не сравнивают, а ненулевое число — истина.
- **Сравнение чисел с плавающей точкой через `==`.** `0.1 + 0.2 == 0.3`
  ложно из-за двоичного представления: такие значения сравнивают с допуском
  или округляют.

## Итоги занятия

| Что | Что делает |
|---|---|
| `def имя(аргументы) -> тип:` | объявление функции |
| `return значение` | вернуть результат; без него функция отдаёт `None` |
| `print(...)` | напечатать; ничего не возвращает |
| докстринг, аннотации | договор: что принимает и что обещает вернуть |
| `assert условие, "текст"` | проверка: падает с `AssertionError`, если условие ложно |

Правило занятия: функцию возвращаем, а не печатаем; проверяем на нескольких
входах, включая границы.
