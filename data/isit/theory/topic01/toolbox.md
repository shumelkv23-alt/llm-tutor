# Генераторы и itertools

Разминка лаборатории — четыре короткие функции: транспонирование, удаление
дубликатов, объединение словарей и скалярное произведение. Все четыре решаются
в одну строку, и за этим стоит один и тот же набор инструментов: ленивые
последовательности и готовые функции из `itertools` и `operator`.

## Зачем

После занятия вы сможете:

- написать функцию-генератор и объяснить, когда тело такой функции начинает
  выполняться;
- собрать ленивую цепочку обработки и посчитать её память;
- транспонировать матрицу без двойного цикла;
- посчитать скалярное произведение через `zip` и `sum`;
- объединить словари, не меняя ни одного из входных;
- назвать ловушки: одноразовость итераторов, разная длина строк, чужая мутация.

## Генераторы

### Главное

Функция, в теле которой есть `yield`, — это **функция-генератор**. Вызов такой
функции не выполняет ни одной строки тела: он возвращает объект-генератор, а
тело пойдёт шаг за шагом, по одному `next()`. Отсюда два следствия, ради
которых генераторы и нужны:

- **ленивость** — элементы считаются по мере надобности, а не все сразу. Пайплайн
  из трёх генераторов не хранит промежуточных списков: память нужна только под
  текущий элемент (плюс то, что генератор помнит сам);
- **работа с бесконечными и большими источниками** — `itertools.count()` или
  файл в миллион строк можно обрабатывать, ни разу не собрав их целиком.

Генератор — это **итератор**, а не контейнер. Он одноразовый: пройдя его до
конца, второй раз вы получите пустоту. Если данные нужны дважды, их сохраняют
в список — один раз, явно. Проверить, что получился именно генератор, можно
через `types.GeneratorType`; тесты лаборатории так и делают.

Второй способ получить генератор — **генераторное выражение**
`(x * x for x in data)`: тот же ленивый поток без имени и без тела функции.
Круглые скобки вместо квадратных — это не «укороченная запись включения», а
другой объект: включение строит список сразу, выражение — по требованию.

### Пример

```python
from collections.abc import Generator
from types import GeneratorType


def uniq(sequence: list[int]) -> Generator[int, None, None]:
    """Элементы в исходном порядке без повторов; работает и на генераторе."""
    seen: set[int] = set()
    for element in sequence:
        if element in seen:
            continue
        seen.add(element)
        yield element


data = [1, 2, 3, 3, 1, 7]
generator = uniq(data)
print(isinstance(generator, GeneratorType))   # True — это генератор, а не список
print(next(generator))                        # 1: тело проснулось на первом next
print(list(generator))                        # [2, 3, 7] — продолжили с того же места
print(list(generator))                        # [] — генератор исчерпан

print(list(uniq([1, 1, 3, 1, 1, 3])))         # [1, 3]
print(list(uniq([])))                         # []


def rounding(number: int) -> Generator[int, None, None]:
    """Тот же приём, но источник — генераторное выражение."""
    yield from uniq(x % 3 for x in range(number))


print(list(rounding(10)))                     # [0, 1, 2]
```

### Частые ошибки

- **Функция возвращает список, а не генератор.** Если вместо `yield` накопить
  `result` и вернуть его, проверка `isinstance(..., GeneratorType)` не пройдёт,
  и ленивости не будет: источник обработается целиком на первом же вызове.
- **Генератор обходят дважды.** Второй `list(generator)` пуст — это не ошибка
  окружения, а свойство итератора. Нужен второй проход — сохраните список.
- **Убрать дубликаты через `set(sequence)`.** Быстро, но порядок теряется; в
  задаче порядок входа — часть договора.
- **`return` в генераторе с значением.** `return value` внутри генератора не
  отдаёт значение вызывающему: он завершает поток (`StopIteration`).
- **Мутация источника во время обхода.** Список, который меняют в теле цикла по
  нему самому, ведёт себя непредсказуемо; обход — операция чтения.

## itertools и пары

### Главное

`zip` — главный инструмент этого раздела: он склеивает последовательности в
пары и **останавливается на самой короткой**. Для матрицы с одинаковыми по
длине строками `zip(*matrix)` даёт транспонирование в одну строку: `*matrix`
раскладывает строки в аргументы, `zip` собирает первые элементы всех строк в
первую строку результата и так далее. На пустой матрице `zip(*[])` — это
`zip()` без аргументов, то есть пусто, и специальная проверка не нужна.

`itertools` и `operator` дают остальное:

- `itertools.chain` — склеить несколько источников в один;
- `itertools.islice` — взять первые `n` элементов бесконечного источника;
- `itertools.count`, `itertools.repeat` — бесконечные счётчики;
- `itertools.pairwise` — соседние пары;
- `operator.mul` — умножение как функция, её удобно передавать в `map`/`sum`.

Скалярное произведение — это `sum(map(mul, lhs, rhs))`: `zip` внутри `map`
снова останавливается на короткой последовательности, поэтому пары не выйдут за
границы. Складывать сами элементы обязательно: `sum(lhs * rhs)` для списков
означает совсем другое (повторение списка), а не поэлементное произведение.

Объединение словарей — тоже одна строка,
`{key: value for dct in dicts for key, value in dct.items()}`, и в ней важны две
вещи: порядок аргументов (побеждает последний) и неизменность входов.
Распаковка `{**first, **second}` делает то же для двух словарей, а `update`
меняет получателя — на «объединить и вернуть новое» он не годится.

### Пример

```python
import itertools
from collections.abc import Callable
from operator import mul


def transpose(matrix: list[list[int]]) -> list[list[int]]:
    """Строки становятся столбцами; на пустой матрице — пустой список."""
    return [list(row) for row in zip(*matrix)]


def product(lhs: list[int], rhs: list[int]) -> int:
    """Скалярное произведение: пары даёт zip, сумму — sum."""
    return sum(map(mul, lhs, rhs))


def dict_merge(*dicts: dict[int, int]) -> dict[int, int]:
    """Плоские словари; значения поздних аргументов перекрывают ранние."""
    return {key: value for dct in dicts for key, value in dct.items()}


print(transpose([[1, 2], [3, 4], [5, 6]]))    # [[1, 3, 5], [2, 4, 6]]
print(transpose([[1], [3]]))                  # [[1, 3]]
print(transpose([]))                          # []

print(product([1, 2, 3], [4, 5, 6]))          # 32
print(product([], []))                        # 0

print(dict_merge({1: 2}, {2: 2}, {1: 1}))     # {1: 1, 2: 2}
print(dict_merge())                           # {}

source = {1: 2}
before = dict(source)
dict_merge(source, {2: 3})
print(source == before)                       # True: вход не меняется

print(list(itertools.islice(itertools.count(1, 2), 4)))   # [1, 3, 5, 7]
print(list(itertools.pairwise([1, 2, 3])))                # [(1, 2), (2, 3)]
print(list(itertools.chain([1, 2], (3,), range(4, 5))))   # [1, 2, 3, 4]

mapper: Callable[[str], int] = len
print(list(map(mapper, ["a", "bb"])))         # [1, 2] — map тоже итератор
```

### Частые ошибки

- **Молчаливая потеря хвоста.** `zip` останавливается на короткой строке: если
  одна строка матрицы короче, `transpose` вернёт матрицу без её хвоста и не
  скажет ни слова. Для «рваных» данных нужен `itertools.zip_longest`.
- **`matrix[0]` для проверки пустоты.** `matrix[0]` на пустом списке — это
  `IndexError`; `zip(*matrix)` пустую матрицу переживает сам.
- **Сумма вместо поэлементной суммы.** `sum(lhs * rhs)` — не скалярное
  произведение, а повторение списка; нужен `zip` (или `map`) плюс `sum`.
- **Мутация первого словаря.** `first.update(second)` меняет аргумент
  вызывающего; тесты лаборатории сравнивают входы до и после вызова.
- **Порядок аргументов забыт.** В `dict_merge(a, b)` побеждает `b`; перепутали
  порядок — получили противоположный ответ без единой ошибки.
- **Ленивый результат обошли дважды.** `zip`, `map` и `itertools`-объекты — тоже
  одноразовые итераторы: сохраните список, если он нужен дважды.

## Итоги занятия

| Что | Как | Цена |
|---|---|---|
| Функция-генератор | `yield`, тело идёт по `next` | ленивая, одноразовая |
| Дубликаты без повторов | `seen` + `yield` | O(n) времени, O(n) памяти под `seen` |
| Транспонирование | `zip(*matrix)` | O(строки × столбцы), короткая строка обрывает |
| Скалярное произведение | `sum(map(mul, lhs, rhs))` | O(n), без промежуточного списка |
| Объединение словарей | `{k: v for d in dicts for k, v in d.items()}` | O(всех ключей), входы целы |
| Бесконечный источник | `itertools.islice(count(...), n)` | берём только `n` элементов |

Правило занятия: генератор — это итератор, значит ленивый и одноразовый; а
`zip` — самый короткий путь к парам, если помнить, что длину он берёт у самой
короткой последовательности и об этом молчит.
