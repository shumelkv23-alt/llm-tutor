# Ветвления и условия

Условие — способ сказать «если так, то так, иначе иначе». Две классические
задачи занятия — медиана из трёх чисел и FizzBuzz — показывают, где ветвления
ломаются: не в синтаксисе, а в порядке ветвей и в границах.

## Зачем

После занятия вы сможете:

- писать цепочку `if / elif / else` и понимать, что порядок ветвей важен;
- пользоваться сравнениями, `and`/`or`/`not` и цепочками вида `a <= b <= c`;
- выбирать между ветвлением и встроенными `min`/`max`;
- собирать список по правилу через `range` и остаток от деления `%`;
- замечать антипаттерн «список из разных типов».

## Медиана из трёх

### Главное

**Медиана** трёх чисел — то, что стоит между двумя другими: у `1, 2, 3` — это
`2`, у `100, -10, -100` — `-10`. Отсортировать три числа и взять среднее было
бы просто, но задача учебная: её просят решить на сравнениях, чтобы
почувствовать, как устроено ветвление.

Ветка выбирается **сверху вниз**, первая подошедшая: `elif` не выполняется,
если сработал `if`. Значит, порядок ветвей — часть решения, а не оформление.

Два подхода:

- **на сравнениях**: выяснить, кто из чисел лежит между двумя другими, и
  вернуть его (`if a <= b <= c or c <= b <= a: return b`);
- **без сравнений**: у трёх чисел сумма минус минимум и минус максимум даёт
  середину — `a + b + c - min(a, b, c) - max(a, b, c)`. Читается как формула
  и не содержит ветвлений вовсе.

Цепочки сравнений — особенность Python: `a <= b <= c` значит `a <= b and b <= c`,
при этом `b` вычисляется один раз. В других языках так писать нельзя, там
`a <= b <= c` значило бы `(a <= b) <= c`.

Условия соединяют словами `and`, `or`, `not` — для отдельных значений это
правильный инструмент (в отличие от столбцов pandas, где нужны `&` и `|`).

### Пример

```python
def get_middle_value(a: int, b: int, c: int) -> int:
    """Среднее по величине из трёх чисел — через сравнения."""
    if a <= b <= c or c <= b <= a:
        return b
    if b <= a <= c or c <= a <= b:
        return a
    return c


def middle_formula(a: int, b: int, c: int) -> int:
    """То же самое без единого сравнения."""
    return a + b + c - min(a, b, c) - max(a, b, c)


cases = [
    (1, 2, 3, 2),
    (3, 2, 1, 2),
    (2, 3, 1, 2),
    (-100, -10, 100, -10),
    (-10, -10, -5, -10),
    (-10, -10, -10, -10),
    (10**12, -(10**12), 10**10, 10**10),
]

for a, b, c, expected in cases:
    assert get_middle_value(a, b, c) == expected, (a, b, c)
    assert middle_formula(a, b, c) == expected, (a, b, c)

print(get_middle_value(-100, -10, 100), middle_formula(-100, -10, 100))
```

### Частые ошибки

- **Порядок ветвей.** `if a > b: return a` перед проверкой `c` вернёт не
  середину, а максимум. Проверяйте условия так, чтобы первая же верная ветвь
  давала правильный ответ.
- **Строгие сравнения там, где нужны нестрогие.** При `a == b` условие
  `a < b < c` ложно, и функция уходит в `else` — на равных числах (в примере
  `-10, -10, -5`) это даёт неверный ответ.
- **Ветвление вместо формулы.** Три числа можно посчитать арифметикой;
  ветвления стоит писать там, где они несут смысл.
- **`elif` после `else`.** `else` всегда последний: он ловит всё, что не
  подошло выше.

## FizzBuzz

### Главное

Задача: вернуть список чисел от 1 до `n`, заменив кратные трём на `"Fizz"`,
кратные пяти — на `"Buzz"`, кратные и трём, и пяти — на `"FizzBuzz"`.

Инструменты: `range(1, n + 1)` даёт числа **от 1 до n включительно** (правая
граница не входит), `%` — остаток от деления, `== 0` — «делится нацело».
Дальше `if / elif / else`: одна ветвь на случай.

**Порядок ветвей здесь решает всё.** Число, кратное 15, кратно и трём, и
пяти. Если первым стоит `if value % 3 == 0: "Fizz"`, то `15` получит
`"Fizz"` и до `"FizzBuzz"` дело не дойдёт. Поэтому проверка `15` (или
`value % 3 == 0 and value % 5 == 0`) идёт **первой**, и только потом — 3 и 5.

Список собирают добавлением в конец: `values.append(...)`. Аннотация
`list[int | str]` честно говорит, что элементы разных типов. Так делают только
в учебных задачах: в обычном коде список из чисел и строк — антипаттерн,
потому что с ним нельзя ни считать, ни сортировать.

### Пример

```python
def get_fizz_buzz(n: int) -> list[int | str]:
    """Числа от 1 до n; кратные 3 — Fizz, 5 — Buzz, 15 — FizzBuzz."""
    values: list[int | str] = []
    for value in range(1, n + 1):
        if value % 15 == 0:
            values.append("FizzBuzz")
        elif value % 3 == 0:
            values.append("Fizz")
        elif value % 5 == 0:
            values.append("Buzz")
        else:
            values.append(value)
    return values


result = get_fizz_buzz(16)
print(result)
assert len(result) == 16
assert result[2] == "Fizz"        # 3
assert result[4] == "Buzz"        # 5
assert result[14] == "FizzBuzz"   # 15
assert result[0] == 1

bad = get_fizz_buzz(1)
print("для n = 1:", bad)
```

### Частые ошибки

- **Проверка 3 раньше 15.** `15` превращается в `"Fizz"`, `"FizzBuzz"` не
  встречается ни разу.
- **`range(n)` вместо `range(1, n + 1)`.** Теряется последнее число, а ноль
  попадает в список лишним: `0 % 3` даёт `0`, и ноль считается делящимся.
- **`if value % 3` вместо `if value % 3 == 0`.** Условие истинно, когда
  остаток **не** ноль, — логика переворачивается. Хуже всего на границе:
  `0 % 3` — это `0`, то есть ложь, и ноль выпадет из списка делящихся.
- **Смешанные типы в продакшене.** Список `[1, "Fizz", 2]` нельзя сложить
  или отсортировать; здесь он нужен по условию задачи, а в реальном коде
  вместо него берут пару «число → метка».

## Итоги занятия

| Что | Что делает |
|---|---|
| `if / elif / else` | ветка выбирается сверху вниз, первая подошедшая |
| `a <= b <= c` | цепочка сравнений: `a <= b and b <= c` |
| `and`, `or`, `not` | логические операторы для значений |
| `min(a, b, c)`, `max(a, b, c)` | минимум и максимум без ветвлений |
| `range(1, n + 1)` | числа от 1 до n включительно |
| `value % k == 0` | «делится на k нацело» |
| `values.append(x)` | добавить элемент в конец списка |

Правило занятия: порядок ветвей — часть решения; частный случай (`15`)
проверяют раньше общего (`3`).
