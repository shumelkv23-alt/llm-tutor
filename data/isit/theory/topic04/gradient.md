# Обучение логистической регрессии

Прошлое занятие дало модель и цену: сигмоида превращает линейную комбинацию в
вероятность, логарифмическая потеря оценивает эту вероятность числом. Сегодня
ищем веса, при которых потеря минимальна, — и обнаруживаем, что формула
градиента у нас уже есть.

## Зачем

После занятия вы сможете:

- вывести градиент логарифмической потери и объяснить, почему он такой простой;
- проверить градиент численно, конечными разностями;
- обучить модель градиентным спуском и сверить качество со sklearn;
- получить вероятности, превратить их в классы порогом и объяснить, что порог меняет;
- назвать ловушки: знак градиента, шаг обучения, нулевая инициализация, качество
  на обучающей выборке.

## Градиент потерь

### Главное

Считаем производные логарифмической потери по весам. Ключ к простоте —
производная сигмоиды: $\sigma'(z) = \sigma(z)(1 - \sigma(z))$. Тогда для одного
объекта

$$\frac{\partial}{\partial z}\left[ -y \ln h - (1-y)\ln(1-h)\right] = h - y,$$

и весь вывод сворачивается в две строчки:

$$\frac{\partial J}{\partial w} = \frac{1}{m}X^T(h - y), \qquad
\frac{\partial J}{\partial b} = \frac{1}{m}\sum_{i=1}^{m}(h_i - y_i)$$

Сравните с линейной регрессией: там градиент MSE был ровно
$\frac{2}{m}X^T(\hat{y} - y)$. Формула та же с точностью до множителя — но
$\hat{y}$ теперь не линейная комбинация, а сигмоида от неё. Именно это
сокращение $h - y$ делает логистическую регрессию учебной моделью: сигмоида и
логарифмическая потеря подобраны друг под друга.

Правило обновления — обычное: $w := w - \alpha \frac{\partial J}{\partial w}$,
где $\alpha$ — скорость обучения (learning rate).

### Пример

```python
import numpy as np

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-np.asarray(z, dtype=float)))

def log_loss(y_true, proba):
    y_true = np.asarray(y_true, dtype=float)
    proba = np.clip(np.asarray(proba, dtype=float), 1e-12, 1 - 1e-12)
    return float(-np.mean(y_true * np.log(proba) + (1 - y_true) * np.log(1 - proba)))

X = np.array([[0.5, -1.0], [1.5, 0.3], [-0.8, 2.0], [2.2, 1.1]])
y = np.array([0.0, 1.0, 0.0, 1.0])
w = np.array([0.3, -0.7])
b = 0.2

h = sigmoid(X @ w + b)
analytic_dw = X.T @ (h - y) / len(y)
analytic_db = float(np.mean(h - y))

# Численная проверка: сдвигаем вес на eps и смотрим, как меняется потеря
eps = 1e-6
numeric_dw = np.zeros(2)
for j in range(2):
    w_plus, w_minus = w.copy(), w.copy()
    w_plus[j] += eps
    w_minus[j] -= eps
    numeric_dw[j] = (log_loss(y, sigmoid(X @ w_plus + b)) - log_loss(y, sigmoid(X @ w_minus + b))) / (2 * eps)

print(np.round(analytic_dw, 8))   # [0.10440886 0.08806222]
print(np.round(numeric_dw, 8))    # то же самое
print(round(analytic_db, 8))      # 0.0485616
```

### Частые ошибки

- **Перепутать знак.** Внутри стоит $(h - y)$, а не $(y - h)$: если считать
  наоборот, спуск поедет в гору, и потеря будет расти на каждой итерации.
- **Забыть множитель $1/m$.** Без деления на число объектов градиент
  пропорционален размеру выборки: шаг обучения, подобранный на сотне строк,
  разнесёт веса на выборке в десять тысяч.
- **Умножать ещё и на $\sigma'$.** Ничего домножать не нужно: производная
  сигмоиды уже сократилась при выводе. Кто всё-таки оставляет её в формуле, тот
  получает тот же оптимум, но более медленный спуск: $\sigma'$ не больше 0.25, а
  на уверенных объектах почти ноль — их вклад в шаг пропадает, и обучение
  буксует.
- **Считать градиент по вероятностям.** Производные берутся по весам $w$ и $b$,
  а не по $h$: последняя — не параметр, а результат прямого прохода.

## Своя модель

### Главное

Обучение собирается в цикл из трёх действий: прямой проход `h = sigmoid(X @ w + b)`,
градиент `X.T @ (h - y) / n_samples`, шаг `w -= learning_rate * gradient`.
Инициализация — нулями; веса и смещение хранятся в атрибутах объекта, потому
что нужны после обучения, а не только внутри `fit`.

На данных лаборатории (200 объектов, два признака, `random_state=1`) модель со
скоростью 0.1 за 2000 итераций даёт точность 0.87, а sklearn на тех же данных —
0.865: своя реализация не хуже. Потеря убывает монотонно — 0.693 после первого
шага, 0.333 через сто, 0.303 через пятьсот, 0.300 к концу: самые крупные
улучшения приходятся на начало, дальше идёт тонкая подстройка.

Скорость обучения — не формальность. На тех же данных шаг 0.001 за 2000
итераций не успевает дойти до хороших весов (точность 0.975 на лёгкой
синтетике против 0.995 при шаге 0.1). Большой шаг тут не разносит веса —
сигмоида гасит градиент сама, — но на разделимых данных у задачи вообще нет
конечного оптимума: веса растут неограниченно (за 2000 итераций при шаге 0.1
норма весов доходит до 7, при шаге 50 — до 50), вероятности липнут к нулю и
единице. Лечится это не меньшим шагом, а штрафом за большие веса — регуляризацией
из прошлого модуля.

### Пример

```python
import numpy as np

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-np.asarray(z, dtype=float)))

class MyLogisticRegression:
    def __init__(self, learning_rate=0.1, n_iterations=2000):
        self.learning_rate = learning_rate
        self.n_iterations = n_iterations
        self.weights = None
        self.bias = None

    def fit(self, X, y):
        X = np.asarray(X, dtype=float)
        y = np.asarray(y, dtype=float)
        n_samples, n_features = X.shape
        self.weights = np.zeros(n_features)
        self.bias = 0.0
        for _ in range(self.n_iterations):
            h = sigmoid(X @ self.weights + self.bias)
            self.weights -= self.learning_rate * (X.T @ (h - y) / n_samples)
            self.bias -= self.learning_rate * float(np.mean(h - y))
        return self

    def predict_proba(self, X):
        X = np.atleast_2d(np.asarray(X, dtype=float))
        return sigmoid(X @ self.weights + self.bias)

    def predict(self, X, threshold=0.5):
        return (self.predict_proba(X) >= threshold).astype(int)

X = np.array([[-1.0, -1.0], [-2.0, -2.0], [1.0, 1.0], [2.0, 2.0]])
y = np.array([0, 0, 1, 1])
model = MyLogisticRegression(learning_rate=0.1, n_iterations=1000).fit(X, y)

print(model.predict(X))                      # [0 0 1 1]: классы угаданы
print(np.round(model.predict_proba(X), 4))   # [0.0094 0.0001 0.9906 0.9999]
print(np.round(model.weights, 4))            # [2.3284 2.3284]
print(round(model.bias, 4))                  # -0.0
```

### Частые ошибки

- **Забыть `return self`.** Тогда `model.fit(X, y).predict(X)` падает с
  `AttributeError: 'NoneType'`, а `model = LogisticRegression().fit(X, y)`
  оставляет в переменной `None`. Ошибка обидная, но частая.
- **Не сохранить веса в атрибутах.** Локальная переменная внутри `fit`
  исчезнет вместе с вызовом, и `predict` будет считать по `None`.
- **Учить «на глазок».** Десяти итераций мало: потеря ещё далека от минимума.
  Если не строить историю потерь, отсутствие сходимости легко принять за
  плохую модель.
- **Ждать от разделимых данных конечных весов.** Если классы разделяются
  прямой, оптимум лежит на бесконечности: потеря убывает, веса растут, а
  вероятности становятся всё резче. Это не баг реализации, а свойство задачи.

## Порог и классы

### Главное

Модель выдаёт вероятность, а вопрос стоял про класс. Мостик между ними —
**порог**: вероятность не меньше порога — класс 1, иначе класс 0. Порог по
умолчанию 0.5, потому что на нём вероятность и класс согласованы: выше 0.5 —
модель считает первый класс более вероятным.

Порог — не параметр модели, а решение о цене ошибки, и его выбирают под задачу.
На данных лаборатории при пороге 0.5 модель относит к первому классу 96
объектов из 200 и угадывает 86.5% ответов. Порог 0.3 даёт 114 единиц и 87.5%
точности, порог 0.7 — 81 единицу и 87.0%. Число предсказанных единиц падает
монотонно, а точность гуляет: она не обязана улучшаться от сдвига порога.
Отдельно стоит помнить, что порог меняет только ответы, а не саму модель:
вероятности остаются теми же.

### Пример

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = make_classification(n_samples=200, n_features=2, n_redundant=0,
                           n_informative=2, random_state=1, n_clusters_per_class=1)

model = LogisticRegression().fit(X, y)
proba = model.predict_proba(X)[:, 1]

for threshold in (0.3, 0.5, 0.7):
    labels = (proba >= threshold).astype(int)
    print(threshold, int(labels.sum()), round(accuracy_score(y, labels), 4))
# 0.3 114 0.875
# 0.5  96 0.865
# 0.7  81 0.87
```

### Частые ошибки

- **Округлять вероятности вместо сравнения с порогом.** `np.round(0.5)` даёт
  ноль, и объект с вероятностью ровно 0.5 уезжает во второй класс, хотя
  находится на самой границе. Сравнение с порогом такой неоднозначности не
  создаёт.
- **Считать, что порог 0.5 всегда правильный.** Если пропустить больного
  дороже, чем отправить здорового на лишний анализ, порог сдвигают вниз; если
  дороже ложная тревога — вверх. Значение 0.5 — лишь точка равной цены ошибок.
- **Мерить качество на обучающей выборке.** Точность 0.87 на тех же 200
  объектах, на которых модель училась, ничего не говорит о новых данных. Для
  честной оценки нужна отложенная выборка — об этом будет занятие про
  переобучение.
- **Путать точность и вероятность.** «Модель уверена на 0.87» и «модель
  угадывает 87% объектов» — два разных утверждения о двух разных числах.

## Итоги занятия

| Вопрос | Инструмент | Что важно |
|---|---|---|
| Градиент | $\frac{1}{m}X^T(h - y)$ | та же формула, что в линейной регрессии, но $h = \sigma(z)$ |
| Проверка | конечные разности | аналитика и численная оценка обязаны совпасть |
| Обучение | `w -= alpha * grad` | цикл: прямой проход, градиент, шаг |
| Из вероятности в класс | `proba >= threshold` | порог — решение о цене ошибки, а не параметр модели |

Правило занятия: сигмоида с логарифмической потерей дают градиент, который
считается одной строкой, а обучение сводится к циклу из трёх действий. Дальше
остаётся один вопрос — где именно модель проводит границу.
