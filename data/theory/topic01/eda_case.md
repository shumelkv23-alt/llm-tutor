# EDA на практике: кейс оттока

Гипотеза → срез → вывод на данных об оттоке и первое правило-прогноз.

## Гипотеза → срез → вывод

### Процесс EDA

#### Зачем

Разведочный анализ данных (EDA) — не набор команд, а способ думать. Цель — не «посчитать всё подряд», а получить **наблюдения**, которые объясняют данные и подсказывают, что делать дальше. Числа без вопроса и вывода — шум.

#### Главное

Рабочий цикл короткий, и его повторяют много раз:

1. **Вопрос или гипотеза.** «Клиенты, которые часто звонят в поддержку, уходят чаще?»
2. **Срез или сводка, которые на него отвечают:** `groupby`, `crosstab`, фильтр, график.
3. **Вывод словами** с числами: «при четырёх и более звонках уходит около половины клиентов (52%), а в среднем — 14,5%».
4. **Проверка** вывода: достаточно ли объектов в группе? Не объясняется ли разница другим признаком?
5. **Следующий вопрос**, который вытекает из вывода.

Что ещё важно:

- Начинайте с осмотра (`shape`, `info`, `describe`) и **базового уровня**: общей доли целевого события. Каждое следующее число сравнивайте с ним.
- Сравнивайте **доли, а не абсолютные количества**.
- Записывайте выводы по ходу работы — так из анализа получится отчёт, а не просто тетрадка с ячейками.
- Корреляция ещё не причина: связь признаков показывает, где искать, но не доказывает механизм.

#### Пример

```python
import pandas as pd

df = pd.DataFrame({
    "Customer service calls": [0, 1, 1, 2, 4, 5, 0, 1, 4, 2, 3, 6],
    "Churn": [False, False, False, False, True, True, False, False, False, False, False, True],
})

base_rate = df["Churn"].mean()
print(f"Базовая доля оттока: {base_rate:.0%}")       # 25%

df["many_calls"] = df["Customer service calls"] >= 4
by_group = df.groupby("many_calls")["Churn"].agg(["mean", "size"])
print(by_group)
# Вывод: при 4+ звонках уходят 3 из 4 клиентов (75%) против 0% остальных.
# Проверка: в группе всего 4 клиента — вывод предварительный, нужен датасет больше.
```

#### Частые ошибки

- **Анализ без вопроса:** десятки графиков и ни одного вывода.
- **Нет базового уровня,** и непонятно, много ли «30% оттока в группе».
- **Выводы по маленьким группам** без оговорки о размере.
- **Путать связь с причиной:** «звонки вызывают уход» — гипотеза. Возможно, и то и другое вызывают проблемы со связью.

## Разбор оттока

### Кейс: EDA оттока телеком-клиентов

#### Зачем

Этот кейс собирает всю тему в один сквозной разбор. В курсе mlcourse.ai используют датасет оттока клиентов телеком-оператора (около 3300 клиентов): по тарифу, минутам разговоров и звонкам в поддержку нужно понять, кто уходит. Ниже — тот же путь на маленькой синтетической выборке с теми же столбцами, чтобы код запускался без файла.

#### Главное

План разбора:

1. **Загрузка и осмотр:** `read_csv`, `shape`, `info` — типы и пропуски.
2. **Приведение типов:** `Churn` в 0/1, тарифы — во флаги 0/1.
3. **Базовый уровень:** общая доля оттока. В исходных данных — около 14,5%.
4. **Гипотезы и срезы:**
   - международный тариф → `crosstab` с `normalize="index"`;
   - звонки в поддержку → `groupby` по числу звонков;
   - нагрузка днём → средние минуты у ушедших и оставшихся.
5. **Выводы и простое правило.** В курсе из наблюдений строят правило «международный тариф **и** 4+ звонка в поддержку → уйдёт». Его точность — около 85,8%, а у константы «никто не уходит» — 85,5%. По одной точности правило почти не лучше константы. Ценно другое: оно ловит часть ушедших, а константа не ловит никого.

#### Пример

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(17)
n = 400
df = pd.DataFrame({
    "International plan": rng.choice(["No", "Yes"], size=n, p=[0.9, 0.1]),
    "Customer service calls": rng.poisson(1.5, size=n),
    "Total day minutes": rng.normal(180, 50, size=n).clip(0),
})
risk = (
    0.08
    + 0.35 * (df["International plan"] == "Yes")
    + 0.40 * (df["Customer service calls"] >= 4)
    + 0.10 * (df["Total day minutes"] > 260)
)
df["Churn"] = rng.random(n) < risk.clip(0, 0.95)

print(df.shape)
print(f"Базовая доля оттока: {df['Churn'].mean():.1%}")

print(pd.crosstab(df["International plan"], df["Churn"], normalize="index").round(2))
print(df.groupby("Customer service calls")["Churn"].agg(["mean", "size"]).round(2))
print(df.groupby("Churn")["Total day minutes"].mean().round(1))

# Простое правило, как в курсе: международный тариф И много звонков.
predicted = (df["International plan"] == "Yes") & (df["Customer service calls"] >= 4)
accuracy = (predicted == df["Churn"]).mean()
constant = (~df["Churn"]).mean()          # «никто не уходит»
caught = (predicted & df["Churn"]).sum() / df["Churn"].sum()
print(f"Правило: {accuracy:.1%}, константа: {constant:.1%}, поймано ушедших: {caught:.0%}")
```

#### Частые ошибки

- **Смотреть на точность без базы.** 85,8% звучит хорошо, но константа «никто не уходит» уже даёт 85,5%. Правило ценно, если ловит именно ушедших.
- **Делать вывод о причине.** Частые звонки в поддержку — сигнал, а не доказанная причина ухода.
- **Забывать о размере групп** при чтении долей по числу звонков: на 6–9 звонках клиентов единицы.
