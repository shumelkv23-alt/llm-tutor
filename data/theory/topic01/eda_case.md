# EDA на практике: кейс оттока

Последнее занятие модуля собирает всё вместе. Разведочный анализ данных
(EDA, exploratory data analysis) — это не набор команд, а цикл вопросов к
данным. На кейсе оттока клиентов из mlcourse.ai пройдём его целиком и
закончим первым прогнозом — без машинного обучения, одним правилом.

## Зачем

После занятия вы сможете:

- формулировать гипотезу так, чтобы её можно было проверить срезом данных;
- проверять гипотезы группировками и таблицами сопряжённости;
- отличать сильный признак от случайного различия в маленькой группе;
- построить правило-прогноз и посчитать его долю верных ответов.

## Гипотеза → срез → вывод

### Главное

Каждый шаг EDA состоит из трёх частей:

1. **Гипотеза** — проверяемое утверждение о данных: «клиенты, которые часто
   звонят в поддержку, уходят чаще». Не «посмотрим, что там», а конкретное
   «если …, то …».
2. **Срез** — вычисление, которое её проверяет: группировка, таблица
   сопряжённости, сравнение средних в двух подвыборках.
3. **Вывод** — ответ числом и словами: «у клиентов с 4+ звонками доля оттока
   в несколько раз выше». И новая гипотеза, которая из него следует.

Перед гипотезами — базовая линия: доля положительного класса во всей выборке.
Любое различие в группах сравнивают с ней. Если в целом уходит 14,5%, то 16%
в группе — почти ничего, а 45% — сигнал.

Два предупреждения. Различие в маленькой группе может быть случайным —
смотрите на размер групп. И корреляция — не причина: если клиенты с
международным тарифом уходят чаще, это не значит, что тариф их «выгоняет»;
возможно, его подключают те, кто много звонит за границу и ищет выгоду.

### Пример

```python
import pandas as pd

df = pd.DataFrame(
    {
        "International plan": ["No", "No", "No", "Yes", "Yes", "Yes", "No", "No", "No", "No"],
        "Customer service calls": [1, 4, 0, 2, 3, 0, 4, 5, 1, 2],
        "Churn": [False, False, False, True, True, False, True, True, False, False],
    }
)

baseline = df["Churn"].mean()
print("базовая доля оттока:", baseline)

# Гипотеза: много звонков в поддержку → чаще уходят.
many_calls = df["Customer service calls"] >= 4
print(df.groupby(many_calls)["Churn"].agg(["mean", "size"]))
```

В выводе две строки: `False` (меньше четырёх звонков) и `True`. Столбец
`size` напоминает, на скольких клиентах держится каждая доля.

### Частые ошибки

- **Смотреть без базовой линии.** «В группе уходит 20%» — много это или мало,
  понятно только рядом с долей по всей выборке.
- **Выводы по трём клиентам.** Группа из трёх человек может дать любую долю.
  Без `size` вывод не делают.
- **Путать связь и причину.** Срез показывает, что признаки связаны, но не
  объясняет почему.

## Разбор оттока

### Главное

Данные telecom_churn из mlcourse.ai: 3333 клиента телеком-оператора, около 20
признаков (штат, длительность обслуживания, тарифы, минуты и звонки днём,
вечером, ночью, звонки в поддержку) и целевой признак `Churn`. Уходят 483
клиента — 14,5%: классы несбалансированы.

Что показывает разбор в mlcourse.ai:

- **Международный тариф.** С ним уходят около 42% клиентов, без него — около
  11%. Сильный признак.
- **Звонки в поддержку.** До трёх звонков доля оттока близка к средней, а
  начиная с четырёх резко растёт. Порог «4 и больше» — естественное правило.
- **Дневные минуты.** У ушедших среднее число дневных минут выше: часть
  клиентов уходит из-за больших счетов.
- **Штат** даёт разные доли оттока, но во многих штатах клиентов мало, и
  различия могут быть случайными.

Инструменты те же, что в прошлых занятиях: `crosstab` с `normalize="index"`
для категориальных признаков, `groupby(...).mean()` для сравнения средних,
`value_counts` для баланса классов.

### Пример

```python
import pandas as pd

df = pd.DataFrame(
    {
        "International plan": ["No", "No", "No", "Yes", "Yes", "Yes", "No", "No", "No", "No"],
        "Total day minutes": [265.1, 161.6, 243.4, 299.4, 281.3, 223.4, 254.6, 303.2, 184.5, 129.1],
        "Customer service calls": [1, 4, 0, 2, 3, 0, 4, 5, 1, 2],
        "Churn": [False, False, False, True, True, False, True, True, False, False],
    }
)

print(pd.crosstab(df["International plan"], df["Churn"], normalize="index").round(2))
print(df.groupby("Churn")["Total day minutes"].mean().round(1))
print(pd.crosstab(df["Customer service calls"], df["Churn"], margins=True))
```

На десяти строках цифры, конечно, не совпадут с полным датасетом — пример
показывает, какими вызовами задаются вопросы.

### Частые ошибки

- **Доля не в ту сторону.** Для «доли ушедших среди клиентов с тарифом» тариф
  должен быть строками, а нормировка — `normalize="index"`.
- **Сравнивать только средние.** Среднее скрывает порог: по звонкам в
  поддержку картина видна только в разбивке по числу звонков.
- **Забыть про штаты с парой клиентов.** Сортируя штаты по доле оттока,
  отбросьте маленькие группы или выведите `size` рядом.

## Первое правило-прогноз

### Главное

Из разбора напрашивается правило: **клиент уйдёт, если у него международный
тариф или он звонил в поддержку четыре раза и больше**. Это уже модель —
простая, но проверяемая.

Прогноз — булева маска: `(df["International plan"] == "Yes") |
(df["Customer service calls"] >= 4)`. Каждое условие в скобках, соединение —
`|` (ИЛИ).

Качество прогноза — **доля верных ответов** (accuracy): `(pred ==
df["Churn"]).mean()`. Сравнение даёт True там, где прогноз совпал с
реальностью, а среднее — их долю. В mlcourse.ai это правило на полном
датасете даёт около 85,8% верных ответов.

Чтобы понять, хорош ли результат, сравните его с базовой линией: прогноз
«никто не уйдёт» верен для всех оставшихся, то есть в 85,5% случаев. Правило
лишь немного обгоняет его — accuracy на несбалансированных данных
обманчива. Точнее модели и честнее метрики — темы следующих модулей курса.

### Пример

```python
import pandas as pd

df = pd.DataFrame(
    {
        "International plan": ["No", "No", "No", "Yes", "Yes", "Yes", "No", "No", "No", "No"],
        "Customer service calls": [1, 4, 0, 2, 3, 0, 4, 5, 1, 2],
        "Churn": [False, False, False, True, True, False, True, True, False, False],
    }
)

pred = (df["International plan"] == "Yes") | (df["Customer service calls"] >= 4)
accuracy = (pred == df["Churn"]).mean()
baseline = (~df["Churn"]).mean()   # прогноз «никто не уйдёт»
print("правило:", accuracy, "базовая линия:", baseline)

print(pd.crosstab(pred, df["Churn"], rownames=["прогноз"], colnames=["факт"]))
```

Последняя таблица показывает, где правило ошибается: строка «прогноз True,
факт False» — клиенты, которые попали под правило, но остались. На полных
данных есть и обратная ошибка — ушедшие без тарифа и с малым числом звонков.

### Частые ошибки

- **`or` вместо `|`.** `cond1 or cond2` для столбцов падает с «truth value of
  a Series is ambiguous».
- **`&` вместо `|`.** «И тариф, и много звонков» — другое, гораздо более узкое
  правило.
- **Не сравнить с базовой линией.** 86% звучит хорошо, пока не вспомнишь, что
  85,5% даёт ответ «никто не уйдёт».

## Итоги занятия

| Что | Что делает |
|---|---|
| `df["target"].mean()` | базовая доля положительного класса |
| `df.groupby(маска)["target"].agg(["mean", "size"])` | доля и размер групп по условию |
| `pd.crosstab(a, target, normalize="index")` | доля целевого класса по значениям признака |
| `(cond1) \| (cond2)` | правило-прогноз как маска |
| `(pred == target).mean()` | доля верных прогнозов (accuracy) |
| `pd.crosstab(pred, target)` | где прогноз ошибается |

Цикл EDA: базовая линия → гипотеза → срез → вывод с размером групп → новая
гипотеза или правило.
