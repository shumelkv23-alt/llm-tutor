# Нелинейные границы и параметр C

Линейная модель проводит прямую границу, а реальные данные ей не обязаны
подчиняться. Занятие показывает, как научить линейную модель строить
нелинейные границы — добавлением полиномиальных признаков — на классическом
примере XOR, и как параметр `C` регулирует сложность получившейся модели.

## Зачем

После занятия вы сможете:

- объяснить, как `PolynomialFeatures` делает границу нелинейной, не меняя модель;
- показать на задаче XOR, почему прямая не справляется и что исправляет дело;
- сказать, как `C` связан с коэффициентом регуляризации `λ`, и что происходит
  при больших и малых `C`;
- подобрать `C` на кросс-валидации в `Pipeline`.

## Полиномиальные признаки

### Главное

Идея: линейной остаётся **модель по новым признакам**, а в исходном
пространстве граница становится кривой. Для двух признаков `x₁, x₂`
полиномиальные признаки степени 2 — это `1, x₁, x₂, x₁², x₁·x₂, x₂²`. Линейная
модель над ними имеет вид `w₀ + w₁x₁ + w₂x₂ + w₃x₁² + w₄x₁x₂ + w₅x₂²`, а это
уже уравнение кривой второго порядка — окружности, эллипса, гиперболы.

В scikit-learn признаки добавляет `PolynomialFeatures(degree=2)`; его ставят
перед моделью в `Pipeline`. Обычно перед преобразованием или после него
признаки масштабируют: старшие степени имеют очень разные масштабы.

Цена — **комбинаторный рост** числа признаков. Для `d` признаков и степени
`k` их число равно `C(d + k, k)`: при 10 признаках степень 5 даёт 3003
признака. Поэтому высокие степени строят неявно, через ядра (метод
опорных векторов), а в явном виде ограничиваются степенью 2–3.

### Пример

```python
from math import comb

import numpy as np
from sklearn.preprocessing import PolynomialFeatures

x = np.array([[2.0, 3.0]])
poly = PolynomialFeatures(degree=2)
print(poly.fit_transform(x))                    # 1, x1, x2, x1², x1·x2, x2²
print(poly.get_feature_names_out(["x1", "x2"]))

for d, k in [(2, 2), (10, 2), (10, 5), (100, 3)]:
    print(f"{d} признаков, степень {k}: {comb(d + k, k)} признаков")
```

### Частые ошибки

- **Называть модель нелинейной.** Нелинейна граница в исходных признаках,
  а модель по новым признакам линейна.
- **Брать высокую степень «на всякий случай».** Число признаков и риск
  переобучения растут очень быстро.
- **Не масштабировать.** Квадраты и кубы признаков с большими значениями
  портят оптимизацию.

## Задача XOR

### Главное

**XOR** — классическая задача, которую не решает ни одна прямая: класс
положительный, когда знаки двух признаков **разные**, и отрицательный, когда
одинаковые. Четыре «угла» плоскости разбиваются на два класса по диагоналям,
и провести одну прямую так, чтобы классы оказались по разные стороны,
невозможно. Логистическая регрессия на таких данных почти не лучше
подбрасывания монеты.

Исправляет ситуацию произведение `x₁·x₂`: у XOR его знак как раз и есть
класс. Полиномиальные признаки степени 2 содержат это произведение, поэтому
логистическая регрессия над ними решает задачу почти безошибочно.

Урок общий: если простая модель не справляется, виновата иногда не модель, а
**признаки**. Добавить нужное преобразование иногда проще, чем менять метод.
Альтернатива явным признакам — метод опорных векторов (SVM) с ядром: он
получает тот же эффект, не создавая признаки явно.

### Пример

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures

rng = np.random.default_rng(12)
X = rng.uniform(-1, 1, size=(400, 2))
y = (X[:, 0] * X[:, 1] > 0).astype(int)        # XOR: одинаковые знаки -> 1

linear = LogisticRegression().fit(X, y)
poly = make_pipeline(PolynomialFeatures(degree=2), LogisticRegression(C=10)).fit(X, y)
print("прямая:", round(linear.score(X, y), 3))
print("с x1*x2:", round(poly.score(X, y), 3))
```

### Частые ошибки

- **Менять модель, не посмотрев на данные.** Картина XOR на диаграмме
  рассеяния сразу показывает, что прямая невозможна.
- **Брать степень выше нужной.** Для XOR достаточно произведения; лишние
  степени только добавят шум.
- **Считать, что нелинейность требует нейросетей.** Часто хватает хороших
  признаков.

## Параметр C

### Главное

Параметр `C` логистической регрессии управляет **регуляризацией**, но
«наоборот» по сравнению с `λ`: `C = 1/λ`. Малое `C` — сильная регуляризация
(большое `λ`), большое `C` — слабая. Например, при `λ = 4` получается
`C = 0,25`.

Последствия:

- **слишком большое `C`** — штраф почти не действует, веса могут быть
  огромными, модель подгоняется под шум и **переобучается**;
- **слишком маленькое `C`** — веса прижаты к нулю, модель слишком проста и
  **недообучается**.

Оптимальное `C` ищут перебором по сетке (обычно логарифмической: 0,01; 0,1;
1; 10; 100) с кросс-валидацией: `GridSearchCV` или `LogisticRegressionCV`.
Особенно важно это для моделей с полиномиальными признаками, где
переобучение — главная опасность.

### Пример

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

rng = np.random.default_rng(13)
X = rng.normal(size=(300, 2))
y = ((X[:, 0] ** 2 + X[:, 1] ** 2 + rng.normal(0, 0.6, 300)) > 1.5).astype(int)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=17, stratify=y
)

pipe = make_pipeline(
    PolynomialFeatures(degree=3), StandardScaler(), LogisticRegression(max_iter=2000)
)
for C in (0.0001, 0.1, 10, 1000):
    pipe.set_params(logisticregression__C=C).fit(X_train, y_train)
    print(C, "обучение", round(pipe.score(X_train, y_train), 3),
          "тест", round(pipe.score(X_test, y_test), 3))

grid = GridSearchCV(pipe, {"logisticregression__C": [0.01, 0.1, 1, 10]}, cv=5)
print(grid.fit(X_train, y_train).best_params_)
```

### Частые ошибки

- **Путать направление `C`.** Рост `C` ослабляет регуляризацию; рост `λ` или
  `alpha` в `Ridge` — усиливает.
- **Подбирать `C` по обучающей выборке.** Там лучше всего огромное `C`.
- **Забывать про масштаб при полиномиальных признаках.** Без
  `StandardScaler` модель может не сойтись (предупреждение о сходимости).

## Итоги занятия

| Что | Что делает |
|---|---|
| `PolynomialFeatures(degree=k)` | добавляет степени и произведения признаков |
| число признаков `C(d+k, k)` | комбинаторный рост с ростом степени |
| XOR | не разделяется прямой; решается добавлением `x₁·x₂` |
| `C = 1/λ` | малое `C` — сильная регуляризация, большое — слабая |
| `GridSearchCV(pipe, {"logisticregression__C": […]})` | подбор `C` в пайплайне |

Порядок работы: посмотреть на данные → при необходимости добавить признаки →
масштабировать → подобрать `C` на кросс-валидации.
