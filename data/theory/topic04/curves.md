# Кривые валидации и обучения

Как понять, что модель переобучена или недообучена, и поможет ли новая
порция данных? Для этого есть два диагностических графика: кривая валидации
(качество при разной сложности модели) и кривая обучения (качество при
разном размере выборки). Занятие учит их строить и читать.

## Зачем

После занятия вы сможете:

- построить кривую валидации по гиперпараметру и найти область лучшего значения;
- по разрыву между кривыми отличить переобучение от недообучения;
- построить кривую обучения и решить, нужны ли ещё данные;
- прочитать результаты `validation_curve` и `learning_curve`.

## Кривая валидации

### Главное

**Кривая валидации** показывает качество модели в зависимости от одного
гиперпараметра, который управляет сложностью: параметра регуляризации `C`,
степени полинома, глубины дерева. Для каждого значения параметра модель
оценивается кросс-валидацией, и строятся две линии: качество на обучающих
фолдах и на валидационных.

Как читать:

- **Обе линии низкие и близки друг к другу** — модель **недообучена**: она
  слишком проста для закономерности.
- **Обучающая линия высокая, валидационная заметно ниже, разрыв растёт** —
  **переобучение**: модель слишком сложна для этих данных и запоминает шум.
- **Лучшее значение параметра** — вершина валидационной линии: до неё модель
  ещё не выучила закономерность, после — уже запоминает шум.

В scikit-learn: `validation_curve(model, X, y, param_name=…, param_range=…,
cv=5)` возвращает два массива «значение параметра × фолд» — оценки на
обучении и на валидации. Усредняют по фолдам (ось 1) и рисуют по оси X
значения параметра, чаще всего в логарифмической шкале для `C`.

Что делать по результату диагностики:

- при **недообучении** усложняют модель: ослабляют регуляризацию (увеличивают
  `C`), добавляют полиномиальные признаки, берут более гибкий метод;
- при **переобучении** упрощают: усиливают регуляризацию (уменьшают `C`),
  убирают лишние признаки, ограничивают степень или глубину, собирают больше
  данных;
- если обе линии высокие и близки, модель подобрана хорошо, и дальнейшая
  настройка даст немного.

Кривая валидации ответит на вопрос «какая сложность лучше», но не на вопрос
«хватит ли данных» — для него существует кривая обучения (следующий раздел).

### Пример

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import validation_curve
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

rng = np.random.default_rng(15)
X = rng.normal(size=(300, 2))
y = ((X[:, 0] ** 2 + X[:, 1] ** 2 + rng.normal(0, 0.7, 300)) > 1.6).astype(int)

pipe = make_pipeline(
    PolynomialFeatures(degree=4), StandardScaler(), LogisticRegression(max_iter=5000)
)
c_values = np.logspace(-4, 3, 8)
train_scores, valid_scores = validation_curve(
    pipe, X, y, param_name="logisticregression__C", param_range=c_values, cv=5
)
for c, train, valid in zip(c_values, train_scores.mean(axis=1), valid_scores.mean(axis=1)):
    print(f"C={c:9.4f}  обучение {train:.3f}  валидация {valid:.3f}  разрыв {train - valid:+.3f}")
print("лучшее C:", c_values[valid_scores.mean(axis=1).argmax()])
```

### Частые ошибки

- **Выбирать значение по обучающей линии.** Она улучшается почти всегда;
  решает валидационная.
- **Не усреднять по фолдам.** Один фолд случаен; смотрите на среднее и
  разброс.
- **Строить кривую для нескольких параметров сразу.** Кривая валидации — про
  один параметр; остальные фиксируют.

## Кривая обучения

### Главное

**Кривая обучения** показывает качество в зависимости от **размера обучающей
выборки**. Модель обучают на 10%, 20% … 100% доступных данных и измеряют
качество на обучающей и валидационной частях.

Типичная картина: чем больше данных, тем ниже обучающая линия (запомнить
много объектов труднее) и выше валидационная. Если линии сходятся, но на
низком уровне, — модель недообучена: **новые данные не помогут**, нужна более
сложная модель или новые признаки. Если между линиями большой разрыв, а
валидационная ещё растёт, — **больше данных поможет**, либо нужна
регуляризация.

В scikit-learn: `learning_curve(model, X, y, train_sizes=[…], cv=5)` возвращает
реально использованные размеры выборки и два массива оценок.

Кривую обучения полезно строить до того, как тратить время на сбор данных
или разметку: если валидационная линия уже вышла на плато, дополнительные
объекты почти ничего не добавят, и усилия лучше направить на признаки и
выбор модели.

Замечание про оценку: качество на обучающей выборке само по себе ничего не
говорит — его можно сделать сколь угодно хорошим, переобучив модель. Это не
метрика качества, а только диагностика разрыва.

### Пример

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import learning_curve
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

rng = np.random.default_rng(16)
X = rng.normal(size=(500, 2))
y = ((X[:, 0] ** 2 + X[:, 1] ** 2 + rng.normal(0, 0.7, 500)) > 1.6).astype(int)

for C in (0.001, 10):
    pipe = make_pipeline(
        PolynomialFeatures(degree=4), StandardScaler(), LogisticRegression(C=C, max_iter=5000)
    )
    sizes, train_scores, valid_scores = learning_curve(
        pipe, X, y, train_sizes=[0.1, 0.3, 0.6, 1.0], cv=5
    )
    print("C =", C)
    for size, train, valid in zip(sizes, train_scores.mean(axis=1), valid_scores.mean(axis=1)):
        print(f"  объектов {size:4d}  обучение {train:.3f}  валидация {valid:.3f}")
```

### Частые ошибки

- **Делать вывод по одной точке.** Важна динамика: сходятся линии или
  расходятся, растёт ли валидационная.
- **Ждать, что любые новые данные помогут.** При недообучении кривые уже
  сошлись, и объекты ничего не добавят — нужна другая модель.
- **Смотреть только на обучающую ошибку.** Она ничего не говорит о качестве
  на новых данных.

## Итоги занятия

| Что | Что показывает |
|---|---|
| `validation_curve(model, X, y, param_name, param_range, cv)` | качество при разных значениях одного гиперпараметра |
| обе линии низкие и рядом | недообучение: модель слишком проста |
| высокая обучающая, низкая валидационная | переобучение: модель слишком сложна |
| `learning_curve(model, X, y, train_sizes, cv)` | качество при разном размере выборки |
| линии сошлись на низком уровне | новые данные не помогут, нужна другая модель |
| большой разрыв, валидационная растёт | больше данных или регуляризация помогут |

Порядок диагностики: сначала кривая валидации — подобрать сложность; затем кривая обучения
— решить, нужны ли ещё данные.
