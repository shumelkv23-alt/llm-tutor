# Линейные модели для текста

Линейным моделям нужны числа в таблице, а у отзыва — слова. Занятие
показывает самый простой способ превратить текст в признаки — мешок слов —
и как собрать всё в `Pipeline`, чтобы векторизатор обучался только на
обучающих данных, а параметры подбирались честно.

## Зачем

После занятия вы сможете:

- построить матрицу «документ × слово» через `CountVectorizer` и объяснить,
  почему она разреженная;
- объяснить, что мешок слов теряет порядок слов;
- собрать `Pipeline` из векторизатора и логистической регрессии;
- избежать утечки данных при векторизации и подобрать `C` в `GridSearchCV`.

## Мешок слов

### Главное

**Мешок слов** (bag of words) представляет документ вектором, длина которого —
размер словаря. Координата означает, сколько раз слово встретилось в
документе (или встретилось ли вообще). Модель никак не использует порядок
слов: «фильм не хороший, а ужасный» и «фильм не ужасный, а хороший» дают
почти одинаковые векторы. Это сильное упрощение, но для многих задач
(определение тональности, спама, темы) его хватает.

`CountVectorizer` строит словарь по обучающим текстам (`fit`) и превращает
тексты в матрицу (`transform`). Матрица огромна, но почти полностью состоит
из нулей: в отзыве из 50 слов ненулевых элементов не больше 50 из
десятков тысяч. Поэтому она хранится как **разреженная матрица** (`scipy.sparse`),
и логистическая регрессия работает с ней напрямую.

Вместо счётчиков часто берут **TF-IDF** (`TfidfVectorizer`): частота слова в
документе умножается на редкость слова во всём корпусе. Слова, которые есть
в каждом отзыве («сервис»), получают маленький вес, а редкие и показательные
— большой. Это почти всегда немного улучшает линейные модели.

Полезные параметры: `lowercase`, `stop_words` (убрать служебные слова),
`min_df` (отбросить редкие слова), `ngram_range=(1, 2)` (добавить пары
соседних слов — так частично возвращается порядок).

### Пример

```python
from sklearn.feature_extraction.text import CountVectorizer

reviews = [
    "хороший фильм хороший сюжет",
    "ужасный фильм скучный сюжет",
    "хороший актёр",
]
vectorizer = CountVectorizer()
matrix = vectorizer.fit_transform(reviews)

print(vectorizer.get_feature_names_out())
print(matrix.toarray())
print(type(matrix).__name__, matrix.shape, "ненулевых:", matrix.nnz)

# Порядок слов теряется: разные фразы — одинаковые векторы.
pair = vectorizer.transform(["не хороший а ужасный", "не ужасный а хороший"])
print((pair[0] != pair[1]).nnz == 0)
```

### Частые ошибки

- **Ждать, что мешок слов поймёт отрицание.** «Не хороший» и «хороший»
  отличаются только словом «не», а смысл — противоположный; помогают
  n-граммы.
- **Превращать разреженную матрицу в обычную.** Для большого словаря
  `toarray()` займёт всю память.
- **Игнорировать регистр, пунктуацию и опечатки.** Они раздувают словарь и размывают сигнал.
- **Не лемматизировать и не чистить.** Разные формы слова («фильм», «фильма»)
  становятся разными признаками, если об этом не позаботиться.

## Pipeline для текста

### Главное

Логистическая регрессия на мешке слов — стандартная сильная базовая модель
для текстов. Её собирают в `Pipeline`: `CountVectorizer` → `LogisticRegression`.
Это решает две задачи.

Во-первых, **нет утечки данных**. Если обучить векторизатор на всех
отзывах, включая тестовые, словарь и частоты слов «подсмотрят» отложенную
выборку, и оценка получится завышенной. В `Pipeline` векторизатор
обучается только на обучающей части — на каждом фолде кросс-валидации заново.

Во-вторых, **удобство подбора параметров**. Параметры любого шага доступны
по имени `шаг__параметр`: `GridSearchCV` перебирает и параметры
векторизатора (`countvectorizer__ngram_range`), и параметр `C` модели
(`logisticregression__C`) в одном поиске. Метод `predict` у пайплайна принимает
сырые тексты — отдельно векторизовать новые отзывы не нужно.

Ещё одно достоинство линейной модели на мешке слов — прозрачность: каждому
слову словаря соответствует свой вес. Положительные веса тянут отзыв к
положительному классу, отрицательные — к отрицательному. Достаточно
сопоставить `coef_` модели с `get_feature_names_out()` векторизатора, чтобы
увидеть, на какие слова модель опирается.

### Пример

```python
import numpy as np
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import GridSearchCV, cross_val_score, train_test_split
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(14)
positive = ["хороший", "отличный", "приятный", "добрый"]
negative = ["ужасный", "скучный", "плохой", "грубый"]
neutral = ["сервис", "номер", "завтрак", "вид", "персонал", "район"]


def make_review(label):
    own = positive if label else negative
    other = negative if label else positive
    words = list(rng.choice(neutral, 4)) + list(rng.choice(own, rng.integers(1, 3)))
    words += list(rng.choice(other, rng.integers(0, 2)))   # шум: слова другой тональности
    rng.shuffle(words)
    return " ".join(words)


labels = rng.integers(0, 2, 300)
texts = [make_review(label) for label in labels]
X_train, X_test, y_train, y_test = train_test_split(
    texts, labels, test_size=0.3, random_state=17, stratify=labels
)

pipe = make_pipeline(CountVectorizer(), LogisticRegression(max_iter=1000))
print("кросс-валидация:", cross_val_score(pipe, X_train, y_train, cv=5).mean().round(3))

grid = GridSearchCV(
    pipe,
    {"logisticregression__C": [0.01, 0.1, 1, 10],
     "countvectorizer__ngram_range": [(1, 1), (1, 2)]},
    cv=5,
).fit(X_train, y_train)
print(grid.best_params_)
print("на тесте:", round(grid.score(X_test, y_test), 3))
print(grid.predict(["хороший завтрак номер", "ужасный сервис"]))

# Веса модели читаются по словарю: что тянет отзыв к положительному классу.
best = grid.best_estimator_
words = best[0].get_feature_names_out()
weights = best[-1].coef_[0]
order = np.argsort(weights)
print("против:", list(words[order[:3]]), "за:", list(words[order[-3:]]))
```

### Частые ошибки

- **Векторизовать все тексты до разбиения.** Тестовые данные влияют на словарь
  и частоты; оценка завышена. Векторизатор — внутри `Pipeline`.
- **Забыть префикс шага.** Параметр для `GridSearchCV` записывается
  `имя_шага__параметр`; имена шагов `make_pipeline` даёт сам, в нижнем регистре.
- **Подбирать `C` и параметры по тесту.** Подбор — на кросс-валидации по
  обучающей части, тест — один раз в конце.

## Итоги занятия

| Что | Что делает |
|---|---|
| `CountVectorizer()` | словарь по обучающим текстам, матрица «документ × слово» |
| разреженная матрица | хранит только ненулевые элементы (`nnz`) |
| `ngram_range=(1, 2)` | добавляет пары слов — частично возвращает порядок |
| `make_pipeline(CountVectorizer(), LogisticRegression())` | векторизатор и модель как одно целое |
| `шаг__параметр` | параметры шагов пайплайна для `GridSearchCV` |

Порядок работы: разбить тексты → собрать пайплайн (при необходимости с TF-IDF) → подобрать параметры на
кросс-валидации → один раз проверить на тесте.
