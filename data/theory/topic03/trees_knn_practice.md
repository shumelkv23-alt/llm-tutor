# Кейсы: деревья и kNN

Два метода занятий модуля теперь сравниваем на двух задачах: прогноз оттока —
таблица с признаками разной природы — и распознавание рукописных цифр —
картинки, превращённые в числа. Вывод занятия: не «какой метод лучше
вообще», а «когда какой подходит».

## Зачем

После занятия вы сможете:

- сравнить дерево и kNN на одной задаче кросс-валидацией;
- объяснить, почему на таблице оттока выигрывает дерево, а на цифрах — kNN;
- по описанию данных выбрать метод и обосновать выбор;
- показать на примере, чем плоха ступенчатая граница дерева.

## Отток и рукописные цифры

### Главное

**Отток клиентов.** Признаки — число звонков в поддержку, минуты разговоров,
тарифные планы: разные по смыслу и масштабу, частично категориальные. В
таких данных ответ часто подчиняется набору порогов («звонков больше трёх
**и** подключён международный тариф»). Дерево находит их напрямую, не
требует масштабирования и показывает правила. В исходном кейсе курса дерево
на отложенной выборке давало около 94% правильных ответов против заметно
меньшего результата у kNN.

**Рукописные цифры.** Картинка 8 × 8 пикселей — 64 числа одного смысла
(яркость), в одной шкале. Расстояние между такими векторами осмысленно:
похожие цифры близки по пикселям. Здесь kNN работает отлично: в курсе он
давал около 98–99%, а дерево заметно уступало, потому что значение одного
пикселя почти ничего не говорит о цифре.

Урок: метод должен соответствовать устройству данных. Дерево любит
таблицы с пороговыми правилами, kNN — данные, где близость по расстоянию
и есть сходство.

Обратите внимание, что в обоих кейсах признаки не готовили специально: на
цифрах работают «сырые» пиксели, на оттоке — таблица как есть. Преимущество
метода здесь определяется только тем, как он обращается с такими признаками:
порогами или расстоянием.

Как сравнивать честно. Берут один и тот же набор данных и одни и те же
фолды кросс-валидации для обоих методов, добавляют базовый уровень («всегда
самый частый класс») и смотрят не только на среднюю точность, но и на разброс
по фолдам. Если методы различаются в пределах разброса, разницы, скорее
всего, нет — тогда выбирают по другим свойствам: скорости, простоте,
интерпретируемости.

### Пример

```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

# Таблица «под отток»: ответ задаёт набор порогов по разным признакам.
rng = np.random.default_rng(14)
n = 600
calls = rng.poisson(1.6, n)
plan = rng.random(n) < 0.15
minutes = rng.normal(180, 50, n)
churn = ((calls >= 3) & plan) | (minutes > 280)
X_churn = np.column_stack([calls, plan, minutes])

digits = load_digits()
cases = {"отток": (X_churn, churn), "цифры": (digits.data, digits.target)}
for name, (X, y) in cases.items():
    tree = cross_val_score(DecisionTreeClassifier(max_depth=6, random_state=17), X, y, cv=5)
    knn = cross_val_score(KNeighborsClassifier(n_neighbors=5), X, y, cv=5)
    print(name, "дерево", tree.mean().round(3), "kNN", knn.mean().round(3))
```

### Частые ошибки

- **Выбирать метод по рейтингу, а не по данным.** Универсально лучшего метода
  нет; результат зависит от устройства признаков.
- **Сравнивать методы на разных разбиениях.** Используйте одну и ту же
  кросс-валидацию для всех.
- **Применять kNN к таблице без масштабирования.** Для оттока его надо
  оформить в `Pipeline` со `StandardScaler`, иначе сравнение нечестно.

## Где какой метод сильнее

### Главное

Сводка по прошлым занятиям:

| Свойство | Дерево | kNN |
|---|---|---|
| интерпретируемость | высокая: читаемые правила | низкая: «потому что похожи» |
| масштабирование признаков | не нужно | обязательно |
| разнородные признаки (числа и категории) | удобно | неудобно: расстояние между категориями неочевидно |
| скорость прогноза | высокая | низкая на больших данных |
| границы классов | отрезки вдоль осей | произвольной формы |
| много признаков | отбирает нужные | страдает от проклятия размерности |

Перед выбором задайте себе четыре вопроса. Однородны ли признаки и
осмысленно ли расстояние между объектами? Нужно ли объяснять каждое решение?
Сколько данных и как быстро нужен ответ? Не идёт ли граница между классами
по диагонали? Ответы почти всегда сужают выбор до одного-двух методов.

Практические выводы. Если нужно **объяснить** решение или данные разнородны —
берут дерево. Если признаки однородны и расстояние осмысленно (изображения,
показания датчиков в одной шкале) — kNN. Если граница между классами
наклонная, например `x₁ = x₂`, то дерево строит излишне сложную «лесенку» и
становится очень глубоким, а kNN справляется естественно. Часто лучшим
решением оказывается ансамбль деревьев — тема следующих модулей курса.

### Пример

```python
import numpy as np
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

# Граница x1 = x2 идёт по диагонали.
rng = np.random.default_rng(15)
X = rng.uniform(0, 1, size=(500, 2))
y = (X[:, 0] > X[:, 1]).astype(int)

tree = DecisionTreeClassifier(random_state=17)
knn = KNeighborsClassifier(n_neighbors=7)
print("дерево:", cross_val_score(tree, X, y, cv=5).mean().round(3))
print("kNN:", cross_val_score(knn, X, y, cv=5).mean().round(3))

tree.fit(X, y)
print("глубина дерева", tree.get_depth(), "листьев", tree.get_n_leaves())
shallow = DecisionTreeClassifier(max_depth=3, random_state=17)
print("дерево глубины 3:", cross_val_score(shallow, X, y, cv=5).mean().round(3))
```

### Частые ошибки

- **Отвечать «лучше kNN» или «лучше дерево» без условий.** Хороший ответ
  называет свойства данных и требования задачи.
- **Выбирать дерево только за интерпретируемость.** Дерево глубины 30
  объяснить нельзя; ценность в простых деревьях.
- **Забывать про скорость прогноза.** kNN, который идеален в ноутбуке, может не
  уложиться во время ответа в сервисе.

## Итоги занятия

| Данные | Подходит |
|---|---|
| таблица с разнородными признаками и порогами | дерево |
| однородные признаки, осмысленное расстояние | kNN (после масштабирования) |
| нужно объяснить решение | неглубокое дерево |
| наклонная граница между классами | kNN или ансамбль, а не одно дерево |
| оба варианта кажутся допустимыми | сравнить кросс-валидацией на одинаковых фолдах |

Порядок работы: посмотреть на природу признаков → выбрать кандидатов →
сравнить на одной кросс-валидации → объяснить выбор.
