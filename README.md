# LLM-тьютор по курсу машинного обучения

Веб-приложение — тьютор на основе LLM, который ведёт ученика по курсу
[mlcourse.ai](https://mlcourse.ai): пять модулей в одном графе — от «Pandas / EDA»
до бэггинга и случайного леса (модули 6–10 не написаны). В курсе 33 занятия, в каждом
2–4 раздела, конспект и итоговое задание с кодом.

## Стек

- Python 3.12, [uv](https://docs.astral.sh/uv/)
- FastAPI + Jinja2, чистые JS и CSS без сборки
- Pyodide (Python в браузере для проверки кода), CodeMirror 5
- OpenRouter API (LLM, слой абстракции модели через конфиг)
- SQLite + FTS5 (RAG и хранилище состояния ученика)
- NetworkX (граф концептов курса)

## Быстрый старт

```bash
uv sync                     # установить зависимости
# заполни OPENROUTER_API_KEY в .env:
#   Windows (cmd/PowerShell): copy .env.example .env
#   macOS/Linux (bash):       cp .env.example .env

# загрузить материалы темы в RAG-индекс (один раз; можно URL или файл):
uv run python -m llm_tutor.course.ingest data/raw/topic01_pandas_data_analysis.md --topic 1
# (кладёт в MATERIALS_DB_PATH, data/materials.sqlite3 — оттуда их берёт веб)

uv run python -m llm_tutor.web        # http://127.0.0.1:8000
```

Граф занятий с разделами, банк заданий и анкета модуля (`data/seed_topicNN.json`,
файл на модуль) и конспекты (`data/theory/topicNN/<занятие>.md`) грузятся в БД
ученика автоматически. Каждый модуль начинается с короткой анкеты; занятие
другого модуля, выбранное в маршруте, открывается через анкету его модуля.
Модуль с `published: false` в seed показывается как «скоро» и в маршрут не входит.

**Ученики.** Каждый регистрируется в браузере (`/register`: имя, email,
пароль). Аккаунты лежат в `data/accounts.sqlite3`, а данные ученика по курсу —
в отдельной БД `data/users/<id>/<курс>.sqlite3`.

**Перенос старой БД.** Состояние ученика из прежнего Telegram-бота
(`data/llm_tutor.sqlite3`) переносится в аккаунт веба — сначала
зарегистрируйтесь, затем:

```bash
uv run python -m llm_tutor.web.cli import-legacy --email ann@example.com --db data/llm_tutor.sqlite3
```

**Админка.** Владелец курса получает раздел `/admin` (ученики с прогрессом,
карточка ученика, воронка по занятиям, сброс пароля, выдача роли админа).
Первого админа назначает командная строка — сначала зарегистрируйтесь, затем
(дальше роль можно выдавать на карточке ученика):

```bash
uv run python -m llm_tutor.web.cli make-admin --email ann@example.com
uv run python -m llm_tutor.web.cli revoke-admin --email ann@example.com
```

**Забыл пароль.** На странице входа есть ссылка «Забыли пароль?»: ученик вводит
email и получает письмо со ссылкой, по которой задаёт новый пароль. Ссылка живёт
час и срабатывает один раз; после смены пароля все прежние входы закрываются.
Ответ на заявку одинаков для любого адреса («если такой email зарегистрирован…»):
по нему нельзя узнать, кто здесь учится.

Отправка писем настраивается в `.env` и **по умолчанию выключена** — тогда
приложение работает в режиме показа: письмо целиком (вместе со ссылкой) печатается
в журнале сервера, и сценарий восстановления проходится насквозь. Для настоящей
отправки через Gmail:

```env
SMTP_USER=aztutorllm@gmail.com
SMTP_PASSWORD=<пароль приложения>
PUBLIC_BASE_URL=https://ваш-адрес
```

`SMTP_PASSWORD` — это **не** пароль аккаунта Google, а «пароль приложения» из
16 символов: Google отвергает обычный пароль (ошибка 535). Получить:
`myaccount.google.com` → Безопасность → Двухэтапная аутентификация → «Пароли
приложений» → создать пароль для «Почта». `PUBLIC_BASE_URL` — внешний адрес
сервера, иначе ссылка из письма ведёт на `127.0.0.1`, то есть на компьютер
ученика. Доступ к журналу сервера есть только у владельца, но в режиме показа в
нём лежат токены — на публичном сервере так работать нельзя.

## Страницы

- **Главная** — для гостя рассказ о тьюторе; для ученика — продолжить занятие,
  итоги и ближайшие шаги маршрута.
- **Мои курсы** — каталог курсов (основной mlcourse, курс ИСИТ и демо-курс «Деревья решений и случайный лес» на один модуль) и запись на курс.
- **Занятие** — слева теория, практика и редактор кода, справа чат с
  тьютором. Соотношение 70/30 меняется ползунком (мышью или клавиатурой) и
  запоминается. На телефоне — переключатель «Урок / Чат».
- **Объясни новичку** — вкладка занятия: после важного занятия ученик
  объясняет его новичку (см. ниже).
- **Профиль** — имя, пароль, тема оформления, итог анкеты и прогресс по темам.
- **Админка** (только админам) — ученики, карточка ученика, аналитика курса
  и раздел **«Курсы»**: преподаватель заводит свой курс, собирает его вручную
  или генерирует из материалов.

## Свой курс

Преподаватель (роль админа) заводит курс в разделе **Админка → Курсы**:
название, описание, источники — файлы с компьютера (`.md`, `.txt`, `.html`,
блокноты `.ipynb`), ссылка на страницу или на репозиторий GitHub. Источники
складываются в `data/courses/<id>/sources/` и дают курсу собственный поиск по
материалам.

**Структура курса — сначала.** Кнопка «Составить структуру» просит модель
предложить, из каких модулей состоит курс: название, что в каждом и сколько
занятий. Это один вызов, и его результат преподаватель правит руками. Дальше
модули генерируются **по структуре**: из неё берутся название модуля и число
занятий, а в промпт идёт место модуля в курсе (что было до и что будет после) —
поэтому соседние модули не повторяют друг друга.

**Генерация** собирает модуль за раз: план, анкету, конспекты,
задания разделов и итоговое задание с кодом — это 15–30 вызовов модели, то есть
минуты и деньги. Прогон идёт в фоне с прогрессом по шагам и кнопкой отмены;
состояние лежит в `generation/run.json`, поэтому сбой шага продолжается с него,
а не с начала модуля. Что получилось, преподаватель **смотрит и правит** —
занятия, разделы, задания с вариантами и тестами, рубрики, анкету модуля и
конспекты — и нажимает «Опубликовать». Переделать можно не модуль целиком, а
один шаг: конспект занятия, задания раздела или итоговое задание (это один
вызов модели вместо восемнадцати). Код-задания сервер проверяет запуском:
тесты обязаны падать на заготовке и проходить на эталонном решении, которое
модель даёт вместе с заданием. До публикации занятие можно посмотреть глазами
ученика, а ненужный модуль — удалить (остальные сдвинутся). До публикации курс черновик: ученики его не видят.

Перед публикацией курс обязан пройти ту же проверку, что и встроенный
(`course.seed`): ≥2 задания на раздел, итоговое задание в каждом занятии,
конспект с заголовками разделов по порядку.

## Как идёт занятие

**Анкета.** Первое занятие начинается с короткой адаптивной анкеты (опыт,
цель, время); по ней строится маршрут — путь по графу до цели. Знакомое по
анкете («Уверенно») тьютор проверит в конце.

**Тьютор ведёт по разделам.** Занятие — 2–4 раздела. По каждому тьютор
объясняет частями (кнопка «Дальше») и задаёт вопрос; верный ответ закрывает
раздел, после двух ошибок раздел засчитывается со слабым местом ⚠️. Затем —
итоговое задание занятия (код во вкладке «Код»). Код решает, закрыто ли
занятие (критерий §6.1: пройдены все разделы и итоговое **или** уверенное
владение с малой неопределённостью), и, если закрыто, объявляет следующее.
Кнопка «Закрыть занятие» запускает проверочный проход: по вопросу на раздел и
итоговое. Маршрут пересчитывается при значимых событиях.

**Ученик может притормозить.** «Не понял, давай подробнее» — тема уйдёт в
усиленный проход: счётчик успехов обнулится, тьютор даст другое объяснение,
пример и выдержку из материала. Флаг ставит модель (`student_stuck`), решение
о переходе принимает код.

**Чат** ведёт тьютор в сократовском режиме: отвечает с опорой на материалы
курса и повышает уровень подсказки (намёк → наводящий вопрос → частичное
решение → разбор), когда ученик застревает. Уровень выбирает модель, но код не
даёт поднять его больше чем на шаг за ход и выше четвёртого. Вопросы **рядом с
курсом** тоже поддерживаются: если в материалах ничего не нашлось, тьютор
отвечает по своим знаниям и честно помечает, что это не из курса (такие ответы
не меняют портрет ученика).

**Код** запускается в браузере (Pyodide в Web Worker, зависший код
останавливается через 10 секунд). «Проверить» выполняет тесты задания, итог
уходит на сервер, и вердикт записывает ядро как событие автопроверки. Тесты
видны в исходниках страницы — это осознанная цена проверки на стороне ученика.

Состояние занятия (текущая тема, фаза, уровень подсказки, маршрут, выданное
задание) лежит в БД ученика, поэтому перезапуск сервера его не теряет.

Задания `choice`/`short` проверяются кодом, без обращения к модели. Открытые
и код-ответы оценивает рубричный грейдер: модель сверяет ответ с бинарными
критериями и обязана подтвердить каждый **дословной цитатой**, а код затем
проверяет, что цитата действительно есть в ответе — не подтверждённый
цитатой критерий не засчитывается. Итоговый балл считает код по весам, и
событие идёт в журнал с ограниченным весом (`RUBRIC_EVIDENCE_WEIGHT`).

Чтобы дополнить банк — добавь объект в массив `items` в `data/seed_topicNN.json`
нужного модуля (`answer` для `choice` — индекс верного варианта строкой, `section`
— раздел занятия или `final: true` для итогового); он подхватится при следующем
старте. Проверка курса: `uv run python -m llm_tutor.course.seed`. Убранное из seed задание
перестаёт предлагаться, но строку из БД не удаляет: на неё ссылается журнал
событий (то же с концептами).

**Банк небольшой** — от двух заданий на каждый раздел и итоговое задание с кодом
в каждом занятии. Повтор уже
отвеченного задания идёт в зачёт с пониженным весом (`REPEAT_EVIDENCE_WEIGHT`),
чтобы не выдавать его за независимое свидетельство.

## Объясни новичку

После **важного** занятия (14 из 33 — те, у которых в seed есть эталон
`explain`) курс стоит, пока ученик не объяснит его «новичку»: так знание
закрепляется лучше всего. Задание — вкладка «Объясни»: слева большой чат с
новичком, справа тот же чат занятия, но на это время там **наставник** со своей
веткой разговора (объясняет суть, но не пишет объяснение за ученика). Остальные
вкладки закрыты («откроется после объяснения»), конспект и задание урока сервер
не отдаёт. Порядок на границе занятий: закрыто занятие → «Объясни новичку» →
разминка повторения → следующее занятие (или анкета следующего модуля).

Новичка играет модель: знает только прошлые занятия, задаёт наивные вопросы,
путается в противоречиях и время от времени «понимает» с типичной ошибкой, чтобы
ученик её поправил. Задание выполнено, когда все обязательные идеи занятия
объяснены верно (новичок говорит «кажется, понял») или на 10-й реплике ученика;
тогда вкладка показывает отчёт и кнопку «Продолжить». Без задания во вкладке —
история, «Объяснить ещё раз» (добровольно: курс не стоит, есть «Закончить») и
согласие показывать сессии преподавателю.

Как это устроено:

- **Эталон занятия** — раздел `explain` узла в `data/seed_topicNN.json`:
  `ideas` (2–4 идеи: `text`, `required`, `expect`; обязательных ≥ 1) и
  `pitfalls` (1–2 типичные ошибки: `belief` — вопрос новичка, `fix` — почему это
  неверно). Поле `lesson` проставляет загрузчик. Утверждения загвоздок о
  библиотеках проверяет запуск
  `uv run --with numpy,pandas,scikit-learn,matplotlib python scripts/check_explain_claims.py`.
- **Висящее задание вычисляется**, а не хранится флагом
  (`student/explain.pending_lesson`): занятие закрыто в маршруте не раньше факта
  `explain_since` (ставится при первом открытии БД ученика), у него есть эталон и
  нет завершённой обязательной сессии. Так задание появляется при любом пути
  закрытия (ответ, проход знакомого, автозакрытие) и не теряется при сбое хода.
- **Ход — два вызова модели.** Скрытый оценщик (`EXPLAIN_EVALUATOR_MODEL`)
  сверяет реплику с эталоном и возвращает JSON; код проверяет его (верно —
  только с дословной цитатой ученика), ведёт покрытие и выбирает, что новичок
  сделает на этом ходу. Новичку эталон **не передаётся никогда** — на
  «просто дай ответ» ему нечего выдать.
- **Промпты и пороги** — `data/prompts/explain.toml` (каталог — `PROMPTS_DIR`);
  правятся без кода и проверяются при старте приложения.
- **После сессии** код собирает отчёт (покрытие, ошибки и пробелы с эталоном,
  загвоздки, что повторить), пишет события `explain` с весом
  `EXPLAIN_EVIDENCE_WEIGHT` (0.3) и ставит занятия с ошибками и пробелами в
  повторение. Закрытые занятия режим не переоткрывает.
- **Приватность.** Сохраняются только реплики сессии, время ходов и отчёт.
  Админ видит сессии ученика, только если тот включил «Показывать мои сессии
  преподавателю»; каждый просмотр пишется в журнал админов.
- **Ручная проверка.** `uv run python scripts/dev_close_module.py 1` отмечает
  занятия модуля закрытыми «сейчас» — по важным сразу появляются задания.

Пока висит задание, ходы курса отвечают **409** («Сначала объясни новичку «…».»)
и ничего не пишут: `next`, `task`, `answer`, `code-result`, `skip`, `stuck`,
`resume`, `verify`, `switch`, `review/start`. Чат (`lesson/chat`) идёт
наставнику. В добровольной сессии курс не стоит и чат урока остаётся тьютору:
наставник отвечает, когда открыта вкладка «Объясни» (поле `to: "mentor"` у
`lesson/chat`; его ветка — `state.explain.active.mentor`). Если «Продолжить»
не смогло начать следующее занятие, задание всё равно засчитывается, а урок
открывается из «Маршрута».

API (префикс `/api/courses/{course_id}/lesson/explain`, ученик записан на курс;
изменяющие запросы — JSON, всё под замком ученика):

| Запрос | Тело | Ответ |
|---|---|---|
| `POST …/turn` | `{text}` (1–8000 символов, не пробелы) | `messages` (реплика ученика и новичка), `progress`, `state` |
| `POST …/start` | `{node_id}` | добровольная сессия; 400 — занятие не закрыто или не важное, 409 — есть активная или висит задание |
| `POST …/stop` | `{}` | `report` добровольной сессии; обязательную закончить нельзя — 409 |
| `POST …/continue` | `{}` | «Продолжить»: следующее задание, разминка или занятие; 409 — задание не выполнено |
| `GET …/sessions/{id}` | — | `session` с репликами (`messages` — новичок, `mentor` — наставник) и отчётом |
| `POST …/settings` | `{share}` | `share` |

Блок `state.explain` в `GET …/lesson/state`: `active` (идущая сессия, а после
выполнения — завершённая с отчётом), `pending` (занятие с висящим заданием),
`ready` (отчёт есть, можно «Продолжить»), `blocked` (курс стоит), `lessons`
(закрытые важные — для «Объяснить ещё раз»), `history`, `share`. Сессия: `id`,
`kind` (`required`/`voluntary`), `node_id`, `title`, `status`, `messages`,
`mentor`, `progress` (`done`/`total` обязательных идей — без их названий),
`turns_left`, `report`. Ошибки: 403 — нет записи на курс; 404 — нет такой
сессии; 422 — пустой или длинный текст; 502 — модель недоступна (реплика не
записана). Старые адреса `/lesson/<курс>/explain…` ведут на занятие (303).

## Тесты

```bash
uv run pytest                     # весь набор без браузера
uv run pytest -m e2e tests/e2e    # браузерные сценарии (Playwright + Chromium)
```

Для e2e нужен Chromium (`uv run playwright install chromium`). Тест запуска
кода в Pyodide берёт локальную копию npm-пакета `pyodide` из
`E2E_PYODIDE_DIR`; без неё он пропускается.

## Оценка качества грейдера

```bash
uv run python -m llm_tutor.eval.grader_eval
```

Прогоняет грейдер по золотому набору (`data/golden_set_topic01.json`, 20
размеченных ответов) на реальной модели и печатает согласие по критериям
(kappa, точность, полнота), матрицу ошибок и число цитат, которых нет в
ответе. Это грубый фильтр, а не откалиброванная метрика: набор мал, разметка
сделана одним человеком.

Подробнее — `llm-tutor-architecture.md`; перенос в браузер — `docs/superpowers/specs/2026-10-10-web-app-design.md` и одноимённый план. `llm-tutor-implementation-plan.md` — исторический план версии с Telegram-ботом.
