# LLM-тьютор по курсу машинного обучения

Telegram-бот-тьютор на основе LLM, который ведёт ученика по курсу
[mlcourse.ai](https://mlcourse.ai) (пилот — topic01 «Pandas / Exploratory Data Analysis»).

## Стек

- Python 3.12, [uv](https://docs.astral.sh/uv/)
- aiogram 3.x (Telegram-бот)
- OpenRouter API (LLM, слой абстракции модели через конфиг)
- SQLite + FTS5 (RAG и хранилище состояния ученика)
- NetworkX (граф концептов курса)

## Быстрый старт

```bash
uv sync                     # установить зависимости
# заполни OPENROUTER_API_KEY и TELEGRAM_BOT_TOKEN в .env:
#   Windows (cmd/PowerShell): copy .env.example .env
#   macOS/Linux (bash):       cp .env.example .env

# загрузить материалы темы в RAG-индекс (один раз; можно URL или файл):
uv run python -m llm_tutor.course.ingest data/raw/topic01_pandas_data_analysis.md

uv run python -m llm_tutor.bot.main   # запустить бота
```

Граф темы и банк заданий (`data/seed_topic01.json`) грузятся в БД автоматически
при старте бота.

Команды бота:

- `/start` — знакомство: сначала короткая анкета (опыт, цель, время), потом тьютор
- `/task` — задание по текущему маршруту (ответ кнопкой, номером пункта или текстом)
- `/skip` — снять висящее задание, не записывая свидетельство
- `/diagnostic` — «подбор маршрута»: несколько коротких заданий с автопроверкой
- `/plan` — готовые узлы маршрута с режимом прохода

Свободный текст ведёт тьютор в сократовском режиме: он отвечает с опорой на
материалы курса и повышает уровень подсказки (намёк → наводящий вопрос →
частичное решение → разбор), когда ученик застревает. Уровень выбирает модель,
но код не даёт поднять его больше чем на шаг за ход и выше четвёртого.
Состояние занятия (текущий узел, уровень подсказки, выданное задание) лежит в
БД, поэтому рестарт бота его не теряет.

Задания `choice`/`short` проверяются кодом, без обращения к модели. Открытые
и код-ответы оценивает рубричный грейдер: модель сверяет ответ с бинарными
критериями и обязана подтвердить каждый **дословной цитатой**, а код затем
проверяет, что цитата действительно есть в ответе — не подтверждённый
цитатой критерий не засчитывается. Итоговый балл считает код по весам, и
событие идёт в журнал с ограниченным весом (`RUBRIC_EVIDENCE_WEIGHT`).

Задания (`choice`/`short`) — для самопроверки. Чтобы
дополнить банк — добавь объект в массив `items` в `data/seed_topic01.json`
(`answer` для `choice` — индекс верного варианта строкой); он подхватится при
следующем старте. Убранное из seed задание перестаёт предлагаться, но строку
из БД не удаляет: на неё ссылается журнал событий (то же с концептами).

Диагностика может спрашивать только те узлы, для которых есть задание. Узлы
без заданий, от которых зависят другие, бот перечисляет в логе при старте
(`seed.py` печатает их же) — непокрытая база запирает маршрут.

## Тесты

```bash
uv run pytest
```

## Оценка качества грейдера

```bash
uv run python -m llm_tutor.eval.grader_eval
```

Прогоняет грейдер по золотому набору (`data/golden_set_topic01.json`, 20
размеченных ответов) на реальной модели и печатает согласие по критериям
(kappa, точность, полнота), матрицу ошибок и число цитат, которых нет в
ответе. Это грубый фильтр, а не откалиброванная метрика: набор мал, разметка
сделана одним человеком.

Подробнее — `llm-tutor-architecture.md` и `llm-tutor-implementation-plan.md`.
