# LLM-тьютор по курсу машинного обучения

Telegram-бот-тьютор на основе LLM, который ведёт ученика по курсу
[mlcourse.ai](https://mlcourse.ai). В курсе пять модулей:

1. Первичный анализ данных с Pandas
2. Визуальный анализ данных
3. Классификация, деревья решений и kNN
4. Линейные модели классификации и регрессии
5. Бэггинг и случайный лес

## Стек

- Python 3.12, [uv](https://docs.astral.sh/uv/)
- aiogram 3.x (Telegram-бот)
- OpenRouter API (LLM, слой абстракции модели через конфиг)
- SQLite + FTS5 (RAG и хранилище состояния ученика)
- NetworkX (граф концептов курса)

## Быстрый старт

```bash
uv sync                     # установить зависимости
# заполни OPENROUTER_API_KEY и TELEGRAM_BOT_TOKEN в .env:
#   Windows (cmd/PowerShell): copy .env.example .env
#   macOS/Linux (bash):       cp .env.example .env

# загрузить материалы в RAG-индекс (один раз на файл; можно URL или файл);
# --topic — номер модуля, к которому относится материал:
uv run python -m llm_tutor.course.ingest data/raw/topic01_pandas_data_analysis.md --topic 1

uv run python -m llm_tutor.bot.main   # запустить бота
```

Материалы индексируются по модулям: каждый файл из `data/raw/` грузится со
своим `--topic` (`topic02_*.md` — `--topic 2` и т. д.), а `--source-url`
задаёт ссылку на страницу курса для цитат. Ученик видит материалы только
своего и пройденных модулей.

Граф курса и банк заданий (`data/seed_topic01.json` … `seed_topic05.json`)
грузятся в БД автоматически при старте бота: все модули собираются в один граф
(`course.seed.load_course`), рёбра между модулями ведут только от прошлых
модулей к следующим.

Команды бота:

- `/start` — знакомство: сначала короткая анкета (опыт, цель, время), потом тьютор
- `/task` — задание по текущему узлу (ответ кнопкой, номером пункта или текстом)
- `/skip` — снять висящее задание, не записывая свидетельство
- `/diagnostic` — «подбор маршрута»: несколько коротких заданий с автопроверкой
- `/plan` — маршрут к цели: модуль («Модуль N/5»), сколько закрыто, где ты сейчас, что дальше
- `/themes` (кнопка «🎚 Темы») — модули курса, внутри — темы; можно прыгнуть в любую.
  При первом входе в модуль бот задаёт его короткую анкету и начинает урок с выбранной темы
- `/close` — «закрой тему»: проверочный проход по текущей теме
- `/resume` — продолжить занятие с того места, где остановились
- `/status` — сводка прогресса
- `/help` — справка

**Тьютор ведёт.** По цели из анкеты строится маршрут — путь по графу до неё.
Бот выдаёт задание по текущему узлу, после ответа сам решает, закрыт ли узел
(критерий §6.1: два задания подряд верно и без подсказок **или** уверенное
владение с малой неопределённостью), и, если закрыт, объявляет следующий и
сразу выдаёт по нему задание. Маршрут пересчитывается при значимых событиях,
и бот сообщает об изменении — но молчит, если различия малы.

**Ученик может притормозить.** Скажи «не понял, давай подробнее» — узел уйдёт
в усиленный проход: счётчик успехов обнулится, вперёд бот не пойдёт, зато даст
другое объяснение, пример и выдержку из материала. Флаг ставит модель
(`student_stuck`), решение о переходе принимает код.

**Свободный текст** ведёт тьютор в сократовском режиме: отвечает с опорой на
материалы курса и повышает уровень подсказки (намёк → наводящий вопрос →
частичное решение → разбор), когда ученик застревает. Уровень выбирает модель,
но код не даёт поднять его больше чем на шаг за ход и выше четвёртого.
Вопросы **рядом с курсом** тоже поддерживаются: если в материалах темы ничего
не нашлось, тьютор отвечает по своим знаниям и честно помечает, что это не из
материалов курса (такие ответы не пишутся в журнал и не меняют портрет).

Состояние занятия (текущий узел, фаза, уровень подсказки, маршрут, выданное
задание) лежит в БД, поэтому рестарт бота его не теряет.

Задания `choice`/`short` проверяются кодом, без обращения к модели. Открытые
и код-ответы оценивает рубричный грейдер: модель сверяет ответ с бинарными
критериями и обязана подтвердить каждый **дословной цитатой**, а код затем
проверяет, что цитата действительно есть в ответе — не подтверждённый
цитатой критерий не засчитывается. Итоговый балл считает код по весам, и
событие идёт в журнал с ограниченным весом (`RUBRIC_EVIDENCE_WEIGHT`).

Чтобы дополнить банк — добавь объект в массив `items` в
`data/seed_topicNN.json` нужного модуля (`answer` для `choice` — индекс
верного варианта строкой); он подхватится при следующем старте. Убранное из seed задание
перестаёт предлагаться, но строку из БД не удаляет: на неё ссылается журнал
событий (то же с концептами).

**Банк** — 103 темы и 257 заданий, на каждую тему не меньше двух. Поэтому:

- узел закрывается серией из двух чистых ответов; чтобы повтор одного вопроса
  не выдавался за два независимых свидетельства, недавно отвеченное не
  предлагается (`ITEM_REPEAT_COOLDOWN_DAYS`, сутки). Для проверки цикла за
  одно занятие паузу можно убавить — тогда повтор пойдёт в зачёт, но с
  пониженным весом (`REPEAT_EVIDENCE_WEIGHT`);
- задачи на узел выдаются из банка; узлы, от которых зависят другие, бот
  перечисляет в логе при старте (и `seed.py` печатает их же). У непокрытых
  узлов занятие идёт диалогом — бот честно об этом говорит.

## Оценка качества грейдера

```bash
uv run python -m llm_tutor.eval.grader_eval
```

Прогоняет грейдер по золотому набору (`data/golden_set_topic01.json`, 20
размеченных ответов) на реальной модели и печатает согласие по критериям
(kappa, точность, полнота), матрицу ошибок и число цитат, которых нет в
ответе. Это грубый фильтр, а не откалиброванная метрика: набор мал, разметка
сделана одним человеком.

Подробнее — `llm-tutor-architecture.md` и `llm-tutor-implementation-plan.md`.
