# llm_tutor

Веб-приложение — тьютор по курсу mlcourse.ai: 5 модулей в одном графе, от
Pandas/EDA до бэггинга и случайного леса (модули 6–10 не написаны). Несколько
учеников со входом; у каждого ученика своя БД на курс (`user_id` в схеме курса
нет — ученика задаёт файл БД). Курс в вебе один — `mlcourse` (прежний id
`mlcourse-topic01` переадресуется, его БД и записи на курс переносятся).

**Главный принцип:** LLM — интерфейс и генератор текста, а не источник истины.
Состояние ученика, вердикты по заданиям, закрытие узлов считает код; журнал
`events` — источник истины.

## Стек и запуск

Python 3.12, FastAPI + Jinja2 (JS и CSS без сборки), OpenRouter (httpx),
SQLite + FTS5, NetworkX, pydantic 2, менеджер — `uv`. Код ученика выполняется в
браузере: Pyodide в Web Worker, редактор CodeMirror 5 (лежит в `static/vendor`).
Секреты — `.env` (шаблон `.env.example`).

```bash
uv sync
uv run pytest -q                       # весь набор без браузера, ~30 с
uv run pytest -q -m e2e tests/e2e      # Playwright; Pyodide — из E2E_PYODIDE_DIR
uv run python -m llm_tutor.web         # http://127.0.0.1:8000
uv run python -m llm_tutor.web.cli make-admin --email ann@example.com   # раздел /admin
```

## Где что

| Слой | Модули |
|---|---|
| `web/` | `app` (сборка, CSP, статика с `?v=`), `accounts` + `api_auth` + `security` (вход, сессии, Origin, роль админа), `userdb` (пул БД учеников), `api_lesson` (ходы занятия), `views` (данные для шаблонов и API), `pages`, `markdown` (рендер без HTML), `courses`, `cli` (`import-legacy`, `make-admin`, `revoke-admin`) |
| `web/` админка | `admin` (снимок по всем ученикам с кэшем, воронка, трудные задания, карточка ученика), `pages_admin` (`/admin/students`, `/admin/students/{id}`, `/admin/course`), `api_admin` (сброс пароля, закрытие сессий) |
| `web/static/js` | `app` (оболочка, запросы, тема и сайдбар), `prefs` (вид до отрисовки), `lesson` (ход занятия, `act`), `split`, `chat`, `theory`, `practice`, `code` + `pyodide-worker`, `survey`, `route`, `profile`, `courses`, `auth`, `admin` |
| `core/` | `turn` (ход: ответ на задание / тьютор, вход в узел, закрытие, переход между модулями), `guided` (урок по частям, «ответ или реплика»), `verify` (проверочный проход), `lesson` (статусы тем, переход, анкета модуля, начало урока), `overview`, `context` (пакет промпта), `intents` |
| `student/` | `survey` (адаптивная анкета по конфигу модуля, `Progress`), `route` (маршрут, рабочий участок модуля, статусы шагов), `planner` (приоритет, режимы), `beta` (модель владения), `guide` (критерий закрытия), `diagnostic` (выбор задания по узлу, запись свидетельств) |
| `course/`, `rag/`, `grader/`, `llm/`, `db/` | граф и seed (`load_course` — все модули), поиск по материалам, автопроверка и рубрики, клиент и промпты, репозитории |

Данные: `data/seed_topicNN.json` — по файлу на модуль (граф занятий с
разделами, банк заданий, анкета модуля в разделе `topic`, таблица `legacy`
«старая тема → занятие/раздел»); 33 занятия из 96 разделов. Задания с кодом
несут `starter`/`setup`/`tests` и рубрику, итоговое задание занятия —
`final`. Модуль, у которого не готово содержание, — `published: false`
(«скоро»); с среза 61 опубликованы все пять модулей. `data/theory/topicNN/<занятие>.md` — конспект занятия, раздел —
заголовок `## <название раздела>`. Правила занятий проверяет
`course/seed._check_lessons` (`MAX_LESSONS = 10`). Курс собран из 103 тем
скриптом `scripts/build_lessons.py` — одноразовым: seed после него правятся
руками, повторный запуск затрёт правки.

Тестовые курсы: `tests/legacy_course.py` — старый формат (103 темы, копия в
`tests/fixtures/legacy_v1`): на нём тесты движка; `tests/course_fixtures.py`
— мини-модули; `tests/fixtures/lessons` (`load_lessons`, `use_lessons_course`
для веба) — курс занятий из двух открытых модулей. Открытые находки ревью —
`problems.md`.

## Процесс

Брейншторм → спека → план → реализация срезами по TDD → **адверсариальное
ревью каждого среза отдельным агентом** (находки воспроизводятся запуском
кода, ревьюер ничего не правит) → триаж → фиксы отдельным коммитом с
регрессионными тестами.

## Конвенции

- Комментарии, докстринги и коммиты пишутся по-русски. Формат коммита: `Срез N: …`,
  `Аудит среза N: …`.
- Слои: `web → core/student/db`. `core/*` и `student/*` не импортируют `web/*`.
- Вывод: `core.*` отдаёт **сырой** текст (Markdown). В веб он попадает через
  `web.markdown.render` (HTML запрещён, ссылки только http(s)) или как
  `textContent` в JS. `innerHTML` — только для HTML, отрендеренного сервером.
- CSP без `unsafe-inline`: никаких встроенных `<script>` и `style=""`; ширины и
  проценты ставит JS через CSSOM. Новые внешние адреса — только через
  `content_security_policy`.
- Схема БД меняется только миграциями (`migrations/` — БД ученика,
  `migrations_accounts/` — аккаунты). Новые поля состояния кладутся в
  `SessionState` (JSON) с дефолтами.
- Тесты асинхронные без декоратора (`asyncio_mode=auto`). Веб — через
  фикстуры `web`/`student` (`tests/conftest.py`), подставной тьютор — в
  `tests/web_fakes.py`. Браузерные — с маркером `e2e`, шаги в `tests/e2e/helpers.py`.

## Подводные камни

- **Атомарность хода** держится на `asyncio.Lock` ученика (`userdb`): всё
  внутри `async with ctx.lock` выполняется без чужих ходов этого ученика.
  Замок живёт в процессе — запускать один воркер uvicorn.
- Подпись `"Уверенно"` в `student/survey.SELF_LEVELS` **не менять**. По ней
  узлы получают статус маршрута `claimed` (🔍): знакомое по анкете, его
  проверяют в конце.
- SQLite в вебе открывается с `check_same_thread=False`: соединение из пула
  используется не в том потоке, где открыто.
- Тёмные токены в `tokens.css` записаны дважды (выбранная тема и системная) —
  правятся парно, `tests/test_audit_48.py` сверяет копии.
- Windows: вставка многострочного Python через heredoc в stdin путает `\n` в
  строковых литералах. Точечные правки делай инструментом Edit.
- Перенос прогресса (срез 56): `course/legacy.remap_progress` при открытии
  БД ученика (`userdb`) — один раз, только если в БД есть следы старых тем;
  отметка — факт `course_layout = "2"`. Пройденное незакрытых занятий и
  занятий неопубликованных модулей ждёт в факте `legacy_passed_sections`.
- `CourseGraph.load` не видит узлы неопубликованных модулей. Тестам данных
  курса нужен граф целиком — `CourseGraph(course.nodes, course.edges)`.
- Агента типа `fork` в окружении может не быть. Тогда ревью делает
  `general-purpose` с самодостаточным ТЗ.
- **Модули грузятся только вместе** — через `load_course` (в вебе — `courses.course_data` + `apply_course`). `load_seed` берёт
  один файл как весь курс и гасит остальные модули.
- **Межмодульные рёбра — только назад** (от прошлого модуля к следующему),
  иначе `CourseGraphError`. Жёсткое межмодульное ребро валидно, но `seed`
  печатает о нём предупреждение — обосновывай в коммите.
- Урок по частям (срез 28): вход в тему — части объяснения и кнопка
  «Дальше»/«Проверим», задание — после последней части. В вебе кнопку рисует
  `state.lesson_button` (из `SessionState`, переживает перезагрузку), ход —
  `POST /lesson/next`.
  Тему закрывает один верный ответ; вторая ошибка — тема закрывается слабой (⚠️).
- `core/guided` не импортирует `core/turn`, а `core/lesson` импортирует: иначе
  цикл импорта.
- Занятие с разделами (срез 54): урок частями объясняет **текущий раздел**
  (`state.section_id`), вопрос — из этого раздела, после разделов — итоговое
  задание; закрывает занятие `guide.is_node_closed(..., sections=…)`. Любая
  смена занятия обязана обнулять `guide.SECTION_RESET`. В промпт идёт текст
  только текущего раздела (`seed.section_text`) и оглавление занятия.
- Дистрактор, который что-то утверждает о поведении библиотеки, проверяй
  запуском (`uv run --with numpy,pandas,scikit-learn python <скрипт>`): трижды
  «ложный» вариант оказывался верным (3046, 4037, 5029/5044).
- Конспекты и задания модулей (срезы 57–61). Примеры конспекта исполняются тестом
  с предупреждениями-ошибками: `plt.show()`/`fig.show()` и `sns.boxplot`
  (matplotlib 3.11 + seaborn 0.13.2 дают `vert`-предупреждение — ящики рисует
  `df.boxplot`) в примеры не попадают. Задание с кодом проверяется в
  `tests/test_seed_code_items.py`: эталон, неверные решения (`WRONG`,
  `MORE_WRONG`) и верные альтернативы на каждое; все тесты задания обязаны
  падать с `AssertionError` на заготовке и без `result`. Модули 3–5 — scikit-learn
  на данных из `setup` (API не новее 1.6, как в Pyodide); время проверки в
  браузере не меряется без `E2E_PYODIDE_DIR`.
- **Админка** (срезы 63–68). Роль — `users.is_admin`, выдаёт её только CLI
  `make-admin`, из веба — никак. Не-админу `/admin*` и `/api/admin*` отвечают
  тем же 404, что и несуществующая страница (гость — редирект на вход / 401);
  защита стоит зависимостью на роутере (`security.admin_user` /
  `admin_page_user`), а не в каждой функции. Роль читается из БД на каждый
  запрос — снятие действует сразу.
- Снимок админки (`admin.snapshot`) читает БД учеников **синхронно, без
  `await`**, и пропускает ученика, у которого идёт ход (`pool.lock(...)
  .locked()`): соединение общее, а ход может не успеть закоммитить. Такой
  ученик берётся из прошлого снимка. Кэш — `app.state.admin_cache`, 60 с;
  по замеру (срез 67) около 6 мс на ученика, при ~200 учениках нужна сводная
  таблица. Диалоги (`messages`) админка не показывает.
  Ядро пишет по событию `events` на каждый концепт задания (`plan_evidence`,
  один `ts`): ответы в админке считаются свёрткой по `(item_id, ts, source)`.
  `events.hints_used`/`time_spent` нигде не заполняются — столбцов про них
  в админке нет.
- Временный пароль (`/api/admin/.../reset-password`) уходит только в ответе с
  `no-store` и не пишется ни в лог, ни в `admin_log`. Диалог с паролем на
  странице очищает поле синхронно: событие `close` у `<dialog>` приходит на
  такт позже скрытия.
- Тесты админки: пути маршрутов берутся из `app.openapi()` — в FastAPI 0.143
  `app.routes` не раскрывает включённые роутеры. Модуль `llm_tutor.web.admin`
  в тестах импортируется как `admin_data`: имя `admin` занято фикстурой.
- Тесты не должны зависеть от `.env`: передавай фикстуру `settings` во всё, что
  иначе зовёт `get_settings()`.
