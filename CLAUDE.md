# llm_tutor

Веб-приложение — тьютор по курсу mlcourse.ai: 5 модулей в одном графе, от
Pandas/EDA до бэггинга и случайного леса (модули 6–10 не написаны). Несколько
учеников со входом; у каждого ученика своя БД на курс (`user_id` в схеме курса
нет — ученика задаёт файл БД). Основной курс — `mlcourse` (прежний id
`mlcourse-topic01` переадресуется, его БД и записи на курс переносятся); рядом встроенные
`isit-ml` и демо-мини-курс `trees-demo` (один модуль, 5 занятий).

**Главный принцип:** LLM — интерфейс и генератор текста, а не источник истины.
Состояние ученика, вердикты по заданиям, закрытие узлов считает код; журнал
`events` — источник истины.

## Стек и запуск

Python 3.12, FastAPI + Jinja2 (JS и CSS без сборки), OpenRouter (httpx),
SQLite + FTS5, NetworkX, pydantic 2, менеджер — `uv`. Код ученика выполняется в
браузере: Pyodide в Web Worker, редактор CodeMirror 5 (лежит в `static/vendor`).
Секреты — `.env` (шаблон `.env.example`).

```bash
uv sync
uv run pytest -q                       # весь набор без браузера, ~30 с
uv run pytest -q -m e2e tests/e2e      # Playwright; Pyodide — из E2E_PYODIDE_DIR
uv run python -m llm_tutor.web         # http://127.0.0.1:8000
uv run python -m llm_tutor.web.cli make-admin --email ann@example.com   # раздел /admin
```

Курсы: встроенный `mlcourse` описан кодом и читает модули из `data/`. Курс,
созданный преподавателем, — папка `data/courses/<id>/`: `course.json`
(метаданные, статус `draft`/`published`, счётчики id), `seed_topicNN.json`,
`theory/topicNN/`, `sources/` (сырьё), `generation/` (артефакты прогонов),
свой `materials.sqlite3`. Реестр — сканирование каталога.

Демо-курс `trees-demo` — встроенный (`web/courses.COURSES`), модуль лежит в `data/demo/`: **копии** занятий
`tree_criteria`/`tree_building`/`tree_tuning` (модуль 3) и `bagging_basics`/`forest` (модуль 5) с заданиями и
конспектами; правки заданий делаются в исходных seed и переносятся копированием (проверяет
`tests/test_demo_course.py`). Задание копируется, только если его главный концепт — занятие демо (раздел
задания — раздел главного концепта). Материалы RAG у него свои (`Course.materials_path`): общий файл дал бы
номера модулей другого курса.

Данные: `data/seed_topicNN.json` — по файлу на модуль (граф занятий с
разделами, банк заданий, анкета модуля в разделе `topic`, таблица `legacy`
«старая тема → занятие/раздел»); 33 занятия из 96 разделов. Задания с кодом
несут `starter`/`setup`/`tests` и рубрику, итоговое задание занятия —
`final`. Модуль, у которого не готово содержание, — `published: false`
(«скоро»); со среза 61 опубликованы все пять модулей. `data/theory/topicNN/<занятие>.md` — конспект занятия, раздел —
заголовок `## <название раздела>`. Правила занятий проверяет
`course/seed._check_lessons` (`MAX_LESSONS = 10`). Курс собран из 103 тем
скриптом `scripts/build_lessons.py` — одноразовым: seed после него правятся
руками, повторный запуск затрёт правки.

Тестовые курсы: `tests/legacy_course.py` — старый формат (103 темы, копия в
`tests/fixtures/legacy_v1`): на нём тесты движка; `tests/course_fixtures.py`
— мини-модули; `tests/fixtures/lessons` (`load_lessons`, `use_lessons_course`
для веба) — курс занятий из двух открытых модулей. Открытые находки ревью —
`problems.md`.

## Процесс

Брейншторм → спека → план → реализация срезами по TDD → **адверсариальное
ревью каждого среза отдельным агентом** (находки воспроизводятся запуском
кода, ревьюер ничего не правит) → триаж → фиксы отдельным коммитом с
регрессионными тестами.

## Конвенции

- Комментарии, докстринги и коммиты пишутся по-русски. Формат коммита: `Срез N: …`,
  `Аудит среза N: …`.
- Слои: `web → core/student/db`. `core/*` и `student/*` не импортируют `web/*`.
- Вывод: `core.*` отдаёт **сырой** текст (Markdown). В веб он попадает через
  `web.markdown.render` (HTML запрещён, ссылки только http(s)) или как
  `textContent` в JS. `innerHTML` — только для HTML, отрендеренного сервером.
- CSP без `unsafe-inline`: никаких встроенных `<script>` и `style=""`; ширины и
  проценты ставит JS через CSSOM. Новые внешние адреса — только через
  `content_security_policy`.
- Схема БД меняется только миграциями (`migrations/` — БД ученика,
  `migrations_accounts/` — аккаунты). Новые поля состояния кладутся в
  `SessionState` (JSON) с дефолтами.
- Тесты асинхронные без декоратора (`asyncio_mode=auto`). Веб — через
  фикстуры `web`/`student` (`tests/conftest.py`), подставной тьютор — в
  `tests/web_fakes.py`. Браузерные — с маркером `e2e`, шаги в `tests/e2e/helpers.py`.

## Подводные камни

- **Атомарность хода** держится на `asyncio.Lock` ученика (`userdb`): всё
  внутри `async with ctx.lock` выполняется без чужих ходов этого ученика.
  Замок живёт в процессе — запускать один воркер uvicorn.
- Подпись `"Уверенно"` в `student/survey.SELF_LEVELS` **не менять**. По ней
  узлы получают статус маршрута `claimed` (🔍): знакомое по анкете, его
  проверяют в конце.
- SQLite в вебе открывается с `check_same_thread=False`: соединение из пула
  используется не в том потоке, где открыто.
- Тёмные токены в `tokens.css` записаны дважды (выбранная тема и системная) —
  правятся парно, `tests/test_audit_48.py` сверяет копии.
- Windows: вставка многострочного Python через heredoc в stdin путает `\n` в
  строковых литералах. Точечные правки делай инструментом Edit.
- Перенос прогресса (срез 56): `course/legacy.remap_progress` при открытии
  БД ученика (`userdb`) — один раз, только если в БД есть следы старых тем;
  отметка — факт `course_layout = "2"`. Пройденное незакрытых занятий и
  занятий неопубликованных модулей ждёт в факте `legacy_passed_sections`.
- `CourseGraph.load` не видит узлы неопубликованных модулей. Тестам данных
  курса нужен граф целиком — `CourseGraph(course.nodes, course.edges)`.
- Агента типа `fork` в окружении может не быть. Тогда ревью делает
  `general-purpose` с самодостаточным ТЗ.
- **Модули грузятся только вместе** — через `load_course` (в вебе — `courses.course_data` + `apply_course`). `load_seed` берёт
  один файл как весь курс и гасит остальные модули.
- **Межмодульные рёбра — только назад** (от прошлого модуля к следующему),
  иначе `CourseGraphError`. Жёсткое межмодульное ребро валидно, но `seed`
  печатает о нём предупреждение — обосновывай в коммите.
- Урок по частям (срез 28): вход в тему — части объяснения и кнопка
  «Дальше»/«Проверим», задание — после последней части. В вебе кнопку рисует
  `state.lesson_button` (из `SessionState`, переживает перезагрузку), ход —
  `POST /lesson/next`.
  Тему закрывает один верный ответ; вторая ошибка — тема закрывается слабой (⚠️).
- `core/guided` не импортирует `core/turn`, а `core/lesson` импортирует: иначе
  цикл импорта.
- Занятие с разделами (срез 54): урок частями объясняет **текущий раздел**
  (`state.section_id`), вопрос — из этого раздела, после разделов — итоговое
  задание; закрывает занятие `guide.is_node_closed(..., sections=…)`. Любая
  смена занятия обязана обнулять `guide.SECTION_RESET`. В промпт идёт текст
  только текущего раздела (`seed.section_text`) и оглавление занятия.
- **Недописанное занятие не запирает ученика** (правка от 2026-10-14). Раздел,
  по которому в банке нет ни одного задания, лежит в `state.skipped_sections`:
  он не «пройден» (ученик ничего не доказывал) и не держит занятие — вопрос
  берётся из следующего раздела с заданиями. Итоговое задание требуется,
  только если оно в банке есть (`diagnostic.has_lesson_item` →
  `guide.is_node_closed(final_required=…)`). Когда спрашивать нечего, ход сам
  закрывает занятие и ведёт дальше, а не отвечает «заданий нет». Валидатор seed
  на недописанное **содержание** опубликованного модуля (тонкий раздел, нет
  итогового, нет конспекта, нет заголовка раздела) печатает предупреждение и
  лишь **формат** считает ошибкой: открыть модуль по частям автор вправе.
- Дистрактор, который что-то утверждает о поведении библиотеки, проверяй
  запуском (`uv run --with numpy,pandas,scikit-learn python <скрипт>`): трижды
  «ложный» вариант оказывался верным (3046, 4037, 5029/5044).
- Конспекты и задания модулей (срезы 57–61). Примеры конспекта исполняются тестом
  с предупреждениями-ошибками: `plt.show()`/`fig.show()` и `sns.boxplot`
  (matplotlib 3.11 + seaborn 0.13.2 дают `vert`-предупреждение — ящики рисует
  `df.boxplot`) в примеры не попадают. Задание с кодом проверяется в
  `tests/test_seed_code_items.py`: эталон, неверные решения (`WRONG`,
  `MORE_WRONG`) и верные альтернативы на каждое; все тесты задания обязаны
  падать с `AssertionError` на заготовке и без `result`. Модули 3–5 — scikit-learn
  на данных из `setup` (API не новее 1.6, как в Pyodide); время проверки в
  браузере не меряется без `E2E_PYODIDE_DIR`.
- **Повторение по расписанию** (срезы 79–83). Расписание — таблица `review_schedule`
  (лестница 1→3→7→14→30→60 дней, `student/review.LADDER_DAYS`), а **не**
  `mastery.next_review`: поле по-прежнему пишется, но маршрут и планировщик его не
  читают. Просрочка закрытое занятие не переоткрывает (переоткрывают провалы,
  `REOPEN_FAILURES`), из приоритета выпала срочность (`priority_w4` в конфиге
  оставлен ради старых `.env`), а режим `"review"` лежит в `NodeMode`/`MODE_LABELS`
  только ради сохранённых снимков маршрута. Строки создаёт `core.turn.post_turn` по
  разнице маршрутов «было/стало закрыто» (все пути закрытия, один коммит с ходом;
  в режиме `skip` или после прохода — ступень 2); старым ученикам — `review.backfill`
  в `userdb.open` один раз (факт `review_backfill`; шаги снимка с id вне `concepts`
  пропускаются — иначе внешний ключ ронял бы открытие БД навсегда). Лимит 10 сроков
  в день UTC — только для первых сроков, не для отсрочек. Верный ответ по
  непросроченной строке расписание не меняет (даже с подсказкой): «Освежить»
  интервал не сокращает. `due_lessons` читает банк один раз на все занятия (на 33
  занятиях 10 мс против 280).
- **Серия повторения** — `SessionState.review` (`ReviewState`); поля урока она не
  читает и не пишет. Ответ засчитывается **занятию задания** (`seed.main_concept`),
  а не `current_node_id`: разминка перед занятием 7 зачитывает занятию 3. Импорт в
  одну сторону: `core/review` → `core/turn`; разминку ставит сам `handle_turn`
  (`_warmup`, только на границе занятий в блоке `closed_note`; занятие, закрытое этим
  ходом, не спрашивается), а конец разминки (ответ, пропуск, `stop`) начинает
  отложенное занятие в `core/review._begin_lesson` — поэтому `start`/`skip`/`stop`
  async (урок зовёт модель). Занятие, ушедшее из графа, пока серия висит,
  пропускается (`issue_review_item`). Чат серии строится по виду состояния
  (`review._view`, в БД не пишется); реплики серии несут `messages.meta.review`, а
  `core.context` помечает их в хвосте диалога.
- **Развилка ходов в `web/api_lesson` при `state.review`**: `answer`/`code-result`
  принимают только `review.item_id` (задание урока и опоздавший результат кода —
  409, событий нет), `chat`/`stuck`/`skip` идут в `core/review`; `switch`/`task`/`verify`
  и живая кнопка `next` сначала снимают серию (`abort`, расписание не трогается);
  `next` в разминке = «Пропустить разминку» (оставшиеся откладываются на сутки).
  Устаревшая кнопка `next` (тема/часть не совпали) серию не трогает. Ходы повторения
  — `POST …/lesson/review/start|stop|settings`; переключатель — факт `review_enabled`
  (выключено: нет разминки и числа на главной, вкладка и расписание работают).
  Карточка курса несёт `review_due` и `review_overdue` (порядок блока «Повторить
  сегодня»). Bodyless-`POST` в API требует `json={}` (`api_guard`).
- **Админка** (срезы 63–69). Роль — `users.is_admin`. Первого админа
  назначает CLI `make-admin`; дальше роль выдаёт и снимает админ на карточке
  ученика (срез 69), себе — нельзя (400): иначе можно остаться без админки.
  Не-админу `/admin*` и `/api/admin*` отвечают
  тем же 404, что и несуществующая страница (гость — редирект на вход / 401);
  защита стоит зависимостью на роутере (`security.admin_user` /
  `admin_page_user`), а не в каждой функции. Роль читается из БД на каждый
  запрос — снятие действует сразу.
- Снимок админки (`admin.snapshot`) читает БД учеников **синхронно, без
  `await`**, и пропускает ученика, у которого идёт ход (`pool.lock(...)
  .locked()`): соединение общее, а ход может не успеть закоммитить. Такой
  ученик берётся из прошлого снимка. Кэш — `app.state.admin_cache`, 60 с;
  по замеру (срез 67) около 6 мс на ученика, при ~200 учениках нужна сводная
  таблица. Диалоги (`messages`) админка не показывает.
  Ядро пишет по событию `events` на каждый концепт задания (`plan_evidence`,
  один `ts`): ответы в админке считаются свёрткой по `(item_id, ts, source)`.
  `events.hints_used`/`time_spent` нигде не заполняются — столбцов про них
  в админке нет.
- **Вопрос по выделенному фрагменту** (срезы 76–78). Фрагмент — поле `quote`
  хода `chat` → `core.context.Focus`; в журнал — только в `messages.meta`
  реплики ученика (`{"quote": …}`), реплика — сам вопрос. Намерения
  разбираются **только по вопросу**: «пропусти» внутри фрагмента — не команда.
  Тексты готовых кнопок — `core.context.FOCUS_QUESTIONS`, их копия в
  `static/js/selection.js` (сверяет тест); ни один не должен ловиться
  `intents.detect` («объясни подробнее» — намерение «не понял»). Код во
  фрагменте не `strip()`-ится, а выравнивается (`focus_text`), иначе модель
  видит ложную ошибку отступа. Цитата конспекта/задания в истории — дословно,
  без повторного Markdown. В редакторе Tab — отступ, к панели ведёт Alt+F10.
  Во фрагменте не больше `FOCUS_MAX_LINES = 20` непустых строк (срез 84): браузер
  гасит кнопки с подсказкой, сервер — 422. Строки считаются до обрезки по знакам;
  `LINE_BREAK`/`BLANK` в `selection.js` повторяют `splitlines`/`strip` (сверяет тест).
  Ctrl+A в источнике — блок под курсором, повторный — весь источник.
- Временный пароль (`/api/admin/.../reset-password`) уходит только в ответе с
  `no-store` и не пишется ни в лог, ни в `admin_log`. Диалог с паролем на
  странице очищает поле синхронно: событие `close` у `<dialog>` приходит на
  такт позже скрытия.
- Тесты админки: пути маршрутов берутся из `app.openapi()` — в FastAPI 0.143
  `app.routes` не раскрывает включённые роутеры. Модуль `llm_tutor.web.admin`
  в тестах импортируется как `admin_data`: имя `admin` занято фикстурой.
- Тесты не должны зависеть от `.env`: передавай фикстуру `settings` во всё, что
  иначе зовёт `get_settings()`.
- **Курсы преподавателя** (срезы A–K). Курс — папка `data/courses/<id>/`;
  реестр (`web/courses.py`) сканирует её и **хранит состояние на процесс**:
  второй `create_app` в том же процессе переключит каталог и для первого
  (в бою процесс один, в тестах каталог задаёт фикстура `courses_home`).
- Черновик курса ученику неотличим от несуществующего: 404 в каталоге, в записи
  и в занятии (`courses.student_course`). Нечитаемый **опубликованный** курс не
  роняет сайт: карточка помечается `status="error"`, запись отвечает 503.
- Два разных «опубликовано»: `course.json → status` — виден ли курс ученикам;
  `topic.published` в seed — **готов ли модуль** (включает строгую
  `_check_lessons`: ≥2 задания на раздел, итоговое задание, конспект с
  `## <раздел>` по порядку). Генерация пишет сразу готовые модули, ручной
  редактор — с `published: false`, а публикация выставляет флаг всем.
- **Id заданий, рубрик и критериев выдаёт сервер** счётчиками курса
  (`store.allocate_ids`) и только вперёд: `repos.replace_seed` делает upsert по
  id и гасит отсутствующие, поэтому повтор id переписал бы журнал ученика.
  Редактор берёт новые id у `POST /api/admin/courses/{id}/ids`.
- Материалы RAG — свои у каждого курса (`<курс>/materials.sqlite3`): общий файл
  один на приложение, а `chunks.topic_id` — номер модуля внутри курса, и модули
  двух курсов столкнулись бы (тьютор цитировал бы чужой курс).
- `UserDBPool.open` применяет seed только при первом открытии, а соединение
  кэширует до конца процесса: после любой правки курса нужен
  `pool.invalidate_course(id)`, иначе ученик останется со старым занятием.
- Порядок создания курса: **сначала структура курса** (какие модули и что в
  них, один вызов модели, `generation/course_plan.json`), потом модули по ней.
  Структура задаёт название модуля и число занятий (модель не может назвать
  модуль по-своему), а в промпт плана модуля идёт его место в курсе — иначе
  соседние модули повторяют друг друга. `steps.check_course_plan` требует
  модулей ≥2 и номеров подряд с 1.
- Генерация модуля — десятки вызовов модели (≈15–30) и минуты, поэтому она
  идёт фоновой задачей (`web/jobs.py`), а состояние каждого шага лежит в
  `generation/run.json`: сбой шага продолжается с него, а не с начала модуля.
  Браузер опрашивает прогресс раз в 2 с — в 90-секундный таймаут запроса это
  не упирается. Модель генерации — отдельная (`GENERATOR_MODEL`): лимит вывода
  и таймаут у `LLMClient` заданы на клиента целиком.
- Промпты генерации несут **явный образец JSON** с точными именами полей:
  описаний полей в схемах слабым и бесплатным моделям не хватает, и они
  выдумывают свои имена. Модели с «размышлениями» тратят на них лимит вывода —
  если ответ приходит пустым, `client._extract_content` показывает причину
  остановки и число токенов, а лечится это поднятием `GENERATION_MAX_TOKENS`.
- **Переделка куска модуля** (`POST …/generate` с `part=theory|items|final|plan|survey`)
  переспрашивает модель только за нужный шаг: остальные берутся готовыми
  артефактами. Переделка конспекта — один вызов вместо восемнадцати.
- **Код-задания проверяются запуском** (`course/build/check.py`): `tests` обязаны
  падать на `starter` и проходить на `solution` (эталон просим у модели вместе с
  заданием). Запуск — отдельным процессом с таймаутом, потому что код пришёл от
  модели. Нет pandas на сервере — честное «не проверено», а не молчание.
- **Предпросмотр**: админ может записаться на черновик и пройти его как ученик
  (страница занятия помечается «Черновик»); обычному ученику тот же адрес — 404.
- Модуль можно **удалить** (`DELETE …/modules/{n}`) — файлы и строка структуры
  уходят, остальные модули сдвигаются, номера остаются подряд с 1. Прогресс
  учеников (события журнала) при этом не трогается.
- Загрузка файлов идёт **текстом в JSON** (браузер читает файл сам): в проекте
  нет `python-multipart`, а `security.api_guard` пропускает только
  `application/json` (и запросы без тела — `DELETE` без данных).
- **«Объясни новичку»** (срезы 85–96). Эталон — в **занятии**: `explain` узла в seed
  (2–4 идеи, ≥ 1 обязательная, 1–2 загвоздки, `belief` — вопрос; формат проверяет
  `seed._check_lesson_explain`; поле `lesson` проставляет загрузчик, а не файл).
  Такие занятия — «важные» (14 из 33). **Висящее задание вычисляется, а не хранится
  флагом** (`student/explain.pending_lesson`: занятие закрыто в снимке маршрута не раньше
  факта `explain_since`, у него есть эталон и нет завершённой обязательной сессии), поэтому
  оно появляется при любом пути закрытия. `explain_since` ставит `userdb.open` один раз:
  ранее закрытые занятия заданий не дают. Пока задание висит, ходы `lesson/*` (десять)
  отвечают 409 без записей (`api_lesson._require_no_explain`, внутри замка и до проверки
  анкеты), а `views.lesson_state` не отдаёт `node` и `item` — конспект скрыт **сервером**;
  `lesson/chat` идёт наставнику. Слои: `core/explain → core/turn, core/review`;
  `core/turn` знает только `student/explain` (граница занятий держит `EXPLAIN_NOTE`).
  «Продолжить» (`core/explain.proceed`) отмечает `proceeded` и пишет ход одним коммитом.
  **Новичку эталон не передаётся никогда** (`core/explain.novice_messages`; держит тест):
  ни `text`/`expect` идей, ни `fix` загвоздок, ни ответы наставника в хвосте. Оценщик —
  отдельная модель (`EXPLAIN_EVALUATOR_MODEL`), его сбой ход не роняет; сбой новичка —
  502 без записи. `correct` и `wrong` засчитываются только с дословной цитатой
  ученика, непроверенная цитата снимается, а `contradiction` оценщика доходит до
  новичка, только если это слова ученика, и в ограждении
  (`student/explain.clean_observation`): иначе через него утёк бы эталон.
  Установка, которую новичок не произнёс (повтор `strict`, запасной вопрос),
  в состоянии не отмечается. События идут источником `explain`, и
  `route._failures_since` их **пропускает** — иначе две ошибки объяснения
  переоткрыли бы занятие. Реплики сессии — `explain_turns`, не `messages`.
  Промпты — `data/prompts/explain.toml`: тексты проходят `str.format`,
  буквальные фигурные скобки удвоены; файл проверяется в `create_app`.
  Загвоздки про поведение библиотек проверяет `scripts/check_explain_claims.py`.
  Согласие показывать сессии админу — факт `explain_share`.

  код в прозе не ловит). Готовый проект на непройденном курсе не архивируется (`keep_done`, 409). Предложение

  Промпты и пределы — `data/prompts/project.toml` (проверяются в `create_app`).
