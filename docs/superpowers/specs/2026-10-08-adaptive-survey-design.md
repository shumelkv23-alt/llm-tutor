# Дизайн: адаптивная анкета в одном сообщении

> Дата: 2026-10-08. Развивает `2026-10-08-lean-entry-design.md` (срезы 19–21).
> Отменяет её §3.1 (reply-кнопка «▶️ Старт»), §3.2 (приветствие из трёх
> предложений) и §3.3 (пять одинаковых вопросов самооценки). Остальное —
> список шагов, ведомый урок, банк заданий — не меняется.

## 1. Зачем

Адверсариальное ревью входа (2026-10-08) нашло, что анкета — декорация, а её
кнопки ведут себя ненадёжно:

| # | Находка | Как воспроизведено |
|---|---|---|
| H1 | Анкета не влияет на урок: все 4⁵ = 1024 комбинации ответов дают один и тот же список шагов и первый узел `python_basics` | перебор `apply_answers` → `build_route` → `next_node_id` |
| H2 | Профиль не доходит до тьютора: `context._PROFILE_KEYS` ждёт ключи старой анкеты (`pandas_experience`, `goal`, `time_budget`), факты `block_*` отсекаются | чтение кода |
| H3 | Клик по старой клавиатуре анкеты засчитывается ответом на текущий вопрос | Q1 «Уверенно», затем тап «Не знаю» по клавиатуре Q1 → `{'block_python': 3, 'block_tables': 0}` |
| H4 | Двойной тап на последнем вопросе: апдейты идут задачами (`handle_as_tasks=True`), второй либо запускает урок второй раз, либо падает `KeyError: 'index'` и вешает «часики» | `asyncio.gather` двух нажатий |
| M5 | Приветствие велит «нажми ▶️ Старт», но вопрос уже пришёл; нажатие отвечает «выбери вариант кнопкой ниже» | чтение кода + маршрутизация |
| M6 | Кнопка анкеты после её финала или рестарта (FSM в `MemoryStorage`) не находит хендлер — `callback.answer()` не зовётся, «часики» висят | чтение кода |
| M7 | `callback.answer()` зовётся после отправки следующего вопроса; на финале LLM думает секунды без «печатает…» | чтение кода |
| M8 | Пять сообщений по четыре кнопки в столбик — после анкеты в истории 20 живых кнопок | — |
| M9 | Повторный `/start` показывает ученику `[модель: anthropic/claude-sonnet-4.5]` и тратит LLM-вызов | `handlers.build_start_reply` |
| L10 | Вопросы абстрактные («Как у тебя с блоком …?»), подписи громоздкие («Слышал(а), но не делал(а)») | — |

Цель — **вход в одно сообщение, которое ведёт себя предсказуемо, и анкета,
от которой зависит урок**.

## 2. Решения (согласованы)

1. **Одно сообщение.** Приветствие, вопросы и сводка — одно и то же сообщение,
   которое правится на месте (`edit_text`). Варианты — сеткой 2×2, прогресс
   «Вопрос k из N».
2. **Вход по кнопке «▶️ Поехали»** в приветствии. Reply-кнопки «▶️ Старт» больше
   нет; «☰ Меню» появляется после анкеты, как сейчас.
3. **Адаптивная анкета**: вопрос об общем уровне, дальше — только нужные
   вопросы по блокам; ранний выход на «Впервые вижу».
4. **Кнопка «‹ Назад»** — со второго вопроса: в одном сообщении ошибочный тап
   иначе не исправить.
5. **Анкета влияет на урок** (срез 23): старт с первого неуверенного блока;
   знакомое не пропускается, а проверяется в конце маршрута; профиль уходит в
   промпт тьютора.
6. **Повторный `/start` — без LLM**: короткое «С возвращением».

## 3. Механика сообщения анкеты

### 3.1 Жизнь сообщения

```
/start (анкета не пройдена)
  → новое сообщение: приветствие + [▶️ Поехали]
[▶️ Поехали]
  → то же сообщение: вопрос об уровне
ответ
  → то же сообщение: следующий вопрос (или сводка, если анкета кончилась)
сводка (кнопок нет)
  → новое сообщение: список ближайших шагов + клавиатура «☰ Меню»
  → урок (как в срезе 21)
```

Приветствие — два предложения и кнопка:

```
👋 Привет! Я тьютор по теме «Pandas / EDA» курса mlcourse.ai.
Пара коротких вопросов — и подберу, с чего начать.
                 [ ▶️ Поехали ]
```

Вопрос по блоку:

```
Вопрос 2 из 5  ▰▰▱▱▱

Фильтруешь и сортируешь таблицы?
loc / iloc, условия, sort_values, value_counts

[ Впервые вижу ]  [ Знаю в теории ]
[ С подсказками ] [ Уверенно ]
[ ‹ Назад ]
```

Сводка (кнопок нет):

```
✅ Понял тебя:
• Python и NumPy — уверенно
• Таблицы pandas — уверенно
• Чтение и осмотр — с подсказками
• Выборка и сортировка — знаю в теории
• Группировки и EDA — впервые вижу

Знакомое не пропускаю — в конце проверим коротким тестом.
```

Последняя строка — только если есть блоки «Уверенно» (§6).

### 3.2 Привязка нажатия к вопросу

- `callback_data` = `survey:<шаг>:<вариант>`; служебные: `survey:go`
  («Поехали»), `survey:<шаг>:back` («Назад»).
- FSM хранит `message_id` сообщения анкеты и номер текущего шага. Нажатие
  засчитывается, только если `callback.message.message_id` совпадает с
  сохранённым **и** шаг совпадает с текущим. Иначе — тост
  «Этот вопрос уже позади» и ничего не пишется. Так отсекаются клики по старому
  сообщению (после повторного `/start`) и двойные тапы.
- **Атомарность.** Проверка шага и его продвижение в FSM идут до первого
  сетевого `await` хендлера. `MemoryStorage` не уступает управление, поэтому
  второе параллельное нажатие увидит уже продвинутый шаг. На финале FSM-состояние
  снимается тоже до сетевых вызовов: второй тап не пройдёт фильтр и не запустит
  урок повторно.

### 3.3 Отзывчивость

- `callback.answer()` — **первым** сетевым вызовом хендлера: «часики» гаснут
  сразу, правка сообщения идёт после.
- Пока ждём LLM, в чате «печатает…» (`aiogram.utils.chat_action.ChatActionSender`):
  первый ход урока после анкеты, свободный текст, ответ на задание кнопкой,
  `/resume`. Хелпер `bot/typing.py` (или функция в `handlers`) отдаёт
  `nullcontext`, если у сообщения нет `bot` (тестовые фейки).
- Правка сообщения через хелпер `safe_edit`: «message is not modified»
  игнорируется; иная ошибка правки (сообщение слишком старое, удалено) — новым
  сообщением с тем же текстом и кнопками.

### 3.4 Нажатия без живой анкеты

Отдельный хендлер `survey:*` **без** фильтра состояния, зарегистрированный
после основного:

| Ситуация | Ответ |
|---|---|
| анкета пройдена | тост «Анкета уже пройдена», кнопки с сообщения снимаются |
| анкета не пройдена (рестарт бота потерял FSM) | анкета начинается заново в этом же сообщении — с вопроса об уровне |

`callback.answer()` вызывается всегда — висящих «часиков» нет ни в одной
ветке.

### 3.5 Текст и кнопки вне анкеты

| Ситуация | Ответ |
|---|---|
| свободный текст до анкеты, FSM пуст | новое приветствие с [▶️ Поехали] |
| свободный текст посреди анкеты | «Ответь кнопкой в сообщении выше 👆» |
| текст «▶️ Старт» (у старых учеников висит reply-кнопка) | как `/start` |
| `/start` посреди анкеты | анкета начинается заново новым сообщением; старое сообщение отсекается по `message_id` |
| команды посреди анкеты | как сейчас (`BUSY_REPLY` у `/task`, `/close`, `/resume`) |

## 4. Логика анкеты

### 4.1 Вопрос об уровне

```
Для начала — как у тебя с Python и pandas?

[ С нуля ]
[ Немного знаю ]
[ Уверенно работаю с pandas ]
```

| Ответ | Дальше | Тапов всего |
|---|---|---|
| С нуля | анкета кончилась; все блоки — «Впервые вижу» | 1 (+«Поехали») |
| Немного знаю | вопросы по блокам 1–5 с ранним выходом (§4.3) | 2–6 |
| Уверенно работаю с pandas | блоки 1–3 — «Уверенно»; спрашиваем блоки 4–5 | 3 |

Ответ пишется фактом `survey_level` (`source="self"`), сам априора не даёт.

### 4.2 Вопросы по блокам

Градации — общие, без «(а)», влезают в сетку 2×2:

| Индекс | Вариант | `correct` для априора |
|---|---|---|
| 0 | Впервые вижу | 0.0 |
| 1 | Знаю в теории | 0.3 |
| 2 | С подсказками | 0.65 |
| 3 | Уверенно | 1.0 |

Подпись «Уверенно» сохраняется дословно: по ней срез 23 узнаёт заявленные
блоки, и у учеников, прошедших анкету раньше, она та же.

Вопросы — «умеешь ли…» с примерами API второй строкой:

| Ключ | Вопрос | Пример API | Узлы |
|---|---|---|---|
| `block_python` | Пишешь на Python и NumPy? | списки, функции, `np.array` | `python_basics`, `numpy_basics` |
| `block_tables` | Создаёшь Series и DataFrame? | индекс, столбцы, `pd.DataFrame` | `pandas_intro`, `pandas_series`, `pandas_dataframe` |
| `block_loading` | Загружаешь и осматриваешь данные? | `read_csv`, `info`, `describe`, `astype` | `read_csv`, `df_inspect`, `describe_stats`, `dtype_conversion` |
| `block_selection` | Фильтруешь и сортируешь таблицы? | `loc` / `iloc`, условия, `sort_values`, `value_counts` | `indexing_loc_iloc`, `boolean_indexing`, `sorting`, `value_counts`, `df_transformations` |
| `block_analysis` | Группируешь и исследуешь данные? | `apply`, `groupby` + `agg`, `pivot_table`, графики | `apply_functions`, `groupby`, `agg_functions`, `summary_tables`, `visualization_basics`, `eda_workflow`, `churn_eda_case` |

Ключи фактов не меняются — `is_completed` и старые профили работают как раньше.
Короткие названия блоков для сводки: «Python и NumPy», «Таблицы pandas»,
«Чтение и осмотр», «Выборка и сортировка», «Группировки и EDA».

### 4.3 Ранний выход

Блоки идут по зависимостям: кто не знает DataFrame, не знает и groupby. Поэтому
ответ «Впервые вижу» на блок k завершает анкету, а блоки k+1…5 получают
«Впервые вижу».

### 4.4 Назад

«‹ Назад» возвращает к предыдущему **заданному** вопросу (стек заданных ключей
в FSM) и снимает его ответ. Достроенные правилом ответы (§4.1, §4.3) в FSM не
кладутся, пока анкета не кончилась, — откатывать нечего. С вопроса об уровне
«Назад» нет; с первого вопроса по блокам — возвращает к вопросу об уровне.

### 4.5 Запись

В БД пишется только в финале (как сейчас): факты всех пяти блоков — заданные
и достроенные — плюс `survey_level`, априор по каждому блоку через
`self_report.apply`, вес `self_evidence_weight`. Повторное прохождение априор не
начисляет (без изменений). Достроенный ответ — такое же свидетельство
`source="self"`: ученик сам выбрал «С нуля» / «Уверенно работаю с pandas».

Прогресс «Вопрос k из N»: N — число вопросов по блокам на выбранной ветке
(5 или 2); ранний выход просто кончает анкету раньше. У вопроса об уровне
прогресса нет.

Логика ветвления — чистая функция в `student/survey.py` (без aiogram):
по ответам до сих пор отдаёт следующий ключ вопроса или «конец» и итоговый
словарь с достроенными блоками. Бот только рисует.

## 5. Повторный /start

Анкета пройдена → без LLM:

```
👋 С возвращением! Продолжаем «<текущий узел>».
```

или, если узла нет: «👋 С возвращением! Напиши что угодно — продолжим.»;

`START_SYSTEM_PROMPT`, `START_GREETING` удаляются, `handle_start` перестаёт
звать модель (сессия и журнал — как раньше).

## 6. Влияние анкеты на урок (срез 23)

### 6.1 Статус «заявлено»

- `RouteStepStatus` получает значение `"claimed"`: узел блока, отмеченного
  «Уверенно», ещё не подтверждённый.
- `build_route`: если снимка нет — `claimed` выводится из фактов анкеты; если
  снимок есть — `claimed` берётся из него (как `closed_before`). Порядок
  статусов: закрыт → текущий → заявлен → впереди. Узел, переставший быть
  `claimed` (текущий, проваленный проход), обратно не возвращается.
- Для готовности `claimed` = выполненный пререквизит:
  `next_node_id` передаёт `completed_ids = closed ∪ claimed` и **не**
  выбирает `claimed` узлы, пока есть другие.

### 6.2 Старт с первого неуверенного блока

Урок начинается с узла, который даёт `next_node_id`. Список «Ближайшие шаги»
(`begin_lesson`) ставит **первым именно его**, дальше — незакрытые и
незаявленные в порядке маршрута. Объявленный первый шаг обязан совпадать с
фактически начатым — тест по всем путям анкеты.

### 6.3 Проверка знакомого в конце

Когда незаявленных узлов не осталось, `next_node_id` отдаёт первый `claimed` по
порядку маршрута. Вход в такой узел — **проверочный проход** (`mode="verify"`,
срез 16) без объяснения:

```
🔍 Осталось подтвердить знакомое: «Основы Python» — пара быстрых вопросов.
<задание>
```

- проход подтвердился → узел закрыт, дальше следующий `claimed`;
- проход оборвался → `guide.on_verification_failed` (как сейчас): узел уходит
  в обычный урок и статус `claimed` теряет.

Так маршрут остаётся закрываемым до конца, а самооценка не подменяет проверку.

### 6.4 Отображение

- `/plan`: `claimed` помечен «🔍 ».
- 🎚 Темы: статус `claimed` с иконкой 🔍; для «доступно» заявленный
  пререквизит считается выполненным. Выбор заявленной темы вручную — обычный
  урок.

### 6.5 Профиль в промпте

- `context._PROFILE_KEYS` заменяется на ключи новой анкеты; профиль
  рендерится по-человечески: «Самооценка: Python и NumPy — уверенно; …».
- В блок состояния добавляется «Самооценка по текущему блоку: <вариант>».
- Правило промпта тьютора: «Впервые вижу» / «Знаю в теории» — с азов и
  аналогией; «С подсказками» — коротко, без азов, акцент на тонкостях;
  «Уверенно» (заявленный узел, проход не подтвердился) — разбирай именно то, на
  чём споткнулся.

## 8. Тестирование

- **ветвление** (чистая функция): «С нуля» → 1 вопрос, все блоки 0;
  «Уверенно работаю» → спрашиваются только блоки 4–5, блоки 1–3 = 3;
  «Немного знаю» + «Впервые вижу» на блоке k → анкета кончилась, блоки после
  k = 0; «Назад» снимает ответ и возвращает предыдущий ключ;
- **сообщение**: «Поехали» правит то же сообщение; вопрос — сетка 2×2 +
  «Назад»; на вопросе об уровне «Назад» нет; сводка без кнопок;
- **гонки и устаревшие клики**: клик по старой клавиатуре (другой `message_id`
  или другой шаг) ничего не пишет и отвечает тостом; два параллельных тапа на
  финале запускают урок ровно один раз; нажатие без FSM — тост или новый
  старт, `callback.answer()` вызван в каждой ветке;
- **отзывчивость**: `callback.answer()` вызывается раньше правки сообщения;
- **вход**: `/start` до анкеты — одно сообщение с «▶️ Поехали»; текст до
  анкеты — то же; повторный `/start` не зовёт LLM и не содержит `[модель:`;
- **влияние** (срез 23): по всем путям анкеты объявленный первый шаг совпадает
  с начатым; при «Уверенно» на блоке 1 урок начинается не с `python_basics`;
  при всех «Впервые вижу» — с `python_basics`; после незаявленных узлов
  маршрут ведёт в проход по заявленным; провал прохода снимает `claimed`;
  профиль и самооценка блока попадают в пакет контекста;
- **E2E**: новый ученик → «Поехали» → «Уверенно работаю с pandas» → два
  ответа → сводка → список шагов (первый — из блока 4) → урок.

## 10. Вне области

- постоянное хранилище FSM (Redis/SQLite) — §3.4 закрывает потерю состояния
  без него;
- многопользовательский режим (бот по-прежнему на одного ученика);
- повторное прохождение анкеты по команде;
- персонализация цели маршрута.

## 11. Риски

| Риск | Митигация |
|---|---|
| Самоуверенный ученик проскочит основы | `claimed` не закрывает узел: проверка в конце, провал — обычный урок |
| Ранний выход занизит оценку (не знает pandas-таблиц, но знает графики) | блоки упорядочены по зависимостям; занижение безопасно — узел просто пройдётся уроком |
| `edit_text` не работает на старом сообщении | `safe_edit` падает обратно на новое сообщение |
| Атомарность держится на `MemoryStorage` | зафиксировано комментарием и тестом гонки; при смене хранилища — пересмотреть |
| Планировщик выберет первым не тот узел, что в списке | список строится от `next_node_id`, тест по всем путям |
| Снимок маршрута потерян (новая сессия) — `claimed` снова выводится из фактов, и узел с проваленным проходом опять станет заявленным | осознанный размен: так же сегодня теряется и `closed` из снимка; в худшем случае узел ещё раз уйдёт в проход и при провале — в урок |
