# Дизайн: лаконичный вход и ведомый урок

> Дата: 2026-10-08. Развивает `2026-10-07-guided-lesson-design.md` (срезы 15–18).
> Отменяет её §7 (экран согласования маршрута) и §3.2 (инлайн-кнопка
> «Продолжить обучение»): решения приняты заново по итогам живого просмотра.

## 1. Зачем

После срезов 15–18 бот умеет вести урок, но интерфейс оказался **загруженным**:
нового ученика встречает схема маршрута из псевдографики, под каждым сообщением
висит кнопка «▶️ Продолжить обучение», в меню четыре действия, а урок
начинается с вопроса, а не с объяснения.

| Проблема | Как сейчас |
|---|---|
| Схема маршрута на входе | псевдографика `<pre>` плюс кнопки узлов плюс «✅ Меня всё устраивает» |
| Кнопки-навигация под каждым ответом | «▶️ Продолжить обучение» приклеена к хвосту каждого хода |
| Три общих вопроса анкеты | опыт / цель / время — про ученика, а не про тему |
| Урок начинается с вопроса | сократовский диалог: «сначала вопросы, которые подводят к ответу» |
| Пустые узлы | 11 узлов из 21 вообще без заданий: ни тестов, ни закрытия |

Цель — **минимальный интерфейс и предсказуемый урок**: одна кнопка на входе,
три предложения приветствия, пять тематических вопросов, список ближайших шагов
вместо схемы, а дальше бот сам рассказывает, показывает пример, даёт пару
тестов и закрывает узел.

## 2. Решения (согласованы)

1. **Кнопка входа** — постоянная reply-клавиатура из одной кнопки **«▶️ Старт»**
   у того, кто ещё не прошёл анкету; после анкеты она меняется на «☰ Меню».
2. **Приветствие — три предложения**: кто я → что будет (короткое интервью) →
   что нажать.
3. **Анкета — 5 вопросов по теме**, по блокам узлов; общих вопросов про цель и
   время нет.
4. **Экран согласования маршрута убирается целиком.** После анкеты — обычным
   списком **ближайшие 5 шагов**, и сразу начинается урок. Кнопки «Меня всё
   устраивает» больше нет.
5. **«Я это уже знаю» — только текстом**: ученик пишет «закрой тему» /
   «я это знаю», бот ведёт проверочный проход (срез 16, не меняется).
6. **Никакой навигационной кнопки под сообщениями.** Ученик пишет сам; бот
   ведёт занятие дальше по любой непустой реплике.
7. **Урок идёт по схеме**: коротко объяснил → показал пример и зачем это нужно
   → дал пару тестов → ответил на вопросы → закрыл узел → сам перешёл к
   следующему.
8. **Банк заданий расширяется до двух заданий на каждый узел** (42 вместо 10).

## 3. Вход

### 3.1 Клавиатура

| Состояние | Постоянная клавиатура |
|---|---|
| Анкета не пройдена | одна кнопка **«▶️ Старт»** |
| Анкета пройдена | одна кнопка **«☰ Меню»** (как сейчас) |

Нажатие «▶️ Старт» обрабатывается тем же хендлером, что `/start` (фильтр по
тексту кнопки), — второго пути входа не заводим.

**Реплика до анкеты.** Свободный текст от того, кто анкету не прошёл, не должен
улетать в тьюторский ход (маршрута и цели ещё нет). Ответ:

```
Сначала пару вопросов о тебе — нажми «▶️ Старт».
```
и та же клавиатура «▶️ Старт». Команды при этом работают как обычно.

### 3.2 Приветствие

```
👋 Привет! Я тьютор по теме 1 курса mlcourse.ai — «Pandas / EDA».
Задам несколько коротких вопросов о тебе — это меньше минуты.
Нажми «▶️ Старт», когда будешь готов пройти опрос.
```

Ровно три предложения. Третье называет **ту кнопку, которая есть** («▶️ Старт»,
а не «Продолжить»): два имени для одного действия путают.

### 3.3 Анкета: 5 вопросов по теме

Каждый вопрос — один блок узлов; варианты — градации самооценки, одинаковые во
всех вопросах:

| Индекс | Вариант | `correct` для априора |
|---|---|---|
| 0 | Не знаю | 0.0 |
| 1 | Слышал(а), но не делал(а) | 0.3 |
| 2 | Делал(а), но с подсказками | 0.65 |
| 3 | Уверенно | 1.0 |

| № | Вопрос | Блок узлов |
|---|---|---|
| 1 | Основы Python и NumPy | `python_basics`, `numpy_basics` |
| 2 | Таблицы pandas: Series и DataFrame | `pandas_intro`, `pandas_series`, `pandas_dataframe` |
| 3 | Чтение и осмотр данных | `read_csv`, `df_inspect`, `describe_stats`, `dtype_conversion` |
| 4 | Выборка и упорядочивание | `indexing_loc_iloc`, `boolean_indexing`, `sorting`, `value_counts`, `df_transformations` |
| 5 | Группировки и разведочный анализ | `apply_functions`, `groupby`, `agg_functions`, `summary_tables`, `visualization_basics`, `eda_workflow`, `churn_eda_case` |

Априор пишется тем же путём, что и раньше (`student/self_report`, вес
`self_evidence_weight`, событие `source="self"`), **только при первом
прохождении анкеты** — как сейчас. Один ответ накрывает весь блок: `correct`
одним значением на все узлы блока.

**Цель маршрута.** Вопрос про цель убран, поэтому факта `goal_concept_id` не
появляется: маршрут строится по всей теме (`route.build_route` с
`goal_concept_id=None` даёт все 21 узел). Это и есть «пройти тему 1 целиком»;
осознанный размен — персонализация цели под ответ больше не работает.

## 4. После анкеты: список шагов вместо схемы

Экран согласования маршрута (схема, кнопки узлов, «✅ Меня всё устраивает»)
удаляется. Вместо него — одно сообщение:

```
📋 Ближайшие 5 шагов:

1. Основы Python
2. Основы NumPy
3. Series и DataFrame
4. Чтение данных: read_csv
5. Осмотр таблицы: describe, info

Начинаем с «Основы Python» — сейчас коротко объясню и покажу пример.
```

- шаги берутся из маршрута: первые пять незакрытых, в порядке маршрута; если
  незакрытых меньше пяти — показываем сколько есть, без пустых строк;
- формат — нумерованный список без псевдографики; тот же список рисует `/plan`
  (`render_steps`), только целиком и с пометками `[x]` / `[>]`;
- сразу за списком бот начинает урок по первому шагу (§5), не дожидаясь
  реплики: два сообщения в одном ходу.

Правка маршрута кнопками на входе больше не предлагается — «я это уже знаю»
работает текстом в любой момент (§2.5).

## 5. Ведомый урок

### 5.1 Ход узла

```
вход в узел
  ↓ тьюторский ход: короткое объяснение + пример + зачем это нужно
  ↓ первое задание узла (код выдаёт сразу, отдельным сообщением)
ответ
  ├── верно и это первый тест → второе задание
  ├── верно и это второй тест  → узел закрыт → объявление + объяснение
  │                              следующего узла + его первый тест
  └── неверно → разбор (верный вариант или эталон) и предложение
                попробовать ещё раз; вперёд не идём
вопрос ученика в любой момент → тьюторский ответ, занятие стоит
```

- **Объяснение идёт первым и отдельным сообщением**, тест — следующим: две
  части в одном сообщении читаются как стена.
- **Объяснение не спрашивает.** Промпт тьютора при входе в узел: рассказать
  вкратце (2–4 предложения), показать короткий пример и сказать, зачем это
  нужно. Сократовские вопросы остаются, но после объяснения, а не вместо него.
- **«Пара тестов» — два задания с автопроверкой.** После верного ответа
  выдаётся следующее задание узла; после второго верного узел закрывается.
- **Закрытие узла и переход** — в том же ходу: объявление «✅ Тема «X» закрыта —
  идём дальше», затем объяснение следующего узла и его первый тест. Бот ведёт
  урок сам, кнопка для этого не нужна.
- **Неверный ответ** не двигает занятие: разбор и ещё одна попытка.

### 5.2 Что закрывает узел

Критерий остаётся прежним (`guide.is_node_closed`: серия чистых ответов
`guide_success_streak` = 2 либо владение ≥ `mastery_skip_threshold` при малой
неопределённости), но **«чистота» ответа зависит от режима**:

| Режим | Что считается чистым ответом |
|---|---|
| Обычный урок | **верный ответ**; подсказки и вопросы серию не обнуляют |
| Проверочный проход («закрой тему» текстом, срез 16) | верный ответ **без помощи** — как сейчас |

Причина: в уроке бот объясняет первым по своей же схеме, и просьба о помощи
перестала быть признаком «списал». В проходе ученик, наоборот, утверждает, что
тему знает, — там чистота ответа и есть доказательство.

### 5.3 Какие тесты и что с повторами

- **В уроке — только автопроверка** (`choice`/`short`). Рубричные задания
  (`open`/`code`) остаются за проверочным проходом: там ученик доказывает
  знание словами. Размен: прозу в обычном уроке не спрашиваем — зато урок
  предсказуем, а закрытие не зависит от вердикта грейдера.
- **Пауза повтора в уроке не применяется** (как в проходе): банк узла — два
  задания, с суточной паузой второе тесто было бы нечем выдать.
- **Защита от зацикливания на одном задании**: одно и то же задание не
  выдаётся дважды подряд. Список выданного в текущем заходе по узлу лежит в
  `SessionState.lesson_item_ids: list[int]` (JSON, миграции не требует) и
  чистится при закрытии узла, переходе на другую тему и старте нового захода.
- **Задания узла кончились, а серия не набрана** (например, оба теста отвечены
  неверно): список выданного обнуляется, и задания идут по второму кругу.
  Повтор идёт слабым свидетельством (`repeat_evidence_weight`, как сейчас),
  поэтому накрутить закрытие повторами нельзя.

Без правила второго круга узел с двумя заданиями становится незакрываемым:
оба уже выданы, серия нулевая.

### 5.4 Свободный текст

| Реплика | Что делает бот |
|---|---|
| намерение («пропусти», «не понял», «закрой тему») | как в срезе 15, без изменений |
| вопрос (`…?`) | тьюторский ответ; занятие стоит на месте |
| висит задание, не вопрос и не намерение | это ответ на задание (как сейчас) |
| задания нет, занятия нет | начинает урок с первого шага маршрута |
| задания нет, занятие идёт | **ведёт занятие дальше**: фаза `explain` — объясняет текущий узел, иначе выдаёт следующее задание |

Последняя строка — то, что раньше делала кнопка «▶️ Продолжить обучение»:
теперь её роль играет любая реплика ученика. Короткая ремарка вроде «ага,
понятно» двигает урок вперёд — это и есть ведомый урок.

## 6. Интерфейс: что убираем

| Убираем | Почему |
|---|---|
| `bot/onboarding.py` целиком (экран согласования, `OnboardingFlow`, колбэки `route:*`) | решения входа принимаются в анкете, правка маршрута — текстом |
| `menu.resume_keyboard()` и инлайн-«▶️ Продолжить» во всех хендлерах | навигационная кнопка под каждым сообщением |
| действие `resume` из меню | меню становится из трёх: 🗺 Маршрут · 🎚 Темы · ✅ Закрыть тему |
| `render.render_route_screen`, `ROUTE_REVIEW_NOTE`, `render.route_window` | экрана согласования нет; список шагов строит `render_steps` |
| псевдографика `<pre>` в `render_plan` | тот же нумерованный список, что и «ближайшие 5 шагов» |
| `tests/test_onboarding.py` | тестировать нечего |

Остаются команды: `/start` · `/plan` · `/themes` · `/close` · `/resume` ·
`/status` · `/task` · `/skip` · `/help` · `/diagnostic`. `/resume` остаётся
командой (для тех, кто хочет кнопкой), но в меню его нет.

Инлайн-кнопки остаются **только** в двух местах: варианты ответа на задание и
варианты ответа анкеты. Больше инлайна в интерфейсе нет.

## 7. Банк заданий

- **Два задания с автопроверкой (`choice`/`short`) на каждый из 21 узла** —
  всего 42 (сейчас 10). Оба проверяются кодом, рубрики для новых не заводим.
- Существующие рубричные задания 9 и 10 остаются: ими работает проверочный
  проход (§5 среза 16).
- Правило банка: у каждого узла минимум два задания — тогда «пара тестов» и
  закрытие по серии достижимы везде, и §5.4 прошлой спеки («проверить нечем»)
  остаётся только страховкой.
- Формат — `data/seed_topic01.json` (поля `prompt`, `answer_type`,
  `concept_weights`, `difficulty`, `options`, `answer`).
- Мини-тесты — `tests/test_seed.py`: у каждого узла ≥ 2 задания, ответ входит в
  варианты, у `choice` ≥ 3 вариантов, `short` имеет непустой эталон.

## 9. Тестирование

- **вход**: клавиатура «▶️ Старт» до анкеты и «☰ Меню» после; свободный текст до
  анкеты не уходит в тьюторский ход; приветствие — три предложения и имя
  кнопки;
- **анкета**: пять вопросов, у каждого четыре варианта; ответ накрывает весь
  блок узлов; повторное прохождение априор не начисляет;
- **список шагов**: ровно пять ближайших незакрытых, в порядке маршрута;
  `/plan` рисует тот же формат;
- **урок**: вход в узел даёт объяснение и сразу первое задание (два сообщения);
  верный ответ выдаёт второе; второй верный закрывает узел и в том же ходу
  объясняет следующий; неверный не двигает; вопрос ученика не двигает;
- **закрытие**: серия из двух верных закрывает узел в уроке, даже если ученик
  спрашивал по ходу; в проверочном проходе подсказка по-прежнему обнуляет
  серию;
- **выдача тестов в уроке**: второе задание отличается от первого; рубричные в
  уроке не выдаются; когда оба выданы, а серия не набрана — идём по второму
  кругу (без суточной паузы), и повтор не закрывает узел;
- **свободный текст**: ремарка без задания ведёт занятие дальше;
- **удаления**: в меню три действия, инлайн-«Продолжить» не приходит ни на один
  ход, экрана согласования нет;
- **E2E**: новый ученик → «▶️ Старт» → приветствие → пять вопросов → список
  шагов → объяснение первого узла → пара тестов → узел закрыт → следующий узел.

Каждый срез — со своим адверсариальным ревью (норма проекта).

## 11. Вне области

- персонализация цели маршрута (вопрос про цель убран осознанно);
- переключение между разделами курса (topic01 → topic02);
- голосовой ввод, рич-медиа, файлы;
- пагинация списка тем.

## 12. Ограничения и риски

| Риск | Митигация |
|---|---|
| Ученик не понял, что делать после объяснения | тест приходит вторым сообщением сразу, ждать реплики не нужно |
