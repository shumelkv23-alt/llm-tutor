# Второй курс: «Машинное обучение для ИСИТ» — дизайн

**Дата:** 2026-10-13
**Источник:** репозиторий `https://github.com/Eldervald/isit_ml_labs` (GPL-3.0),
снимок `0da67c6` — 134 файла: 13 заданий `lab1-python-intro`, 6 заданий

## 1. Что делаем

Переносим курс с гита в тьютор **полностью** — девятый модуль включается, если
он переносим. Курс идёт **рядом с mlcourse**, отдельной записью в реестре
курсов: у каждого курса свой каталог seed-файлов, свои конспекты и свой файл
БД ученика (`data/users/<id>/<course>.sqlite3`).

Конспекты **пишутся заново** в стиле тьютора (`## Раздел` → «Главное / Пример /
Частые ошибки»), авторские README и markdown-ячейки ноутбуков служат
источником фактов, а не текстом для копирования. Так решается и вопрос
лицензии исходного репозитория (GPL-3.0): производного текста не возникает.

**Что не переносится** (решение владельца курса, 2026-10-13):

| Откуда | Почему |
|---|---|
| `lab-hard-graphs.ipynb` | `torch` и `pycombo` — нет в сборке Pyodide 0.27.8, поставить из PyPI не даёт CSP. В самом репозитории обе зависимости закомментированы в `pyproject.toml` |
| `lab_extra_concurrency` | Pyodide в Web Worker однопоточный: `threading`/`concurrent.futures` не работают, задание требует ~21 с ожиданий |
| `lab2-libs/e_validation` | `pydantic` v2 (ядро на Rust) в Pyodide нет |

Остальные 30 заданий переносятся: первое — целиком в браузерный автозапуск,
второе — включая реальные данные (`titanic.csv`, выборка из `imdb.csv`).

## 2. Модель тьютора, в которую укладываем

| Репозиторий | Тьютор |
|---|---|
| лаборатория (`lab1`, `lab2`, `lab3`…) | **модуль** (`topic.number`, `seed_topicNN.json`) |
| группа родственных заданий | **занятие** (узел графа, 2–4 **раздела**) |
| одно задание (`f_iterate_me`) или его половина | **раздел** (`## <название>` в конспекте) |
| `test_public.py` | авторские **задания** (`items`): 2+ на раздел, одно итоговое на занятие |
| — | **конспект** `data/theory/topicNN/<занятие>.md` (пишется заново) |

Их тесты **не переносятся**: они построены на собственной библиотеке `testlib`
(проверки «использован оператор `:=`», «использована `sum()`» — анализ
байткода, AST и исходников). Такие проверки в браузере недоступны и
противоречат принципу тьютора: судим по результату, а не по способу записи.
Вместо структурных проверок — вопросы-выборы («какой способ итерации тут
уместен?») в банке заданий.

## 4. Формат конспекта

Один файл на занятие — `data/theory/topicNN/<занятие>.md`, шаблон повторяет
mlcourse:

```markdown
# <Название занятия>

<одна-две фразы, зачем это>

## Зачем

После занятия вы сможете:

- …

## <Название раздела>          ← ровно заголовки разделов из seed, в том же порядке

### Главное

<объяснение по-русски, термины полужирным>

### Пример

```python
<исполняемый пример: он проверяется тестом конспекта>
```

### Частые ошибки

- …

## Итоги занятия        ← не раздел, служебный заголовок

## Источник             ← ссылка на исходный репозиторий/ноутбук
```

Требования проекта, которым конспект обязан удовлетворять:
- заголовки `## <title>` всех разделов занятия **в порядке seed** —
  `course/seed._check_theory_sections` падает иначе;
- формулы — **без LaTeX**: KaTeX/MathJax в приложении нет, только текст и код;
- примеры кода исполняются тестом конспекта (как в срезах 57–61):
  `plt.show()`/`fig.show()`/`sns.boxplot` в примеры не попадают.

## 5. Формат задания с кодом

Правила взяты из `tests/test_seed_code_items.py` и `CLAUDE.md`:

- решение кладёт ответ в переменную `result`; первая проверка —
  `assert "result" in globals(), "…"`;
- `starter` — заготовка, которая на запуске падает **именно `AssertionError`**
  (не `TypeError`), с непустым текстом;
- `setup` готовит данные и эталон (`_day`, `_eve` — копии, чтобы поймать
  мутацию входа);
- каждое задание несёт `rubric_id`, а в `tests/test_seed_code_items.py`
  заводится **эталон, неверные решения (`WRONG`, `MORE_WRONG`) и верные
  альтернативы**; все неверные обязаны падать с `AssertionError`;
- время прогона в браузере — до 10 с (`code.js:14`). Тяжёлые вещи
  (леса с `GridSearchCV`, кросс-валидация на больших данных) в автозапуск не
  идут — им место в вопросах и открытых ответах.

Перенос по лабораториям:

- **lab1** — чистый Python: переносится целиком. Задание вида «реализуй
  функцию» становится «реализуй функцию и сохрани результат вызова в `result`».
- **lab2** — numpy/pandas: переносится. `titanic.csv` (10 КБ) встраивается в
  `setup` целиком; `imdb.csv` (3.4 МБ) — выборкой, эталонные значения считаются
  заново по выборке.
- **lab3–lab9** — numpy/sklearn/matplotlib: переносится, кроме заданий
  «построй график» без проверяемого результата (они становятся разделами с
  вопросами и открытым ответом). `matplotlib` работает в памяти (`Agg`) —
  проверяются данные графика и объект `Axes`/`Figure`.

## 6. Регистрация курса

- id курса — `isit-ml`, название «Машинное обучение для ИСИТ», подпись
  «Python, NumPy, pandas и классический ML».
- файлы курса — в отдельном каталоге, чтобы `course_paths()` (glob по
  `data/`) не смешал два курса:

  ```
  data/isit/seed_topic01.json … seed_topic09.json
  data/isit/theory/topic01/<занятие>.md …
  ```

  `course/seed.theory_dir_for` выводит каталог конспектов из имени seed-файла
  (`seed_topic01.json` → рядом `theory/topic01`) — при таком раскладе работает
  без правок.
- `web/courses.py`: у `Course` появляется поле `data_dir: Path | None`,
  `course_data` для такого курса зовёт `course_paths(course.data_dir)`
  (glob выполняется при первом обращении, а не на импорте: каталог наполняется
  по мере написания модулей).
- Подписи «Тьютор mlcourse.ai» в шаблонах входа/регистрации/восстановления и
  текст «Пока доступен один курс» на главной становятся нейтральными.

## 7. Идентификаторы и порядок

- Номера модулей 1…9, `topic.number` = номер в имени файла.
- id заданий — `N*1000 + k` (модуль 1 — 1001…, модуль 9 — 9001…), уникальны по
  курсу; id рубрик и критериев — свои, не пересекаются с mlcourse (проверяются
  внутри курса, но так проще читать).
- Рёбра: внутри модуля — только вперёд по порядку занятий; между модулями —
  только назад (в модуль с меньшим номером), иначе `CourseGraphError`.
  Межмодульные связи — мягкие (`hard: false`), кроме одной-двух осознанных
  жёстких (например «массивы NumPy» → «метрики регрессии»).
- `legacy` не нужен: предыстории у курса нет, прогресс переносить не с чего.
- `published: false`, пока модуль не готов целиком: в неопубликованном модуле
  не требуются ни 2 задания на раздел, ни итоговое, ни конспект. Включаем
  `published: true` последним шагом модуля.

## 9. Риски

- **Лимит 10 секунд** на прогон кода в браузере: задания с лесами,
  кросс-валидацией и `GridSearchCV` надо держать на маленьких данных.
  В CPython время измеряется тестом, в браузере — нет (`E2E_PYODIDE_DIR`).
- **Версия sklearn** в Pyodide 0.27.8 — API не новее 1.6; параметры вроде
  `solver="liblinear"` и старые имена метрик надо сверять.
- **Объём.** Курс размером с mlcourse: 39 занятий, 96 разделов, ~230 заданий,
  ~400 КБ конспектов. Это не одна сессия работы; каждый модуль — отдельный
  законченный срез с ревью.
- **Расхождение с первоисточником** в мелочах (их эталонные числа получены на
  полных данных): для `imdb` и `titanic` эталоны считаются заново по тем
  данным, что лежат в `setup`, и это фиксируется в конспекте.
