# Дизайн: веб-приложение вместо Telegram-бота

> Дата: 2026-10-10. Переносит интерфейс тьютора из Telegram в браузер:
> четыре страницы (главная, мои курсы, занятие, профиль), вход для
> нескольких учеников, теория и практика рядом с чатом тьютора, запуск кода в
> браузере. Оформление берётся из веб-панелей проекта `bar_order_bot`
> (стилистика Azati) и дорабатывается. Принцип проекта не меняется: LLM
> объясняет и предлагает, а состояние ученика, вердикты и закрытие узлов
> считает код; журнал `events` — источник истины.

## 1. Зачем

Telegram ограничивает урок лентой сообщений: теорию, задание, код и диалог
нельзя видеть одновременно, а код нельзя запустить. В браузере занятие
раскладывается на две части: слева — теория и практика по теме, справа — чат с
тьютором, который помогает и проверяет.

## 2. Решения

Согласованы с пользователем 2026-10-10:

1. **Несколько учеников со входом** по email и паролю. У каждого свой прогресс.
2. **Telegram-бот удаляется последним срезом**, когда веб догонит его по
   функциям. До этого бот продолжает работать над тем же ядром.
3. **Код запускается в браузере** через Pyodide (Python и pandas в WebAssembly).
   Сервер чужой код не исполняет. Задания `code` получают тесты.
4. **Теория пишется вручную:** конспект на каждый из 21 узла topic01 по
   материалам mlcourse.ai, своими словами и со ссылкой на источник.

Приняты при проектировании, на согласование:

5. **Отдельная БД на ученика, а не `user_id` в каждой таблице.** Ядро
   (`core`, `student`, `db.repos`: около 5000 строк и 590 тестов) построено на
   инварианте «одна БД — один ученик». Файл `data/users/<user_id>/<course_id>.sqlite3`
   сохраняет этот инвариант. Ядро и его тесты не меняются, а данные учеников
   разделены файлами, а не условием `WHERE user_id = ?`, которое легко забыть в
   одном из ~60 запросов. Аккаунты и веб-сессии лежат в общей
   `data/accounts.sqlite3`.
   Минусы: сводная аналитика по всем ученикам потребует обхода файлов (сейчас
   она не нужна). Миграции применяются к файлу ученика при открытии;
   `migrate()` уже идемпотентен.
6. **Стек фронтенда — как у панелей бара:** FastAPI, Jinja2, обычные JS и CSS,
   без npm и сборки. Внешние библиотеки (Pyodide, CodeMirror) грузятся с CDN по
   точным версиям. Markdown превращается в HTML на сервере через
   `markdown-it-py` с выключенным сырым HTML. Так безопасно рендерятся и
   конспекты, и реплики модели.
7. **Нумерация срезов — 37–49.** Номера 24–36 заняты планом модулей
   (`2026-10-08-course-modules.md`). Его срезы, которые трогают `bot/*`
   (анкета модуля, приветствие), после переноса пересматриваются под `web/*`.

## 3. Архитектура

Слои: `web → core/student/db`, так же как `bot → core/student/db`.
`core/*` и `student/*` не импортируют `web/*`.

```
src/llm_tutor/web/
  __main__.py     запуск: uv run python -m llm_tutor.web
  app.py          create_app(settings, client): маршруты, статика, lifespan
  accounts.py     пользователи, пароли, веб-сессии (data/accounts.sqlite3)
  userdb.py       БД ученика: открыть → migrate → seed → материалы; кэш, lock
  courses.py      реестр курсов (сейчас один)
  pages.py        HTML-страницы (Jinja2)
  api_auth.py     /api/auth/*, /api/me
  api_lesson.py   /api/courses/*, /api/courses/{id}/lesson/*
  views.py        данные страниц из ядра: структуры, а не HTML
  markdown.py     безопасный Markdown → HTML
  templates/      base.html, home, courses, lesson, profile, login, register
  static/         css/, js/, fonts/, icons.svg
migrations_accounts/
  001_accounts.sql
```

Запуск: `uv run python -m llm_tutor.web`. Это uvicorn на `WEB_HOST:WEB_PORT`,
по умолчанию `127.0.0.1:8000`. Seed графа и материалы грузятся в БД ученика
сами.

Новые настройки (`.env`): `WEB_HOST`, `WEB_PORT`, `ACCOUNTS_DB_PATH`
(`data/accounts.sqlite3`), `USERS_DIR` (`data/users`), `MATERIALS_DB_PATH`
(`data/materials.sqlite3`), `REGISTRATION_OPEN` (`true`), `COOKIE_SECURE`
(`false` локально, `true` за HTTPS). `TELEGRAM_BOT_TOKEN` становится
необязательным в срезе 37 и удаляется в срезе 49.

## 4. Аккаунты и вход

Схема `migrations_accounts/001_accounts.sql`:

- `users(id, email UNIQUE, name, password_hash, created_at)`. Email хранится в
  нижнем регистре.
- `web_sessions(token_hash PRIMARY KEY, user_id, created_at, expires_at)`.
- `enrollments(user_id, course_id, enrolled_at, PRIMARY KEY(user_id, course_id))`.

`migrate()` получает параметр каталога миграций, чтобы обслуживать обе схемы.

Пароли: `hashlib.scrypt` (n=2¹⁴, r=8, p=1, соль 16 байт), сравнение через
`hmac.compare_digest`. Новых зависимостей не нужно. Минимум 8 символов.

Сессия — cookie `lt_session` со случайным токеном (32 байта),
`HttpOnly`, `SameSite=Lax`, `Secure` по `COOKIE_SECURE`. В БД хранится
`sha256` токена, поэтому утечка файла не даёт войти. Срок 30 дней.

Изменяющие запросы — только `POST` JSON на `/api/*`. Сервер требует
`Content-Type: application/json`. Если браузер прислал `Origin` или
`Sec-Fetch-Site`, они должны указывать на тот же сайт. Вместе с `SameSite=Lax`
это закрывает CSRF без отдельного токена.

Перебор паролей: не больше 5 неудачных входов на email за 15 минут. Счётчик
держится в памяти процесса.

Гостю доступны главная (лендинг), `/login` и `/register`. Остальные страницы
ведут на `/login?next=…`, причём `next` принимается только как
относительный путь. Выход удаляет строку сессии.

Перенос нынешней БД: `uv run python -m llm_tutor.web.accounts import-legacy
--email … --db data/llm_tutor.sqlite3` копирует файл в папку ученика и
записывает его на курс.

## 5. БД ученика

`userdb.open(user_id, course_id)`:

1. `get_conn(data/users/<user_id>/<course_id>.sqlite3)`;
2. `migrate(conn)`;
3. `load_seed(conn, курс.seed_path)` — идемпотентный upsert, как при старте бота;
4. синхронизация материалов RAG (ниже).

Соединения кэшируются в процессе и закрываются при остановке.

**Блокировка ученика.** Каждый изменяющий запрос занятия выполняется под
`asyncio.Lock` пары (ученик, курс). Двойной клик по «Отправить» или две
вкладки не перемешают ходы: второй дождётся первого. Это заменяет
атомарность анкеты на `MemoryStorage` (подводный камень из CLAUDE.md).

**Материалы RAG.** `course.ingest` пишет чанки в общую
`data/materials.sqlite3`. При открытии БД ученика её `chunks` сверяется с
ревизией материалов (число и контрольная сумма чанков в таблице `meta`
материалов). При расхождении чанки перезаливаются через `ATTACH`. FTS-индекс
обновляют существующие триггеры. Ретривер не меняется.

Доработки относительно панелей бара:

- блоки кода, вкладки, чат и ползунок — новые компоненты в той же системе

  «результат неизвестен» для отправки, потеря связи.

Адаптивность: 1440, 1024, 390 и 320 px. Ниже 900 px сайдбар становится
верхней полосой, как у бара.

## 7. Страницы

### 7.1 Главная `/`

**Гость.** Hero: «Разбирайся в данных с тьютором, который проверяет, а не
угадывает». Кнопки «Начать учиться» (регистрация) и «Войти». Три шага «как
это работает»: короткая анкета → урок с теорией и практикой → тьютор в чате
и проверка кода. Ниже — карточка курса.

**Ученик.** Приветствие по имени и карточка «Продолжить занятие»: курс, текущая
тема, прогресс «закрыто N из 21», кнопка. Рядом — «Ближайшие шаги» (5 шагов
маршрута, со статусами как в `/plan`) и короткая сводка: закрытых тем,
решённых заданий. Если ученик ни на что не записан, показывается призыв
выбрать курс.

### 7.2 Мои курсы `/courses`

Каталог из реестра `web/courses.py`. Курс описан полями `id`, `title`,
`subtitle`, `description`, `source_url`, `seed_path`, `theory_dir`. Сейчас
курс один: `mlcourse-topic01`, «Pandas и разведочный анализ данных»
(mlcourse.ai, тема 1).

Две секции: «Мои курсы» (ученик записан) и «Доступные». Карточка курса:
название, источник, число тем, полоса прогресса, статус («Не начат» /
«Анкета» / «В процессе» / «Пройден»), кнопка «Записаться» или
«Продолжить». Запись создаёт БД ученика и строку в `enrollments`.

### 7.3 Занятие `/lesson/<course_id>`

**Шапка урока:** курс, текущая тема, кнопки «Маршрут» и «Закрыть тему».
«Маршрут» — выезжающая панель со списком тем и статусами (✓ закрыта,
▶ текущая, 🔍 знакомая, впереди). Клик по теме переводит на неё
(`switch_node`). «Закрыть тему» запускает проверочный проход
(`verify.start_verification`).

**Раскладка:** две панели, левая 70 %, правая 30 %. Между ними ползунок:

- вертикальная ручка, `role="separator"`, `aria-valuenow` — доля левой панели;
- перетаскивание мышью и пальцем (pointer events);
- клавиатура: ←/→ — шаг 2 %, Home/End — пределы;
- двойной клик возвращает 70/30;
- пределы: левая от 45 до 80 %, чат не уже 280 px;
- доля запоминается в `localStorage` (в `try/catch`; без хранилища — 70/30);
- реализация — `grid-template-columns: var(--split) 8px 1fr`.

Ниже 900 px сплита нет: вверху переключатель «Урок | Чат», ползунок скрыт.

**Левая панель — вкладки «Теория», «Практика», «Код».**

- *Теория:* конспект текущего узла (§9) с подсветкой примеров. У каждого
  примера есть кнопка «Открыть в редакторе», которая копирует его во вкладку
  «Код». Внизу — «Перейти к практике».
- *Практика:* задание, которое ждёт ответа (`pending_item_id`), берётся из
  состояния сессии, а не из текста ответа. Ввод зависит от типа: `choice` —
  кнопки вариантов, `short` — поле ввода, `open` — многострочное поле,
  `code` — «Решить в редакторе» (вкладка «Код» с заготовкой). Действия:
  «Ответить», «Пропустить», «Не понимаю» (усиленный проход). После ответа
  карточка показывает вердикт, посчитанный кодом (✓ / ✗), а разбор тьютора
  приходит в чат. Без задания показывается «Взять задание»
  (`start_practice_reply`). Под карточкой — серия: «верно подряд: 1 из 2».
- *Код:* редактор CodeMirror 5 (Python). Кнопки:
  «Запустить» (Pyodide, показывает вывод), «Проверить» (только для задания
  `code` с тестами, §8), «Показать тьютору» (отправляет код в чат вопросом).

**Анкета.** Пока анкета не пройдена, левая панель показывает её: вопрос,
варианты сеткой 2×2, прогресс и «Назад», как в Telegram. Чат в это время
неактивен и подсказывает пройти анкету. После сводки кнопка «Начать урок»
запускает первый ход (логика `bot/start.begin_lesson`, перенесённая в ядро).
Ветвление анкеты считают чистые функции `student/survey.Progress`. Сервер не
хранит промежуточное состояние: клиент присылает ответы целиком, сервер
воспроизводит их через `Progress` и отвергает недопустимую последовательность.

**Правая панель — чат.** История — реплики текущей сессии из `messages`.
Реплики тьютора рендерятся через безопасный Markdown. Поле ввода: Enter
отправляет, Shift+Enter переносит строку. Пока тьютор отвечает, видно
«Тьютор печатает…», повторная отправка заблокирована. Обрыв связи после
отправки показывает «Связь прервалась — результат неизвестен», затем страница
перечитывает состояние, а не повторяет отправку. Над полем — подсказки
«Объясни проще», «Дай пример», «Дай задание».

### 7.4 Профиль `/profile`

- **Аккаунт:** имя, email, дата регистрации; смена имени; смена пароля
  (нужен текущий); тема оформления; выход.
- **Обучение** по каждому курсу: итог анкеты (уровень, что отмечено
  знакомым) и таблица тем — статус маршрута, владение
  `α/(α+β)` полосой и уверенность словами («мало данных» / «уверенно»), как в
  `/status`. Ниже — «Ближайшие шаги».

## 8. Задания с кодом и Pyodide

**Seed.** У задания `code` появляются необязательные поля:

- `starter` — заготовка в редакторе;
- `setup` — код подготовки данных (например, создаёт `df`), выполняется до
  решения;
- `tests` — код с `assert`, выполняется после решения в том же пространстве
  имён.

Миграция `004` добавляет `items.starter`, `items.setup`, `items.tests` и
`concepts.theory` (§9). План модулей тоже собирался взять номер `004`.
Кто реализуется вторым, тот берёт следующий номер.

**Исполнение.** Pyodide работает в Web Worker. Порядок: `setup` → код
ученика → `tests`. Вывод `stdout`/`stderr` собирается. Таймаут 10 секунд, после
него воркер уничтожается и создаётся заново, так что бесконечный цикл не
вешает вкладку. pandas загружается через `loadPackage`. Первая загрузка
весит 10–15 МБ, поэтому Pyodide грузится лениво, при первом открытии вкладки
«Код», с индикатором «Загружаем Python…». Без CDN вкладка честно сообщает,
что запуск недоступен; отправить код тьютору или на рубрику можно и так.

**Вердикт.** `passed` = все проверки прошли без исключений. `report` — текст
первой упавшей проверки. Клиент шлёт `{item_id, code, passed, report}`. Сервер
проверяет, что это текущее задание `code` с тестами, и проводит ответ через
ту же ветку, что и автопроверку: событие `source='autotest'`, серия,
закрытие узла, следующее задание. Тьютор получает код и `report` и пишет
разбор в чат. В ядре для этого появляется приём готового `GradeResult`
вместо вызова грейдера.

**Доверие.** Вердикт считается в браузере ученика. Подделать его можно,
но обманет ученик только себя. Это осознанная цена решения №3: сервер не
исполняет чужой код. Задания `code` без `tests` по-прежнему оценивает
рубричный грейдер.

**Банк.** Задание 10 получает `setup`/`tests`. Добавляется 6–8 заданий
`code` на узлы с операциями pandas. Тест прогоняет эталонное решение каждого
задания через его `tests` в CPython: pandas — dev-зависимость.

## 9. Теория

Конспект узла — файл `data/theory/topic01/<node_id>.md`. В Markdown его
проще писать и ревьюить, чем строку в JSON. `load_seed` кладёт текст в
`concepts.theory`, так соблюдается правило «seed грузится в БД». Валидатор
seed предупреждает об узле без конспекта.

Структура конспекта (300–700 слов): «Зачем», «Главное», «Пример» (код),
«Частые ошибки», «Источник» (ссылка на mlcourse.ai). Материалы
mlcourse.ai распространяются по CC BY-NC-SA 4.0, поэтому конспект пишется
своими словами, с указанием источника и без копирования абзацев.

Тест извлекает из конспектов блоки ```` ```python ```` и выполняет их в CPython с
pandas: пример, который не запускается, не пройдёт CI. Контент проходит
отдельное адверсариальное ревью на фактические ошибки.

Тьютор видит конспект текущего узла в контексте промпта (`core/context`).
Тогда объяснения в чате не расходятся с тем, что ученик читает слева.

## 10. Изменения ядра

- **Нейтральные тексты.** Ответы ядра ссылаются на команды Telegram (`/task`,
  `/plan`, `/skip`, «🎚 Темы»). Они заменяются формулировками, общими для
  обоих интерфейсов: «Возьми новое задание», «Загляни в маршрут». Тесты,
  которые сверяют эти строки, обновляются.
- **Структурированное задание.** В `TurnReply` добавляется поле `item_id`:
  выданное в ходе задание. Веб показывает его в «Практике», а `tail` в чат
  не выводит. Журнал по-прежнему пишет ход целиком, так модель видит задание
  в истории.
- **Из `bot/` в ядро** переезжает то, что не про Telegram: `switch_node`
  (`bot/themes`), статусы узлов, начало урока (`bot/start.begin_lesson`
  без отправки сообщений). Данные для `/plan` и `/status` (`bot/render`)
  становятся структурами в `core/overview.py`. Бот вызывает их и только
  форматирует.

## 11. Удаление Telegram (срез 49)

## 12. Тесты

- API: `httpx.AsyncClient` с `ASGITransport`, LLM — через `respx`, как
  сейчас. Фикстура даёт временные каталоги `accounts`/`users`/`materials`.
- Сценарии `test_bot_flows` и `test_e2e_topic01` переносятся на веб:
  регистрация → запись → анкета → урок → ответ → закрытие узла.
- Изоляция: два ученика проходят разное, и ни одно событие не попадает в
  чужую БД.
- Браузер: Playwright (python) — необязательная dev-зависимость. Тесты с
  маркером `e2e` пропускаются, если браузера нет. Они проверяют ползунок
  (мышь, клавиатура, запоминание), чат, ответ вариантом и мобильную
  раскладку. Pyodide-тест помечен `network`.
- Два теста `test_render` сейчас падают без `.env`: они зовут
  `get_settings()`. Чинится в срезе 37.
