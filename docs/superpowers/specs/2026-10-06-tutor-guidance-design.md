# Дизайн: дорожная карта, ведение ученика и вопросы рядом с курсом

> Дата: 2026-10-06. Основано на `llm-tutor-architecture.md` (§5–§8) и
> `llm-tutor-implementation-plan.md`. Развивает MVP (Фаза 0 + Срезы 1–7).

## 1. Зачем

MVP — тонкий сквозной срез: чат работает, модель ученика считается кодом,
грейдер проверяет цитаты. Но продукт задуман иначе: **на основании диагностики
составлять и переделывать дорожную карту и вести по ней ученика за руку**,
параллельно уточняя его портрет, и отвечать на вопросы, которые «рядом» с
курсом, а не строго внутри него.

Сегодня три вещи из четырёх сделаны не полностью:

| Замысел | Что есть сейчас |
|---|---|
| Портрет ученика (знает / не знает) | **сделано**: Beta-счётчики, журнал событий с весами по надёжности источника, затухание, диагностика |
| Дорожная карта | **наполовину**: `/plan` показывает фронт (3 доступных узла), а не путь к цели; пересмотра нет; `SessionState.plan_snapshot` — мёртвое поле |
| Ведение «за ручку» | **нет**: тьютор реактивный, режим узла считается и показывается, но ни на что не влияет |
| Вопросы рядом с курсом | **заблокировано**: при отсутствии материала — детерминированный отказ без вызова модели |

## 2. Решения (согласованы)

1. **Ведёт бот.** Он решает, что узел пройден, и переходит дальше сам.
   Ученик может **притормозить**: сказать «ещё не понял, дай больше» — и бот
   углубляет текущий узел, не идя вперёд.
2. **Маршрут хранится снимком** в состоянии сессии, пересчитывается по
   событиям, и бот сообщает об изменении. (Архитектура §6.4.)
3. **Вопросы рядом с курсом** — отвечает по общим знаниям, явно помечает, что
   это за пределами темы, и **не пишет свидетельств** в журнал.
4. **Логика ведения — отдельный слой** (`student/guide.py`), а не надстройка в
   `core/turn.py`: «за ручку» это машина состояний, её надо тестировать
   отдельно от Telegram и от LLM.
5. **Узлы без заданий в банке** (их 7 из 21) ведём диалогом, честно предупредив
   об этом; маршрут не рвём.

## 3. Маршрут

### 3.1 Что это

Путь от текущего положения до цели, а не список доступного. Подграф цели —
предки цели плюс сама цель (§6.2 «маршрут по подграфу цели»).

### 3.2 Структура

```python
class RouteStep(BaseModel):
    concept_id: str
    mode: NodeMode            # из планировщика: full / compressed / verify / ...
    status: Literal["closed", "current", "ahead"]

class Route(BaseModel):
    goal_concept_id: str | None   # из анкеты; None — вершина темы по топопорядку
    steps: list[RouteStep]        # топопорядок подграфа цели
    built_at: float

    @property
    def closed_count(self) -> int: ...
```

Хранится в `SessionState.route` (заменяет `plan_snapshot` — §8.1 называет
маршрут слоем памяти состояния сессии). Существующие сессии переживут замену:
лишние поля JSON pydantic игнорирует.

### 3.3 Пересчёт — по событиям, не на каждый показ

| Триггер (§6.4) | Что происходит |
|---|---|
| узел закрыт | следующий становится `current` |
| серия провалов | узел уходит в `reinforce` (усиленный проход) или `revisit` (вернуться к пререквизиту) |
| смена цели | подграф строится заново |
| долгий перерыв | узел больше не проходит критерий закрытия с учётом затухания — уходит в `review` (отдельного порога «сколько дней» не вводим: смотрим на decayed-оценку) |

«Серия провалов» — тот же порог, что уже есть в планировщике для буксовки
(`STUCK_FAILURES = 3` неудачи в окне `FAILURE_WINDOW_DAYS`).

Правило оттуда же: «если различия малы — оставить старый план». Сравниваем
новый маршрут со снимком и **молчим**, если нет ничего значимого:

```python
@dataclass(frozen=True)
class RouteChanges:
    closed: list[str]        # узлы, ставшие закрытыми
    added: list[str]         # появившиеся в маршруте
    removed: list[str]       # ушедшие из маршрута
    current_changed: bool

def is_significant(changes: RouteChanges, *, min_steps: int = 2) -> bool:
    # значимо: сменился текущий узел, что-то закрылось, или изменилось ≥ min_steps шагов
```

### 3.4 Что видит ученик

`/plan` показывает путь: «закрыто 4 из 21», текущий узел, следующие 3–5 и цель.
Плюс — когда маршрут реально перестроился — в ответе строка вида
«Маршрут перестроен: закрыт groupby, добавилось повторение sorting».
«Почему сейчас именно это» — §6.5: роль LLM озвучивать план и объяснять выбор.

## 4. Ведение

### 4.1 Модуль `student/guide.py`

Машина состояний на узел:

```
explain (объяснение по материалу курса)
   → practice (задание из банка)
   → check (вердикт + разбор)
   → узел закрыт → следующий узел в фазе explain
```

```python
GuidePhase = Literal["explain", "practice", "check"]
```

Ответственности: владеть фазой и текущим узлом, считать критерий закрытия,
реагировать на «ученик застрял», объявлять следующий шаг.

### 4.2 Критерий закрытия узла — считает код

Из §6.1 («стабильное решение N задач без подсказок **или** порог оценки с
малой неопределённостью»):

- **два задания подряд решены верно и без подсказок** (`hint_level == 0` в
  момент ответа), **или**
- владение ≥ `mastery_skip_threshold` **и** неопределённость мала (то же
  условие, что даёт режим `skip`).

Принципиально: «понятно?» доказательством не является, доказательство —
решённые задачи.

### 4.2.1 Новые параметры конфига

| Ключ | Дефолт | Смысл |
|---|---|---|
| `guide_success_streak` | 2 | сколько заданий подряд без подсказок закрывают узел |
| `route_min_significant_changes` | 2 | сколько шагов должно измениться, чтобы сообщать о пересмотре |

Остальное берётся из существующего: `mastery_skip_threshold`,
`diagnostic_uncertainty_threshold` (как «малая неопределённость»), `STUCK_FAILURES`.

### 4.3 «Ученик застрял»

Ученик говорит «не понял / давай подробнее / не до конца понял». Модель
распознаёт это в структурированном ответе (флаг `student_stuck`), код переводит
узел в **усиленный проход** (§6.1 — «другие объяснения, больше практики, разбор
заблуждений»):

- счётчик успехов обнуляется — узел сейчас не закроется, вперёд бот не уйдёт;
- тьютор добавляет глубину: выдержки из материала, разобранный пример, ступень
  лестницы вверх, дополнительные задания по этому же узлу.

Команда не нужна: промах модели не страшен, потому что вперёд без решённых
задач не пускает критерий закрытия.

### 4.4 Узлы без заданий

Если у текущего узла нет заданий в банке — бот честно говорит «заданий по
этому узлу у меня нет, идём разговором», фаза сразу `explain`, а закрытие — по
второму пути критерия (порог владения после разговора). Предупреждение о таких
узлах уже есть при загрузке seed.

### 4.5 Что уходит ученику в ответе

`handle_turn` возвращает не просто текст, а текст и (опционально) варианты для
кнопок: после закрытия узла ответ содержит объявление следующего узла,
краткое объяснение по материалу и задание. Для `choice`-заданий бот прикрепляет
кнопки. Тип ответа:

```python
@dataclass(frozen=True)
class TurnReply:
    text: str
    options: list[str] | None = None   # для инлайн-кнопок
```

## 5. Вопросы рядом с курсом

Убирается детерминированный отказ «не нашёл в материалах темы 1». Модель
вызывается всегда, разница — в промпте. Состояний три, а не два:

| Состояние | Как отвечает тьютор |
|---|---|
| фрагменты нашлись | по материалу, со ссылкой на раздел (как сейчас) |
| материал загружен, но по этим словам не совпал | по своим знаниям, с пометкой «это не из материалов курса» и просьбой добавить слова из материала |
| материалов курса нет вовсе (индекс пуст) | то же, но без просьбы переформулировать |

**Почему три, а не два.** Поиск ключевой, а материал курса англоязычный при
русских вопросах: «как сгруппировать строки по столбцу?» — это узел `groupby`
темы 1, но поиск промахивается. Если считать промах признаком «вне темы»,
ученик услышит, что ключевая тема курса лежит за его пределами.

**Пометка всегда о происхождении, а не о границах курса.** «Это не из
материалов курса» — правда в любом случае; «это за пределами темы 1» —
утверждение о курсе, которого бот из промаха поиска сделать не может.

Запрет выдумывать факты курса в промпте остаётся: пометка отделяет «сказано
моделью» от «сказано курсом».

**Портрет от таких ответов не портится**: на тьюторском пути события в журнал
не пишутся вообще — свидетельства дают только задания (`checked`, `rubric`) и
анкета (`self`). Требование «без записи в журнал» выполняется по построению.

Из кода уходит константа `NO_COURSE_ANSWER` и короткое замыкание, которое её
возвращало; тесты, которые его проверяли (`test_offtopic_question_is_refused_without_llm`
и родственные), заменяются на проверку новой политики: без материала ответ
уходит модели и помечается как «вне темы».

## 6. Изменения состояния и схемы

`SessionState`:

| Поле | Изменение |
|---|---|
| `plan_snapshot` | **удаляется** (мёртвое), вместо него `route: Route \| None` |
| `node_streak: int = 0` | **новое**: успешных заданий подряд без подсказок по текущему узлу |
| `phase: GuidePhase = "explain"` | **новое**: фаза ведения (`explain`/`practice`/`check`) |
| остальные | без изменений |

`TutorReply` (`llm/schemas.py`): добавляется `student_stuck: bool = False`.

Миграции БД не требуется: состояние живёт в JSON-поле `sessions.state`.

## 7. Раскладка по коду

**Новое:**
- `student/route.py` — построение маршрута (подграф цели + режимы + статусы),
  сравнение снимков, правило значимости.
- `student/guide.py` — фазы, критерий закрытия, реакция на «застрял», переход
  к следующему узлу.

**Меняется:**
- `schemas.py` — `Route`, `RouteStep`, `GuidePhase`, правки `SessionState`.
- `llm/schemas.py` — флаг `student_stuck`.
- `llm/prompts.py` — блок маршрута и фазы, правила ведения, правила «рядом с
  курсом» (в т.ч. переписанный промпт «материала нет»).
- `core/context.py` — блок маршрута в пакете (§8.2).
- `core/turn.py` — оркестрация: транспорт остаётся, решения уезжают в guide;
  возвращает `TurnReply`.
- `bot/handlers.py` — `/plan` показывает маршрут; ответы с кнопками из `TurnReply`.

### 7.1 Поток хода

```
handle_turn(текст)
├── есть pending_item_id → это ответ на задание
│     ├── проверить (код для choice/short, грейдер для open/code)
│     ├── guide: обновить streak, решить «узел закрыт?»
│     └── закрыт → пересчёт маршрута → сообщение об изменении → объявление следующего узла
└── иначе → свободный ход
      ├── модель отвечает: текст, уровень подсказки, флаг «застрял»
      ├── застрял → guide: усиленный проход, streak = 0
      └── фаза explain → в контекст подмешивается материал по узлу
```

Поиск материала для фазы `explain` — по имени и описанию узла (связка
`chunk → concept` не сделана, см. §9).

## 8. Тестирование

- **guide**: переходы фаз; оба пути критерия закрытия; «застрял» обнуляет
  счётчик и блокирует переход; узел без заданий ведёт диалогом.
- **route**: подграф цели, топопорядок и статусы; дифф; правило тишины на
  малых различиях; пересчёт по каждому триггеру.
- **промпты**: без материала ответ разрешён с пометкой; выдумывать факты курса
  запрещено; детерминированного отказа больше нет.
- **turn**: интеграционный — узел закрывается по двум задачам, маршрут
  перестраивается, сообщение об изменении уходит ученику.
- **E2E**: сквозной сценарий дополняется ведением (закрытие узла → следующий).

## 9. Порядок работ

Работа режется на три среза — в стиле проекта, каждый со своим ревью:

| Срез | Что | Почему в этом порядке |
|---|---|---|
| **8** | Вопросы рядом с курсом | самый маленький и независимый: снимает самую раздражающую текущую поломку, пока ученик не начнёт спрашивать «а что такое numpy» |
| **9** | Маршрут | ведение опирается на маршрут, поэтому он идёт первым из двух больших |
| **10** | Ведение | надстройка над маршрутом: фазы, критерий закрытия, «застрял» |

Если хочется быстрее до «составлять карту» — можно поменять 8 и 9 местами, они
не пересекаются.

## 10. Вне области

Сознательно **не** делаем в этом заходе, чтобы не превращать его в три:

- резюме сессий и консолидация памяти (§8.1, §8.3) — Фаза 2;
- определение концепта вопроса эмбеддингами (§8.2) — отдельная работа;
- детектор буксовки по времени и защита от gaming (§7) — Фаза 2;
- backfill `chunks.concept_id` (привязка материалов к узлам): сейчас у всех
  чанков `NULL`, поэтому материал ищется по имени и описанию узла;
- проактивные сообщения между сессиями (повторение в начале сессии, чек-ин) —
  §7 упоминает их с оговоркой «возможность отключить»;
- валидация генерируемых заданий (§7) — задания у нас авторские, из seed.

## 11. Риски

| Риск | Митигация |
|---|---|
| Модель не распознаёт «не понял» | промах стоит мало: вперёд без решённых задач не пускает критерий закрытия |
| Критерий закрытия слишком строгий/мягкий | оба порога в конфиге, подбираются на живых прогонах |
| Маршрут дёргается | правило значимости (§3.3) и снимок |
| Модель выдаёт общие знания за факты курса | пометка в промпте + запрет; события из диалога не пишутся |
| Режим `reinforce` не помогает | это ровно то, что описано как способ выхода из буксовки; если не работает — данные для Фазы 2 |

## 12. Что проверяется только на живом прогоне

Держит ли тьютор рамку ведения (не выдаёт решение, объявляет шаг), адекватно ли
распознаёт «не понял», не вырождается ли маршрут в линейный проход по всем
узлам. Тестами это не покрывается — как и лестница подсказок в текущем MVP.
