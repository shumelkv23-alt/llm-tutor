# Дизайн: общение с ботом — лаконичность, меню, маршрут и вход

> Дата: 2026-10-07. Развивает `2026-10-06-tutor-guidance-design.md`
> (Срезы 8–10). Основа — `llm-tutor-architecture.md`.

## 1. Зачем

Срезы 8–10 сделали машинерию ведения: маршрут, фазы занятия, критерий
закрытия узла, реакцию на «застрял». Но разговорная часть осталась «сырой»:

| Проблема | Как сейчас |
|---|---|
| Модель льёт простыни текста | в промпте только «кратко и по-дружески» — модель игнорирует |
| `/plan` — сухие две строки | «Маршрут: закрыто 4 из 21. Цель — …» |
| Нового ученика бросают в анкету | `/start` сразу задаёт вопросы без объяснений |
| Функционал спрятан в слэш-командах | «маршрут», «задание», «пропуск», статус — надо угадать команду |
| Нет способа вернуться к пройденному или забежать вперёд | маршрут ведёт линейно, выбора узла нет |

Цель — сделать общение **понятным**: короткие ясные объяснения, видимое меню,
аккуратный путеводитель по маршруту и вежливый вход в курс. Это не про новую
машинерию ведения (она уже есть), а про **слой представления и навигации**
поверх неё.

## 2. Решения (согласованы)

1. **Меню — постоянная reply-клавиатура** (7 кнопок). Всегда видна под полем
   ввода: ученик сразу понимает, что умеет бот. Слэш-команды остаются как
   синонимы.
2. **«Выбор темы» — узлы внутри topic01** (не разделы курса: мульти-тёмовой
   инфраструктуры в проекте пока нет).
3. **Лаконичность — конкретные правила в промпте** плюс HTML-оформление
   (сейчас сообщения уходят простым текстом, разметка не работает вовсе).
4. **Табличка `/plan` — моноширинный блок в рамке.** Настоящих таблиц Telegram
   не умеет; эмодзи внутри `<pre>` ломают выравнивание, поэтому сетка — из
   моноширинных символов, эмодзи только в шапке над блоком.
5. **Онбординг — представление до анкеты**, меню прикрепляется сразу.

## 3. Меню

### 3.1 Набор кнопок

Постоянная reply-клавиатура, 7 кнопок:

```
┌──────────────────┬───────────────┬─────────────┐
│ 📚 Моё обучение  │  🗺 Маршрут   │  🎚 Темы    │
├──────────────────┼───────────────┼─────────────┤
│  🎯 Задание      │ ❓ Не понимаю  │ ⏭ Пропустить│
├──────────────────┴───────────────┴─────────────┤
│                  ℹ️ Что умею                    │
└────────────────────────────────────────────────┘
```

Ряд 1 — навигация и инфо о себе; ряд 2 — действия в занятии; ряд 3 — справка.

| Кнопка | Действие | Что за этим |
|---|---|---|
| 📚 Моё обучение | дашборд ученика: текущий узел, фаза, прогресс, уровень подсказки | **новое** — `render_status` |
| 🗺 Маршрут | табличка-путеводитель | `render_plan` переписывается (§6) |
| 🎚 Темы | список узлов со статусами и переходом к любому | **новое** (§8) |
| 🎯 Задание | выдать задание по текущей теме | существует: `start_practice_reply` |
| ❓ Не понимаю | узел в усиленный проход, объясняю глубже | **новое** (§7) |
| ⏭ Пропустить | снять задание без записи свидетельства | существует: `skip_pending` |
| ℹ️ Что умею | справка по кнопкам и командам | **новое** — `render_help` |

### 3.2 Механика

Reply-кнопка отправляет **свой текст как обычное сообщение**. Значит:

- Метки кнопок — **единый источник истины** (константы в `bot/menu.py`),
  одинаковые для клавиатуры и для перехвата.
- Хендлер меню (`F.text.in_(MENU_LABELS)`, `StateFilter(None)`) идёт **до**
  общего хендлера свободного текста и разводит метку на действие.
- **Эмодзи-префикс — не для красоты**: он гарантирует, что свободный вопрос
  вроде «а что там по маршруту?» уйдёт тьютору, а не сработает как кнопка.
  Перехват — по точному совпадению полной метки.
- Слэш-команды (`/plan`, `/task`, `/skip`) остаются: кнопки — витрина поверх них.

### 3.3 Сборка клавиатуры

```python
ReplyKeyboardMarkup(
    keyboard=[[KeyboardButton(text=...), ...], ...],
    resize_keyboard=True,
    is_persistent=True,
)
```

`is_persistent=True` — клавиатура не сворачивается. Прикрепляется на онбординге
(§9) и переприкрепляется к обычным текстовым ответам; сообщения с инлайн-кнопками
вариантов (`_options_keyboard`) клавиатуру не трогают — она остаётся.

### 3.4 Поведение в потоках FSM

Пока идёт анкета или диагностика, постоянное меню мешает: нажатие кнопки
пришлёт текст, а FSM-роутеры ответят «жми кнопку варианта». Поэтому:

- при старте анкеты/диагностики меню **скрывается** (`ReplyKeyboardRemove`);
- после завершения потока меню **возвращается**.

## 4. Действия меню — где живут

Тонкие обёртки над существующим кодом (см. §10 по раскладке):

| Действие | Реализация |
|---|---|
| Моё обучение | `render.render_status(conn, state)` — по образцу `render_plan` |
| Маршрут | `render.render_plan(conn)` — переписан (§6) |
| Темы | `bot/themes.py` — инлайн-список + колбэки (§8) |
| Задание | `core.turn.start_practice_reply` (как есть) |

| Что умею | `render.render_help()` — статичный текст |

## 5. Лаконичность и оформление

### 5.1 Промпт

В `llm/prompts.py` правила «кратко и по-дружески» заменяются конкретными
(в `_TUTOR_TURN_RULES` и `_NO_FRAGMENTS_RULES`, чтобы действовало во всех
состояниях материала):

- Отвечай **2–4 предложениями по делу**, а не абзацами.
- **Без вступлений** («Отличный вопрос!», «Конечно, давай разберём») — сразу суть.
- **Одна мысль за сообщение.** Нужно больше — ученик попросит.
- **Не пересказывай материал целиком** — только нужное для текущего шага.
- Заканчивай **одним шагом или вопросом**, а не списком всего подряд.
- Сократовский стиль и лестница подсказок сохраняются без изменений.

### 5.2 HTML-оформление

Сейчас `message.answer(reply)` шлёт простой текст — любая разметка показывается
как есть. Включаем `parse_mode="HTML"` для сообщений бота:

- текст модели и данные из БД **экранируются** (`html.escape`) — модель не
  должна уметь вставлять разметку в свой ответ;
- наша разметка (жирный акцент, `<pre>` для таблички §6) формируется кодом;
- единый хелпер экранирования в `bot/render.py`.

## 6. Табличка маршрута (`/plan`, «🗺 Маршрут»)

`render_plan` переписывается: вместо двух строк — шапка + моноширинный блок.

Реальный рендер:

```
🗺 Маршрут · topic01 — цель «EDA-кейс», пройдено 4/21
<pre>
┌──────────────────────────────────┐
│ Пройдено  ███░░░░░░░░░░░░░  4/21 │
├──────────────────────────────────┤
│  [x]  Python              усвоен │
│  [x]  NumPy               усвоен │
│  [x]  read_csv            усвоен │
│  [>]  DataFrame            ←сейчас│
│  [ ]  groupby             впереди│
│  [ ]  crosstab            впереди│
│  [ ]  EDA-кейс              цель │
└──────────────────────────────────┘
</pre>
```

- `[x]` пройдено · `[>]` сейчас · `[ ]` впереди.
- Прогресс-бар `█`/`░` + `N/21`.
- **Окно вокруг текущего**, а не все 21 узел: несколько шагов назад и вперёд
  плюс цель — чтобы сообщение оставалось читаемым. Размер окна — константа.
- Внутри `<pre>` **только** моноширинные символы (рамка `┌─│└`, `█░`, `[x]`);
  эмодзи — в шапке, вне блока.

Данные берутся из того же `route_mod.build_route`, что и сейчас; меняется
исключительно представление.

## 7. «❓ Не понимаю»

Кнопка (и свободная фраза «не понял») должна надёжно включать усиленный проход
по текущему узлу.

Механика сегодня: модель сама ставит флаг `student_stuck`, код вызывает
`guide.on_student_stuck`. Но если висит задание (`pending_item_id`) и ученик
пишет «не понял», `handle_turn` примет это за **ответ на задание** — неверный
путь.

Решение — отдельный вход `core.turn.stuck_reply(conn, client, model, settings)`:

- берёт текущее состояние, применяет `guide.on_student_stuck` (узел в
  `reinforce`, `node_streak=0`, ступень подсказки вверх);
- идёт тьюторским путём (не веткой ответа, независимо от `pending_item_id`) с
  фиксированной репликой-поводом «Не понял, давай подробнее по текущей теме»;
- при висящем задании помечает `task_hinted=True` (помощь оказана — ответ уже
  не «без подсказок»);
- пишет ход одним коммитом (как `post_turn`).

`_tutor_branch` получает параметр `force_stuck: bool = False`, чтобы обработка
«застрял» не дублировалась.

## 8. «🎚 Темы» — навигация по узлам

Нажал → бот присылает **инлайн-список всех узлов** topic01 со статусами:

```
🎚 Куда идём?

Можно вернуться к пройденному или заглянуть вперёд —
про будущее предупрежу, там ещё не закрыты пререквизиты.

[✅ Python]   [✅ NumPy]      [✅ read_csv]
[▶️ DataFrame][🔜 groupby]    [🔜 crosstab]
...
```

Статусы узла:

| Статус | Когда | Поведение при нажатии |
|---|---|---|
| ✅ пройдено | владение ≥ `mastery_skip_threshold` (малая неопределённость) | перейти сразу |
| ▶️ сейчас | `current_node_id` | ничего / перейти сразу |
| 🟢 доступно | все жёсткие пререквизиты закрыты (`graph.hard_prerequisites`) | перейти сразу |
| 🔜 впереди | есть незакрытые жёсткие пререквизиты | **сначала предупреждение** |

- Колбэки: `theme:<node_id>` (переход), `theme_go:<node_id>` (подтверждённый
  переход вперёд).
- **Предупреждение** для «впереди»: *«groupby — не закрыты пререквизиты (agg,
  sorting). Всё равно идём? 🎯 Да / ↩️ Нет»*.
- **Переход**: `current_node_id=<node>`, `phase="explain"`, `mode=None`,
  `node_streak=0`, `hint_level=0`, маршрут пересчитывается
  (`route_mod.refresh`); сообщение «Ок, переходим к «X»» + объяснение.
- **Висящее задание при переходе снимается** (`pending_item_id=None`) без записи
  свидетельства — как «Пропустить», но без отдельной реплики.
- 21 узел — одна инлайн-клавиатура (Telegram держит до 100 кнопок), без
  пагинации. Группировка по рядам 3.

## 9. Онбординг

### 9.1 Первый `/start` — представление, потом анкета

Раньше: анкета сразу. Теперь — короткое представление (можно текстом или
промптом), затем анкета с **прикреплённым меню**.

```
👋 Привет! Я — твой тьютор по теме 1 курса
mlcourse.ai: «Pandas / EDA».

Как мы будем учиться:
  1 · короткая анкета — что ты уже знаешь
  2 · соберу маршрут под твою цель
  3 · ведём по шагам: объясняю → даю задачу → проверяю

Меню — на кнопках внизу. Застрял — жми ❓ Не понимаю.

Начнём 👇
```

### 9.2 После анкеты

Вместо текущего `SURVEY_DONE_REPLY` — сообщение, указывающее на меню:

```
✅ Профиль заполнен. Можно посмотреть маршрут (🗺)
или сразу взять первое задание (🎯).
Я рядом — жми ❓, если что-то непонятно.
```

Меню возвращается (анкета его скрывала, §3.4).

## 10. Раскладка по коду

**Новое:**

- `bot/menu.py` — константы меток, сборка reply-клавиатуры, таблица
  «метка → действие», хелперы скрытия/возврата меню.
- `bot/render.py` — `render_status`, `render_help`, переписанный `render_plan`
  и форматирование таблички, хелпер экранирования.
- `bot/themes.py` — инлайн-список узлов и колбэки `theme:*`.

**Меняется:**

- `bot/handlers.py` — хендлер меню (до свободного текста), `parse_mode="HTML"`,
  прикрепление клавиатуры, `/plan` через новый рендер, подключение
  `bot/themes`.
- `bot/survey.py` — представление до анкеты, скрытие/возврат меню, новый
  текст «профиль заполнен».
- `llm/prompts.py` — правила лаконичности.
- `core/turn.py` — `stuck_reply`, параметр `force_stuck` у `_tutor_branch`.
- `bot/main.py` — регистрация новых роутеров (меню, темы), если выносятся
  отдельными.

**Схема/БД:** изменений нет. Состояние живёт в JSON-поле `sessions.state`;
маршрут и текущий узел уже есть.

## 11. Тестирование

- **menu**: сборка клавиатуры из меток; перехват метки разводится на действие;
  свободный текст с похожим словом уходит тьютору, а не в меню; меню скрыто в
  FSM-потоке и возвращается после.
- **render**: табличка — выравнивание и корректные статусы; окно вокруг
  текущего; прогресс-бар; экранирование (текст модели с `<b>` показывается
  буквально).
- **stuck**: нажатие «Не понимаю» включает усиленный проход даже при висящем
  задании; `task_hinted=True`; ход записан одним коммитом.
- **themes**: переход в доступный узел; «впереди» требует подтверждения;
  висящее задание снимается; маршрут пересчитан.
- **онбординг**: представление уходит до анкеты; меню прикреплено; после анкеты
  меню вернулось.
- **промпты**: правила лаконичности присутствуют во всех состояниях материала.
- **E2E**: сквозной сценарий — вход → меню → маршрут → навигация.

| Срез | Что | Почему в этом порядке |

Каждый срез — со своим адверсариальным ревью (норма проекта).

## 13. Вне области

- переключение между **разделами курса** (topic01 → topic02) — нет
  инфраструктуры, отдельная большая работа;
- настройки/персонализация меню, кастомизация набора кнопок;
- рич-медиа (картинки, файлы) в ответах;
- кнопки внутри `<pre>`/таблички (Telegram их там не поддерживает).

## 14. Риски

| Риск | Митигация |
|---|---|
| Эмодзи в `<pre>` ломают выравнивание | эмодзи только вне блока, внутри — моноширинные символы |
| `parse_mode=HTML` ломается на тексте модели | всё динамическое экранируется хелпером |
| Кнопка меню конфликтует со свободным текстом | перехват по точной эмодзи-метке; команды остаются |
| Постоянное меню мешает во время анкеты | скрытие на время FSM-потока, возврат после |
| «Не понимаю» принимается за ответ на задание | отдельный вход `stuck_reply`, минуя ветку ответа |
| Список из 21 узла — стена кнопок | группировка рядов; при росте темы — пагинация (вне области) |

## 15. Что проверяется только на живом прогоне

Стала ли речь тьютора действительно лаконичной (промпт-правила не гарантируют);
читается ли табличка на телефоне и в десктопе одинаково ровно; не мельтешит ли
постоянное меню; удобно ли прыгать по узлам, не ломая ведение.
