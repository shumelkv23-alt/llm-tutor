# «Объясни новичку» внутри занятия — обязательное задание после важных занятий

Переделка режима из `2026-10-24-explain-novice-design.md` (срезы 85–91) по итогам
живого теста. Ядро режима — новичок без эталона, скрытый оценщик, проверка цитат
кодом, отчёт, слабые события, повторения — остаётся. Меняется, **где и когда** он
живёт: не отдельная страница по пройденному модулю, а задание в ходе курса.

## Зачем

На живом тесте режим на отдельной странице ощущался как «ещё одна функция
сбоку»: в него надо специально зайти, а значит, закрепление через объяснение
случается редко. Владелец курса хочет, чтобы объяснение было **частью
прохождения**: закрыл важное занятие — объясни его своими словами, и только
потом дальше. И чтобы во время объяснения перед глазами был большой чат с
новичком, а помощник-наставник — рядом, а не за кнопкой.

## Что видит ученик

### Когда появляется задание

Занятие помечено как **важное**, если у него в seed есть эталон `explain`. В
курсе таких 14 из 33 (таблица ниже). Когда важное занятие закрывается — любым
путём: верным ответом, проходом знакомого по анкете, автозакрытием занятия без
заданий, — перед следующим занятием появляется задание:

> ✅ Занятие «Группировка и сводные таблицы» закрыто. Перед тем как идти дальше —
> объясни его новичку своими словами.

Порядок на границе занятий: **закрыто занятие → «Объясни новичку» (если
занятие важное) → разминка повторения (если есть просроченное) → следующее
занятие** (или анкета следующего модуля, или «курс пройден»).

Задание **обязательное**: пока оно не выполнено, курс не двигается.

### Как выглядит

Вкладки урока: `Теория · Практика · Код · Повторение · Объясни`. Пока висит
задание, у «Объясни» точка, вкладка выбрана, а остальные четыре закрыты с
подписью «откроется после объяснения».

```
┌─ левая панель ───────────────────────────────┬─ правая панель ──────────┐
│ Объясни новичку: «Группировка и сводные      │ Наставник                │
│ таблицы». Конспект откроется после задания.  │ помогает тебе объяснить  │
│ ▓▓▓▓░░░░ объяснено 1 из 2 · осталось 7 реплик│                          │
│ 🐣 Новичок: Привет! Расскажешь, что такое…   │ 🧑‍🏫 …                     │
│ Ты: …                                        │                          │
│ [ Объясняй своими словами…          ] [➤]   │ [ Спроси наставника… ][➤]│
└──────────────────────────────────────────────┴──────────────────────────┘
```

- **Слева** — большой чат с новичком. Поведение новичка прежнее: знает только
  прошлые занятия, задаёт наивные вопросы, путается в противоречиях, может
  «понять» с типичной ошибкой, просит своими словами при вставке, на «просто дай
  ответ» честно не знает и советует спросить наставника справа.
- **Справа** — привычная панель чата занятия, но на время задания это
  **наставник** со своей веткой разговора (история урока там не показывается).
  Наставник видит эталон занятия и диалог с новичком, объясняет ученику суть, но
  не пишет объяснение за него. Идея, которую затронул наставник, засчитывается
  потом вполовину (как раньше).
- Кнопок «Позвать наставника» и «Завершить» нет: наставник всегда справа, а
  задание завершается само.
- Разделитель ширины работает как обычно; на телефоне переключатель
  «Урок / Наставник».

### Когда задание выполнено

Задание выполнено, когда **все обязательные идеи занятия объяснены верно**
(новичок говорит «кажется, понял») или на **10-й реплике ученика** новичку. Тогда
сессия завершается сама, во вкладке «Объясни» — отчёт (покрытие, ошибки и
пробелы с эталоном, загвоздки) и кнопка **«Продолжить»**: она начинает разминку
или следующее занятие, правая панель снова становится тьютором урока.

### Без задания

Во вкладке «Объясни»:

- прошлые отчёты (новые сверху; открываются с репликами и отчётом);
- **«Объяснить ещё раз»** — выбор закрытого важного занятия; тот же макет, но
  **добровольно**: курс не блокируется, есть кнопка «Закончить», вкладки урока
  открыты;
- блок «Что сохраняется» и переключатель «Показывать мои сессии преподавателю»
  (как раньше).

## Эталон на занятие

### Формат

Эталон переезжает из `topic` в узел-занятие (`nodes[]` seed-файла):

```json
{
  "id": "grouping",
  "name": "Группировка и сводные таблицы",
  "...": "...",
  "explain": {
    "ideas": [
      {"id": "split_apply_combine", "text": "…", "required": true, "expect": "…"}
    ],
    "pitfalls": [
      {"id": "groupby_returns_table", "belief": "…?", "fix": "…"}
    ]
  }
}
```

- Поля `lesson` у идей и загвоздок больше нет: занятие задаётся местом в файле
  (загрузчик проставляет его сам, как модуль занятию).
- Правила (`course/seed._check_explain`, теперь по занятиям): идей **2–4**,
  обязательных **≥ 1**, загвоздок **1–2**, id уникальны в пределах модуля,
  `belief` — вопрос. Ошибка формата — `SeedError`.
- Модульный `topic.explain` убирается из схемы (`Topic`) и из seed. Опубликованный
  модуль без важных занятий — предупреждение.
- Загвоздки, утверждающие о поведении библиотеки, проверяются запуском
  (`scripts/check_explain_claims.py`, id совпадают с id загвоздок).

### Важные занятия

| Модуль | Занятия (id) |
|---|---|
| 1 | `selection`, `grouping`, `eda_case` |
| 2 | `distributions`, `numeric_relations` |
| 3 | `tree_criteria`, `knn`, `validation` |
| 4 | `linreg`, `logreg`, `nonlinear` |
| 5 | `bagging_basics`, `forest`, `feature_importance` |

Идеи и загвоздки модульного эталона переносятся в эти занятия, недостающее
дописывается (2–4 идеи, 1–2 загвоздки на занятие).

## Задание: правила

### Висящее задание (вычисляется, не флаг)

`student/explain.pending_lesson(conn, route) -> str | None` — самое раннее (по
порядку курса) занятие, которое:

1. закрыто в снимке маршрута;
2. имеет эталон (`concepts.explain`);
3. закрыто **не раньше** факта `explain_since`;
4. не имеет **завершённой обязательной** сессии (`kind = "required"`,
   `status = "finished"`).

Так задание ставится при любом пути закрытия, и его нельзя «потерять» сбоем
хода. Факт `explain_since` (unix-время) пишется один раз при открытии БД ученика
(`userdb.open`, как `review.backfill`): уже закрытые до обновления занятия старых
учеников заданий не дают.

Занятие, переоткрытое провалами, перестаёт быть закрытым — задания по нему нет,
пока его не закроют снова (тогда, если обязательной сессии ещё не было, оно
появится).

### Сессия задания

- Обязательная сессия начинается **сама**, когда ученик впервые после закрытия
  видит состояние занятия или делает ход: `core.explain.ensure_required` создаёт
  её (`kind = "required"`, `concept_id`) с первой репликой новичка
  (`[novice].opening` с названием занятия), без вызова модели. Повторный вызов
  возвращает ту же активную сессию.
- Добровольная — кнопкой «Объяснить ещё раз» (`kind = "voluntary"`), только по
  закрытому важному занятию и только когда обязательной нет. Активная сессия у
  ученика одна.
- Ход новичку — `core.explain.turn(..., to="novice")`: оценщик → установка →
  новичок → фильтр (как раньше). Ход наставнику — `to="mentor"`: наставник →
  оценщик отмечает затронутые идеи. Поле `ExplainState.mode` и `set_mentor`
  уходят.
- **Автозавершение**: после хода новичку, если все обязательные идеи `correct` —
  `finish(end_reason="coverage")`; если реплика ученика новичку десятая —
  `finish(end_reason="limit")`. В том же коммите, что и ход. Ответ новичка этого
  хода записывается (на `coverage` — его «кажется, понял»).
- Добровольную можно закончить кнопкой (`end_reason="button"`); обязательную —
  нет (409).
- Отчёт, события `explain`, владение и повторения — как раньше (`_close`).
- Брошенная **добровольная** сессия (24 ч без ходов) закрывается с отчётом.
  Обязательная по времени не закрывается — она ждёт ученика; закрывается она
  (`end_reason = "stale"`) только если занятие перестало быть важным (эталон убрали
  из seed).

### Блокировка

Пока есть висящее задание (обязательная сессия активна или ещё не начата), ходы,
двигающие курс, отвечают **409** «Сначала объясни новичку «…»», событий и
записей нет: `lesson/next`, `lesson/task`, `lesson/answer`, `lesson/code-result`,
`lesson/skip`, `lesson/stuck`, `lesson/resume`, `lesson/verify`, `lesson/switch`,
`lesson/review/start`. `lesson/chat` идёт наставнику. Анкета следующего модуля
ждёт: в `lesson_state` задание важнее анкеты.

### «Продолжить»

`core.explain.proceed(...)` — после завершённой обязательной сессии: если висит
ещё одно задание (закрыли несколько важных занятий разом), начинается оно; иначе
— разминка (`turn._warmup`) или следующее занятие (`turn._start_lesson`; режим
`verify` — задание прохода), как это делает граница занятий сегодня. Анкета
следующего модуля и «курс пройден» — тем же путём, что и сейчас.

Зависимости: `core/explain` импортирует `core/turn` (граница занятий);
`core/turn` импортирует только `student/explain` (`pending_lesson`) — цикла нет.

### Граница занятий в `handle_turn`

В блоке `closed_note` перед разминкой: если `pending_lesson(...)` вернул занятие,
разминка и урок следующего занятия **не** начинаются; к ответу добавляется
`EXPLAIN_NOTE` («Перед тем как идти дальше — объясни новичку «…»»). То же — во
всех местах, где ход начинает следующее занятие после закрытия (`_issue_task` при
автозакрытии, проход `verify`).

### Конспект закрыт на сервере

Пока висит задание, `views.lesson_state` не отдаёт содержимое урока: `node`
(теория, разделы) и `item` — `null`; вместо них блок `explain`. Закрытая вкладка —
не только картинка.

### Схема — миграция `009_explain_lesson.sql`

```sql
ALTER TABLE concepts ADD COLUMN explain TEXT;                    -- JSON ExplainConfig
ALTER TABLE explain_sessions ADD COLUMN concept_id TEXT;         -- занятие; NULL — старая модульная
ALTER TABLE explain_sessions ADD COLUMN kind TEXT NOT NULL DEFAULT 'voluntary';
CREATE INDEX IF NOT EXISTS idx_explain_sessions_concept ON explain_sessions(concept_id, kind, status);
```

`topics.explain` остаётся и больше не пишется. Старые модульные сессии (тестовые)
видны в истории как «Модуль N» и ничего не блокируют.

### API занятия

Всё под замком ученика, `POST` — JSON.

| Запрос | Тело | Ответ |
|---|---|---|
| `POST …/lesson/explain/turn` | `{text}` | реплика ученика и новичка, свежее состояние |
| `POST …/lesson/chat` при задании | как сейчас | реплика наставника (ветка задания) |
| `POST …/lesson/explain/start` | `{node_id}` | добровольная сессия (400 — занятие не закрыто или не важное; 409 — есть активная или висит обязательная) |
| `POST …/lesson/explain/stop` | `{}` | закончить добровольную (409 — обязательная) |
| `POST …/lesson/explain/continue` | `{}` | «Продолжить»: следующее задание, разминка или занятие (409 — задание не выполнено) |
| `GET …/lesson/explain/sessions/{id}` | — | реплики и отчёт |
| `POST …/lesson/explain/settings` | `{share}` | согласие |

Блок `state.explain`:

```text
active:   {id, kind, node_id, name, messages (новичок), mentor (ветка наставника),
           progress {done, total}, turns_left, status, report} | null
pending:  node_id | null          # висит обязательное (до старта сессии или после отчёта)
ready:    bool                     # отчёт есть, можно «Продолжить»
lessons:  [{node_id, name}]        # закрытые важные — для «Объяснить ещё раз»
history:  [{id, kind, node_id, name, started_at, coverage}]
share:    bool
```

Ошибки: 409 — блокировка, не та сессия, обязательную нельзя закончить; 422 —
пустой или длиннее 8000 символов текст; 502 — модель недоступна (реплика не
записана).

## Пороги (`data/prompts/explain.toml`)

`max_student_turns = 10`, `wrap_up_share = 1.0` (все обязательные), `pitfall_max =
1`, `pitfall_every = 2`, остальное прежнее. Новичок в промпте знает: названия
пройденных до этого занятий и название объясняемого (оглавление модуля ему не
нужно). Установка `ask` — про раздел объясняемого занятия (название раздела, не
текст).

## Крайние случаи

- Закрыли разом несколько важных занятий (проход знакомого) — задания идут по
  очереди, «Продолжить» ведёт к следующему.
- Важное занятие — последнее в курсе: после задания «Продолжить» показывает
  «курс пройден».
- Модель недоступна — реплика не записана (502), её можно отправить снова;
  других обходов у обязательного задания нет.
- Эталон занятия убрали из seed, пока висит задание — задание исчезает (условие 2),
  а активная обязательная сессия по нему закрывается с `stale`-отчётом при
  следующем открытии состояния занятия.
- Две вкладки — ходы по очереди под замком; ход по завершённой сессии — 409.
- `scripts/dev_close_module.py` закрывает занятия «сейчас» — для важных занятий
  модуля появятся обязательные задания (удобно для ручной проверки).

## Срезы и тесты

### Срез 92 — эталон на занятие

Формат и проверки, перенос с модуля, миграция `009`, `concepts.explain`, эталон 14
занятий, проверка запуском. Тесты: формат (2–4 идеи, ≥ 1 обязательная, 1–2
загвоздки, `belief` — вопрос, дубли), у каждого из 14 занятий эталон есть, у
остальных нет; эталон доходит до БД.

### Срез 93 — ядро

`pending_lesson`, `explain_since`, `ensure_required`, `start_voluntary`,
`turn(to=…)`, автозавершение, `proceed`, `stop`, граница занятий в `handle_turn`.
Тесты: задание появляется при **каждом** пути закрытия важного занятия (ответ,
проход `verify`, автозакрытие без заданий); старые закрытые занятия заданий не
дают; порядок задание → разминка → занятие; несколько заданий по очереди;
автозавершение по покрытию и по лимиту в том же коммите; обязательную нельзя
закончить; добровольная не блокирует; наставник не двигает покрытие; новичку
эталон не попадает (прежние тесты, включая враждебного оценщика).

### Срез 94 — API занятия

Развилка в `api_lesson`, ходы `lesson/explain/*`, блок `explain`, урок скрыт при
задании; уходят `api_explain` и страницы, редирект старых адресов. Тесты: каждый
заблокированный ход — 409 без событий; `chat` при задании — наставник, не тьютор
урока; в состоянии нет теории и задания, пока висит задание; «Продолжить» до
выполнения — 409; редирект.

### Срез 95 — интерфейс

Вкладка «Объясни», закрытые вкладки, наставник в правом чате, отчёт и
«Продолжить», «Объяснить ещё раз», история, согласие. Тесты страницы: вкладка
есть, нет inline-скриптов и стилей.

### Срез 96 — админка, документы, E2E

Админка — занятие и тип в сессии. README, архитектура, CLAUDE.md. E2E: закрыть
важное занятие → задание → две реплики новичку → вопрос наставнику → отчёт →
«Продолжить» → следующее занятие.
