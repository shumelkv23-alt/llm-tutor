# Восстановление пароля по почте — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.
> Спека — `docs/superpowers/specs/2026-10-13-password-reset-design.md` (ссылки
> «§N» ведут туда). Каждый срез — TDD: сначала падающие тесты, потом код. После
> среза — адверсариальное ревью отдельным агентом (находки воспроизводятся
> запуском кода, ревьюер ничего не правит) → триаж → фиксы отдельным коммитом
> `Аудит среза N: …` с регрессионными тестами.
> Журнал исполнения — `.superpowers/sdd/2026-10-13-password-reset/progress.md`.

**Goal:** Ученик, забывший пароль, сам получает письмо со ссылкой и задаёт новый
пароль. В письме — одноразовый токен; в БД — только его хеш; ответ не выдаёт,
зарегистрирован ли адрес; сброс закрывает все сессии ученика.

**Architecture:** Токены сброса — новая таблица в БД аккаунтов (миграция 004) и три
функции в `web/accounts.py`. Почта — новый модуль `web/mailer.py` (`SmtpMailer` на
`smtplib` в потоке, `LogMailer` — режим показа без настроенного SMTP), внедряется в
`create_app` как LLM-клиент. Два эндпоинта в `web/api_auth.py` под общим
`api_guard` и две страницы на `auth_base.html`.

**Tech Stack:** прежний: FastAPI, Jinja2, SQLite, smtplib, pytest
(`asyncio_mode=auto`). Новых зависимостей нет.

## 1. Уточнения к спеке

1. **Срок жизни ссылки — в минутах** (`PASSWORD_RESET_TTL_MINUTES`, дефолт 60):
   так его читает человек в `.env`; в БД лежит абсолютное `expires_at`.
2. **Лимит запросов письма — 3 за 15 минут** (`PASSWORD_RESET_LIMIT`): письма
   дороги, а честный повтор «письмо не пришло» укладывается.
3. **Счётчик лимитера растёт на каждый принятый запрос**, а не только на
   неудачный: защищаем отправку письма, а не вход. Ключ — email (как у
   `LoginLimiter`), поэтому поведение для существующего и несуществующего адреса
   одинаково.
4. **Текст сообщения об успехе живёт в шаблоне**, а не в ответе API: тогда тела
   ответов не различаются даже случайно, и антиперечисление не зависит от того,
   кто читает JSON.
5. **`GET /reset-password` не проверяет сессию**: токен — самостоятельное
   доказательство, а залогиненного ученика сброс всё равно разлогинит.
6. **`GET /forgot-password` вошедшего уводит на `/profile`** — как `_auth_page`
   у входа и регистрации: вошедшему пароль меняется в профиле.
7. **Остаточная разница времени ответа** (у существующего адреса — ещё и вставка
   токена) принята сознательно: это единицы микросекунд, а не scrypt, и выровнять
   её фиктивной записью мешает внешний ключ на `users`.
8. **`BackgroundTasks` и тесты**: `httpx.ASGITransport` дожидается фоновых задач
   Starlette, поэтому запись в подставном мейлере видна сразу после ответа. Если
   это окажется не так — фолбэк: `await mailer.send(...)` прямо в эндпоинте
   (подставной мейлер мгновенный).

## 3. Риски

- **Gmail принимает только «пароль приложения»** (16 символов при включённой
  двухэтапной аутентификации). Без него — режим показа через `LogMailer`;
  при отказе аутентификации в журнале остаётся код 535 и подсказка.
- **`PUBLIC_BASE_URL` за прокси** должен совпадать с внешним адресом, иначе
  ссылка в письме нерабочая.
- **`LogMailer` пишет токен в журнал** — это режим локального показа; на публичном
  сервере так работать нельзя (сказано в `.env.example` и README).
- **Лимитер в памяти процесса** сбрасывается рестартом; проект и так рассчитан на
  один воркер uvicorn.

## 4. Проверка вживую

```bash
uv run pytest -q
uv run pytest -q -m e2e tests/e2e
uv run python -m llm_tutor.web
```

1. Зарегистрировать ученика, выйти, на `/login` нажать «Забыли пароль?».
2. Ввести email → «проверьте почту»; в окне сервера — письмо со ссылкой.
3. Открыть ссылку → новый пароль → «пароль изменён».
4. Войти новым паролем; вход, открытый в другой вкладке, разлогинен.
5. Открыть ту же ссылку повторно → «ссылка недействительна».

Настоящая отправка: `.env` → `SMTP_USER`, `SMTP_PASSWORD` (пароль приложения),
`PUBLIC_BASE_URL`; перезапуск. Как получить пароль приложения —
`myaccount.google.com` → Безопасность → Двухэтапная аутентификация → «Пароли
приложений».
