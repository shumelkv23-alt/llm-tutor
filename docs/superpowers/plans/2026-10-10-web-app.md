# Веб-приложение вместо Telegram-бота — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.
> После каждого среза — адверсариальное ревью отдельным агентом (находки
> воспроизводятся запуском кода, ревьюер ничего не правит) → триаж → фиксы
> отдельным коммитом `Аудит среза N: …` с регрессионными тестами.

**Goal:** Тьютор работает в браузере. Четыре страницы: главная, мои курсы,
занятие, профиль. Несколько учеников со входом. На странице занятия слева
теория, практика и редактор кода (70 %), справа чат тьютора (30 %), между ними
ползунок. Код запускается в браузере через Pyodide и проверяется тестами
задания. Оформление — из панелей `bar_order_bot` (Azati). Telegram-бот
удаляется последним срезом.

**Architecture:** Новый слой `web/` (FastAPI + Jinja2 + обычные JS/CSS, без
сборки) над неизменным ядром. Ученик = отдельная SQLite-БД
`data/users/<user_id>/<course_id>.sqlite3`, поэтому инвариант ядра «одна БД —
один ученик» сохраняется. Аккаунты, веб-сессии и записи на курсы лежат в
`data/accounts.sqlite3`, материалы RAG — в `data/materials.sqlite3`.
Изменяющие запросы занятия идут под `asyncio.Lock` ученика. Каждый ответ API
возвращает свежее состояние занятия, и интерфейс перерисовывается по нему.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, Jinja2, markdown-it-py,
pydantic 2, SQLite + FTS5, pytest (asyncio_mode=auto), httpx + respx;
Pyodide и CodeMirror 5 с CDN по точным версиям; Playwright — необязательно.

**Spec:** `docs/superpowers/specs/2026-10-10-web-app-design.md`

## Global Constraints

- Весь набор: `uv run pytest -q`. На старте 589 passed и 2 failed: два теста
  `test_render` зовут `get_settings()` без `.env`. Это чинится в срезе 37.
- Слои: `web → core/student/db`. `core/*` и `student/*` не импортируют ни
  `bot/*`, ни `web/*`.
- **Вывод.** `core.*` отдаёт сырой текст. В вебе текст модели и ядра проходит
  `web.markdown.render()` (markdown-it-py, `html=False`, ссылки только
  `http(s)`). В шаблонах — автоэкранирование Jinja2. `|safe` разрешён только
  для результата `markdown.render()` и для иконок.
- В JS не используется `innerHTML` с данными: только `textContent` или HTML,
  уже отрендеренный сервером.
- Схема БД ученика меняется только миграциями `migrations/`. Схема аккаунтов —
  `migrations_accounts/`. Новые поля состояния кладутся в `SessionState` с
  дефолтами.
- Telegram-бот работает до среза 49. Правки ядра не ломают его тесты.
- Подпись `"Уверенно"` и ключи фактов анкеты не меняются (CLAUDE.md).
- Внешние скрипты — только с `cdn.jsdelivr.net` и `cdnjs.cloudflare.com`, с
  точной версией. Шрифты — локальные woff2.
- Коммиты по-русски: `Срез N: …`, `Аудит среза N: …`.

## Review Focus

Ввод, который спека подразумевает, но легко пропустить. В скобках — задача,
где он проверяется тестом.

1. **Чужие данные.** Ученик A не видит и не меняет БД ученика B ни через
   `course_id`, ни через подмену cookie (38.2, 39.3).
2. **Двойная отправка.** Два одновременных `POST /chat` от одного ученика дают
   два последовательных хода, а не перемешанное состояние (39.2, 41.3).
3. **Старое задание.** Ответ с `item_id`, который уже не висит, получает 409 и
   текст «задание неактуально» без события в журнале (41.3).
4. **Подделанная анкета.** Недопустимая последовательность ответов
   (пропущенный вопрос, индекс вне вариантов) отвергается, факты не пишутся
   (41.2).
5. **Open redirect.** `/login?next=https://evil` ведёт на `/` (38.3).
6. **XSS в чате.** Реплика модели с `<script>` и `javascript:`-ссылкой
   отображается текстом (41.1, 42.3).
7. **Бесконечный цикл в коде** — вкладка не виснет, через 10 с воркер
   перезапускается (46.2).
8. **Ползунок** не выходит за пределы 45–80 % и переживает перезагрузку
   (42.2).

## Отложенное

- История чата после перезагрузки показывает задание внутри реплики тьютора:
  журнал хранит ход целиком (модели нужно видеть задание). Живой ход кладёт
  задание в «Практику», а в чат — отметку. Если мешает — метка начала
  задания в `messages.meta` и обрезка при показе истории.
- «Ближайшие шаги» после анкеты не пишутся в журнал и после перезагрузки
  из чата пропадают.
- Аудит 38.4: `users.id` без AUTOINCREMENT — после удаления пользователя его
  id и каталог `data/users/<id>` достались бы новому ученику. Удаления
  аккаунтов в приложении нет; когда появится, нужны AUTOINCREMENT (миграция
  с пересозданием таблицы при выключенных внешних ключах) и удаление
  каталога ученика вместе с аккаунтом.
- Выбор темы «впереди» (пререквизиты не закрыты) в вебе переходит сразу; бот
  переспрашивал и перечислял незакрытые пререквизиты. Если нужно — флаг
  `prereqs_open` в списке тем и подтверждение в `route.js`.
