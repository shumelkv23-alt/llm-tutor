# Админка (первая итерация) — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.
> Спека — `docs/superpowers/specs/2026-10-12-admin-panel-design.md` (ссылки
> «§N» ведут туда, если не сказано иное). Каждый срез — TDD: сначала падающие
> тесты, потом код. После среза — адверсариальное ревью отдельным агентом
> (находки воспроизводятся запуском кода, ревьюер ничего не правит) → триаж →
> фиксы отдельным коммитом `Аудит среза N: …` с регрессионными тестами.
> Журнал исполнения — `.superpowers/sdd/2026-10-12-admin-panel/progress.md`.

**Goal:** Раздел `/admin` для владельца курса: список учеников с прогрессом,
карточка ученика (только чтение), сброс пароля и закрытие сессий, воронка по
занятиям и таблица трудных заданий. Только чтение того, что посчитал код;
единственные записи — управление аккаунтами и `admin_log`.

**Architecture:** Роль — флаг `users.is_admin` (миграция аккаунтов 003). Данные
админки лежат в `web/admin.py`: один обход БД всех записанных учеников строит
**снимок** (`Snapshot`), из него считаются список, воронка и таблица заданий;
снимок кэшируется на 60 с. Карточка ученика считается заново, без кэша.
Статусы тем и прогресс берутся из `core.overview` — формул в админке нет.
Страницы — Jinja2 в общей оболочке, действия — `/api/admin/*` под
существующим `api_guard`.

**Tech Stack:** прежний: FastAPI, Jinja2, SQLite, pytest (`asyncio_mode=auto`).
Новых зависимостей нет.

## 1. Уточнения к спеке

Решения, принятые при составлении плана. Не расходятся со спекой по
поведению, но уточняют то, что в ней не определено.

1. **Список учеников тоже берётся из снимка** (спека §4 не говорила об
   источнике). Один обход вместо двух: прогресс, слабые темы, последняя
   активность, события для воронки и заданий собираются за раз. Цена —
   данные списка могут отставать до 60 с; кнопка «Обновить» (`?refresh=1`)
   пересчитывает сразу. Имена, email, `last_login_at` и число сессий читаются
   из `accounts.sqlite3` свежими на каждый запрос.
2. **Ход ученика и чтение.** Соединение ученика общее с его ходами, а ход
   держит `asyncio.Lock` и может не успеть закоммитить (CLAUDE.md, «Атомарность
   хода»): чтение «посреди хода» увидело бы половину изменений. Поэтому:
   - снимок читает ученика только если `not pool.lock(...).locked()`; занятого
     берёт из предыдущего снимка (если был) и помечает `busy`;
   - карточка занятого ученика показывает баннер «Ученик сейчас отвечает —
     обновите страницу через несколько секунд» вместо данных курса.
   Чтение синхронное, без `await`: между проверкой замка и чтением ход
   вклиниться не может.
3. **Какой БД касаемся.** Только записанных на курс и только если
   `pool.exists(...)`; БД не создаётся. Открытие (`pool.open`) доводит
   схему/seed/материалы до текущих — это то же, что случится при входе
   ученика, и это идемпотентно.
4. **Занятие задания** — главный концепт (`course.seed.main_concept`), а не
   любой из `concept_weights`. Раздел — `item.section`.
5. **«С первой попытки»** — по самому раннему `events.ts` пары
   (ученик, задание); при равенстве `ts` — по `events.id`.
6. **«Дошли»** (§7.1) считается только у учеников с `course_survey_done`:
   до анкеты статусы тем не осмысленны.
7. **Ключ кэша** — id курса; курс один, но интерфейс `snapshot(course)` не
   предполагает этого. Снимок хранится в `app.state.admin_cache`, а не в
   модуле: тесты создают приложения независимо и не должны видеть чужой кэш.
8. **Часы для тестов.** `admin.snapshot(..., clock=time.time)`: кэш и «данные
   на HH:MM» проверяются без `sleep`.
9. **404 вместо 403** для вошедшего не-админа — единый обработчик, а не
   проверка в каждом маршруте: новый маршрут не может её забыть (по аналогии
   с `api_guard`). Реализация — зависимость на уровне роутера
   (`APIRouter(dependencies=[Depends(admin_user)])`), а не в каждой функции.
10. **Список — все аккаунты, включая админов** (с пометкой «админ»): владелец
   обычно и сам учится. Сводка «Аккаунтов» считает всех. (Срез 64.)
11. **Текущее занятие слабым не считается**: `topic_rows` помечает `weak` только
    у закрытых занятий со статусом «закрыто», а текущее имеет статус
    «текущее». `closed` при этом считает и закрытое текущее занятие — как
    карточка курса (`course_progress`). (Срез 64.)

## 2. Global Constraints

- Весь набор: `uv run pytest -q` (~30 с, без браузера); на старте среза 63
  записать в журнал исполнения число прошедших тестов как базу.
  Браузерные — `uv run pytest -q -m e2e tests/e2e`.
- Слои: `web → core/student/db`. `core/*` и `student/*` админки не знают,
  `web/admin.py` может импортировать `core.overview`, `course.seed`,
  `db.repos`, `web.views` (`solved_items`).
- Схема аккаунтов меняется только миграцией `003_admin.sql`;
  `accounts.SCHEMA_VERSION = 3`. Схема БД ученика **не меняется**.
- CSP без `unsafe-inline`: нет `<script>` и `style=""` в шаблонах; ширины
  полос прогресса — JS через CSSOM по `data-percent`. Нового внешнего адреса
  нет, `content_security_policy` не трогаем.
- `innerHTML` в админке не используется. Данные в шаблонах — автоэкранирование
  Jinja2; JS пишет через `textContent`.
- Эндпоинты — `async def`. scrypt — через `asyncio.to_thread`.
- Секреты: временный пароль не пишется ни в лог, ни в `admin_log`, ни в
  исключения; ответ с ним — `Cache-Control: no-store`.
- Тесты не зависят от `.env`: фикстуры `web_settings`/`settings`.
- Комментарии, докстринги и коммиты — по-русски: `Срез N: …`,
  `Аудит среза N: …`.
- Новые тексты интерфейса — по-русски, в стиле остального веба; «занятие», а
  не «тема».

## 3. Review Focus

Что ревьюер проверяет запуском, а не чтением:

1. **Доступ.** Каждый маршрут `/admin*` и `/api/admin*` (перебрать по
   `app.routes`) отвечает не-админу 404, гостю — редирект (страницы) / 401
   (API). Нет маршрута админки, обходящего зависимость. Снятие роли действует
   на следующем запросе без перелогина.
2. **CSRF.** Изменяющие `/api/admin/*` с чужим `Origin`/`Sec-Fetch-Site` и без
   `application/json` отклоняются (общий `api_guard`, но проверить именно эти
   маршруты).
3. **Утечки.** В HTML, JSON, логах и `admin_log` нет `password_hash`,
   подстроки `scrypt$`, токенов сессий, временного пароля (кроме единственного
   ответа сброса).
4. **Согласованность.** Снимок не читает ученика, у которого идёт ход
   (`lock.locked()`); два параллельных запроса снимка не строят его дважды
   (нет `await` между проверкой кэша и записью — проверить).
5. **Самоприменение.** Сброс пароля и закрытие сессий над собой — 400, и
   ничего не изменилось (сессия админа цела, пароль прежний).
6. **Битые данные.** БД ученика, которая не открывается; ученик без файла;
   событие по заданию, которого нет в seed; `concept_id = NULL` в событии;
   пустой курс (нет учеников) — страницы отвечают 200 без трейсбека.
7. **Числа.** Проценты и доли — деление на ноль; «Закрыли ≤ Дошли ≤ учеников»
   на подготовленных данных; сумма по занятиям в воронке сходится с
   прогрессом в списке.
8. **XSS.** Имя `<script>…`, `"><img onerror=…>` и условие задания с
   разметкой выводятся текстом на всех трёх страницах и в диалоге пароля.
9. **Миграция.** БД версии 2 с данными (пользователи, сессии, записи)
   поднимается до 3 без потерь; повторное открытие ничего не меняет; БД версии
   4 (новее приложения) по-прежнему отказывает.

## 5. Готовность

- `uv run python -m llm_tutor.web.cli make-admin --email …` делает аккаунт
  админом; в меню появляется «Админка», у остальных её нет и адрес даёт 404.
- Список, карточка и аналитика строятся на настоящем курсе (пять модулей) и на
  данных нескольких учеников; битая БД одного ученика ничего не ломает.
- Сброс пароля выдаёт временный пароль один раз, закрывает все сессии
  ученика; действия попадают в `admin_log` без секретов.
- Диалоги учеников нигде не показываются.
- `uv run pytest -q` и `uv run pytest -q -m e2e tests/e2e` зелёные.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Снимок по сотням учеников блокирует цикл событий (чтение синхронное) | замеряем в 67.4 и пишем в журнал; порог, после которого нужна сводная таблица (спека §9), — по замеру. До тех пор кэш 60 с |
| Админ читает данные посреди хода ученика | Ruling 2: замок занят → пропуск; тест на `lock.locked()` |
| `pool.open` для давно не заходившего ученика пишет в его БД (миграции, seed, `remap_progress`) | идемпотентно и произошло бы при его входе; в журнале отметить. Если ревью найдёт недопустимое — читать через `mode=ro` без миграций (отдельное решение) |
| `ALTER TABLE ... ADD COLUMN` не идемпотентен | `migrate()` применяет файл ровно один раз по `user_version` в транзакции — как миграция 004 ученика; тест «повторное открытие» |
| Временный пароль виден админу и в буфере обмена | осознанный компромисс (спека §2 п. 5); ссылка восстановления — следующая итерация |
| Раздутые таблицы на `/admin/course` на телефоне | таблицы в контейнере с горизонтальной прокруткой; e2e 320 px в срезе 66 проверяет оболочку, а в 67 — таблицу вручную |
