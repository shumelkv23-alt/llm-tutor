# Показ llm_tutor вживую: что нажать и что показать

Сценарий для показа на **настоящих базах и с настоящей моделью**. Никаких демо-учеников,
заглушек и отдельных баз: приложение запускается как обычно, ученики заводятся в
браузере, ответы тьютора, новичка и наставника приходят от модели.

Курс показа: демо-курс **«Деревья решений и случайный лес»** (`trees-demo`), 5 занятий.
Три из них «важные» (`tree_criteria`, `bagging_basics`, `forest`): после каждого ученик
объясняет занятие новичку.

Терминальные команды `sc …` только читают базы и показывают, что сделал каждый ход
внутри. Они ничего не пишут и модель не вызывают.

## 1. Что понадобится

| Что | Зачем |
|---|---|
| Рабочий ключ в `.env` (`OPENROUTER_API_KEY`) и сеть | урок, чат, новичок, оценщик, наставник проекта |
| Интернет в браузере | Pyodide (запуск кода ученика) грузится с `cdn.jsdelivr.net` |
| Два настоящих аккаунта, заведённых через браузер | **А** показывается вживую с нуля, **Б** подготовлен накануне |
| Терминал в корне проекта | команды `sc` |

Аккаунт **А** проходит всё на глазах у зрителей: анкета, первые вопросы, «не понял»,
закрытие занятия, «Объясни новичку». Аккаунт **Б** нужен для того, на что вживую нет
времени: повторение (нужны сроки, которые наступили) и проект (нужен пройденный курс).

Оба аккаунта обычные, роль админа получает только Б (шаг 10). Пароли и почты придумайте
сами и запишите: после регистрации восстановить их нельзя, пока не настроена почта.

## 2. Подготовка накануне

Нужна ветка с «Объясни новичку» и проектом (она уже в `master`).

```bash
git switch master && git pull origin master
uv sync
cp -n .env.example .env     # если .env ещё нет; впишите свой OPENROUTER_API_KEY
uv run python -m llm_tutor.web          # http://127.0.0.1:8000
```

Пути баз берутся из `.env` (`ACCOUNTS_DB_PATH=data/accounts.sqlite3`,
`USERS_DIR=data/users`). Их менять не надо: это и есть настоящие базы. Во всех
терминалах рабочая папка одна и та же, тогда `sc` и сервер смотрят в одни файлы.

В отдельном терминале заведите короткое имя:

```bash
alias sc="uv run python scripts/showcase.py"
```

### 2.1. Материалы RAG демо-курса (один раз, по желанию)

У демо-курса материалы свои, `data/demo/materials.sqlite3`; в репозитории файла нет.
Без него тьютор объясняет по конспекту текущего раздела, а в `sc context` будет
«материалы RAG: empty». Чтобы показать и поиск по материалам:

```bash
uv run python -m llm_tutor.course.ingest https://mlcourse.ai/book/topic03/topic03_decision_trees_kNN.html --topic 1 --db data/demo/materials.sqlite3
uv run python -m llm_tutor.course.ingest https://mlcourse.ai/book/topic05/topic5_part1_bagging.html --topic 1 --db data/demo/materials.sqlite3
uv run python -m llm_tutor.course.ingest https://mlcourse.ai/book/topic05/topic5_part2_random_forest.html --topic 1 --db data/demo/materials.sqlite3
```

Файл не коммитьте.

### 2.2. Аккаунт Б: пройти курс по-настоящему (30-40 минут)

Зарегистрируйтесь в браузере (аккаунт Б) и запишитесь на «Деревья решений и случайный
лес». Пройдите все 5 занятий как обычный ученик с настоящей моделью:

1. Анкета: уровень любой, блоки «Деревья решений», «Переобучение», «Бэггинг» с разными
   ответами.
2. Каждое занятие: части объяснения, вопросы разделов, итоговое задание.
3. После каждого «важного» занятия (`tree_criteria`, `bagging_basics`, `forest`)
   пройти «Объясни новичку» до отчёта и нажать «Продолжить».

Требования к подготовке:

- **Начните не позже вчерашнего дня.** Закрытие занятия ставит его на лестницу
  повторений со сроком через 1 день. Закрытое вчера занятие в день показа уже в «Срочном»,
  и шаг 8 показывается честно, без перевода часов.
- **Одну-две ошибки сделайте нарочно.** Они покажут разные оценки занятий и слабое
  место на профиле.
- **Один раз запустите код-задание.** Pyodide грузится при первом запуске несколько
  секунд, потом он закэширован браузером.
- Роль админа выдайте одной командой (она меняет только аккаунт Б):

```bash
uv run python -m llm_tutor.web.cli make-admin --email <почта аккаунта Б>
```

Ключи к вопросам, чтобы знать, где отвечать неверно, а где верно (только читает seed):

```bash
python3 -c "
import json
d=json.load(open('data/demo/seed_topic01.json'))
for i in d['items']:
    if i['answer_type']=='choice':
        print(i['id'], i.get('section','итог'), '|', i['prompt'][:60], '| верно:', i['options'][int(i['answer'])][:60])
"
```

Тексты вопросов выводятся с id задания: тот же id вы увидите в ленте `watch`.

### 2.3. Аккаунт А

Регистрироваться на подготовке не нужно: на показе это первый шаг. Достаточно придумать
почту и пароль.

## 3. За 10 минут до показа

| Проверка | Как |
|---|---|
| Сервер отвечает, модель жива | войти под Б, открыть занятие, написать в чат «привет»: должен прийти ответ |
| Повторение Б просрочено | вкладка «Повторение»: в блоке «Срочное» есть занятия; или `sc --email <Б> review` |
| Проект Б открыт | `sc --email <Б> project` показывает «проект можно выбрать» или уже начатый |
| Pyodide работает | запустить код в любом код-задании Б |
| Терминалы с одной рабочей папкой | `pwd` в каждом, `ls data/users/*/` показывает папки учеников |
| Экран очищен | закрыть чужие вкладки и почту; уведомления выключить |

## 4. Раскладка экрана

```
+--------------------------------+-----------------------------------+
| Браузер                        | Терминал 1: sc --email <А> watch  |
| http://127.0.0.1:8000          | живая лента записей в базу        |
| (аккаунт А; Б во втором окне   +-----------------------------------+
|  браузера или в приватном)     | Терминал 2: команды шагов         |
|                                | sc context / mastery / explain    |
+--------------------------------+-----------------------------------+
```

- `watch` держите открытым весь показ. Нажали кнопку, через секунду справа появились
  строки: реплики, `events`, пересчёт α/β, состояние занятия, расписание.
- Аккаунт Б держите в **другом окне браузера или в приватном**, иначе сессии
  перепутаются.
- Ответ модели идёт 3-15 секунд, «Объясни новичку» дольше: работают две модели подряд.
  Пока ждёте, показывайте экран `watch`: в нём видно, что происходит.

## 5. План показа

| # | Шаг | Кто | Время | Что показываем |
|---|---|---|---|---|
| 1 | Регистрация и запись | А | 1 мин | у каждого ученика свой файл базы |
| 2 | Анкета | А | 2 мин | самооценка = слабое свидетельство, вес 0.3 |
| 3 | Контекст тьютора | А | 2 мин | из чего собирается промпт, модель ничего не помнит |
| 4 | Ответ на задание | А | 3 мин | вердикт даёт код, оценка пересчитывается, второй вопрос |
| 5 | «Не понял» и фрагмент | А | 2 мин | лестница подсказок, события нет |
| 6 | Закрытие занятия | А | 2 мин | закрывает код, занятие встаёт на лестницу повторений |
| 7 | «Объясни новичку» | А | 4 мин | у новичка нет эталона, оценщик с цитатами |
| 8 | Повторение | Б | 2 мин | лестница 1-3-7-14-30-60, ответ как свидетельство |
| 9 | Проект | Б | 4 мин | разговор вместо форм, страж чисел, отказ писать код |
| 10 | Админка | Б | 1 мин | админка считает теми же функциями ядра |

Всего около 23 минут. Для короткого показа (12 минут) оставьте шаги 4, 6, 7, 9.

## Шаг 1. Регистрация и запись на курс

**Нажать (браузер, аккаунт А):**

1. `/register`: почта, пароль, имя.
2. Главная: карточка курса «Деревья решений и случайный лес», **Записаться**.

**Терминал 2:**

```bash
ls data/users/*/
```

Рядом с папками других учеников появится новая, `data/users/<id>/trees-demo.sqlite3`.

**Сказать:** «У каждого ученика свой файл SQLite на каждый курс. В схеме курса нет
`user_id`: ученика задаёт сам файл. Общая только база аккаунтов: почты, хеши паролей,
сессии, записи на курсы. Журнал `events` в файле ученика источник истины, всё остальное
считается из него».

Узнать `<id>` ученика:

```bash
uv run python -m sqlite3 data/accounts.sqlite3 "SELECT id, email FROM users WHERE email='<почта А>'"
```

**Не запускайте** `sc students` на экране: он перечисляет всех настоящих учеников
из базы. Везде ниже стоит `--email`.

## Шаг 2. Анкета: слабый априор

**Терминал 1 (запустить до анкеты):**

```bash
sc --email <А> watch
```

**Нажать:** на странице курса пройти анкету. Уровень «Немного обучал модели» и **разные**
ответы по блокам:

- «Деревья решений»: «С подсказками»
- «Переобучение и настройка дерева»: «Знаю в теории»
- «Бэггинг и случайный лес»: «Впервые вижу»

**Увидите в `watch`** (числа у вас будут свои):

```
events  <занятие> · self · верно (result 0.65) · вес 0.30
events  <занятие> · self · неверно (result 0.3) · вес 0.30
events  <занятие> · self · неверно (result 0.0) · вес 0.30
mastery <занятие>: α 1.00→1.20, β 1.00→1.10, оценка 0.50 → 0.52
state   создано: занятие tree_criteria, раздел idea
```

**Затем:**

```bash
sc --email <А> mastery
```

Таблица оценок по пяти занятиям: у блоков с разной самооценкой оценки разошлись.

**Сказать:** «Самооценка - свидетельство с весом 0.3. Она не закрывает занятие. Метка
„Уверенно“ ставит занятию значок „проверим“, и его проходят проверочным проходом без
подсказок».

## Шаг 3. Из чего собирается контекст тьютора

**Нажать:** открыть первое занятие «Дерево решений и критерии разбиения», раздел
«Дерево как цепочка правил».

**Терминал 2:**

```bash
sc --email <А> context                                              # блоки, по 6 строк
sc --email <А> context --text "Чем энтропия отличается от Джини?" --full
```

**Увидите:** системный промпт, разрезанный на блоки, с размером каждого: кто ты и
модуль, правила материала, как говорить и вести диалог, лестница подсказок, маршрут,
контракт JSON, профиль по анкете, состояние занятия, срез модели ученика, оглавление
занятия, конспект **только текущего раздела**, хвост диалога, вопрос ученика.

**Сказать:** «Модель ничего не помнит между вызовами. Каждый ход контекст собирается
заново из базы. Самый большой блок это проверенный конспект раздела: модель объясняет
по нему, а не по памяти. Команда не вызывает модель, она показывает то, что ушло бы в
запрос».

## Шаг 4. Ответ на задание и пересчёт оценки

**Нажать:**

1. **Дальше** по частям объяснения до кнопки **Проверим**.
2. Ответить на первый вопрос раздела **неверно** (какой вариант неверный, смотрите по
   ключам из п. 2.2).
3. Затем на следующий вопрос раздела верно.

**Следить за терминалом 1.** Ожидаемая картина (формат реальный, значения свои):

```
реплика ученика   <выбранный вариант>
реплика тьютора   Не совсем: верный вариант ...
events  <занятие> · checked · задание <id> · неверно (result 0.0) · вес 1.00
mastery <занятие>: α ..., β ..., оценка 0.52 -> 0.36
state   pending_item_id: <id> -> <id>        <- следующий вопрос того же раздела
state   check_misses: 0 -> 1
-------------------------------------------------------
реплика тьютора   Верно ... Раздел «Дерево как цепочка правил» пройден
events  <занятие> · checked · задание <id> · верно (result 1.0) · вес 1.00
mastery ... оценка 0.36 -> 0.51
state   section_id: 'idea' -> 'entropy'
```

**Терминал 2:**

```bash
sc --email <А> mastery --node tree_criteria
```

Пересчёт α/β по журналу, событие за событием.

**Сказать:** «Вердикт дал код: вариант проверяет `autocheck`, код ученика тесты в
браузере, модель здесь не участвовала. Ход это один коммит: реплики, событие, α/β,
состояние. Оценка равна α/(α+β). Вес свидетельства: тесты и выбор 1.0, открытый ответ
по рубрике 0.5, анкета 0.3. Между ходами α чуть уменьшается: это забывание к
Beta(1,1), λ = 0.05 в сутки».

## Шаг 5. «Не понял» и лестница подсказок

**Нажать:** в чате урока написать «не понял, объясни подробнее». Модель ответит своими
словами, это нормально.

**Увидите в `watch`:**

```
реплика ученика   не понял, объясни подробнее
реплика тьютора   ...
state   mode: None -> 'reinforce'
state   hint_level: 0 -> 1
state   task_hinted: False -> True
```

Строки `events` нет.

**Сказать:** «Просьба о помощи не свидетельство незнания. Уровень подсказки выбирает
модель, но код не даёт подняться больше чем на 1 за ход: иначе один ответ модели выдал
бы готовое решение».

**Плюс:** выделить фрагмент конспекта мышью, в панели над выделением **Объясни проще**.
В ленте у реплики ученика будет `meta={"quote": …}`: цитата уходит модели как данные, а
намерение разбирается только по самому вопросу.

## Шаг 6. Закрытие занятия: задание «Объясни новичку»

**Нажать:** ответить на вопросы разделов «Энтропия и прирост информации» и «Критерий
Джини», затем на итоговое код-задание (Pyodide, первый запуск несколько секунд).

**Увидите в `watch` одним ходом:**

```
реплика тьютора   Верно ... Занятие «Дерево решений и критерии разбиения» закрыто
events  ... · autotest · задание <id> · верно (result 1.0) · вес 1.00
mastery ... оценка ... -> ...
state   current_node_id: 'tree_criteria' -> 'tree_building'
маршрут Дерево решений и критерии разбиения: current -> closed
review_schedule  ...: ступень - -> 0, срок через 1.0 дн
explain novice   <первая реплика новичка>
explain_sessions #1: active
```

В браузере открывается вкладка **Объясни**, остальные закрыты («откроется после
объяснения»).

**Сказать:** «Закрывает занятие код: пройдены все разделы и итоговое, вторая ошибка
даёт слабое место. Оценка при этом может быть ниже порога 0.75: закрывает прохождение
разделов, а не оценка. Закрытие сразу ставит занятие на лестницу повторений. Занятие
важное, поэтому до следующего ученик объясняет его новичку».

## Шаг 7. «Объясни новичку»

**Терминал 2 (до первой реплики):**

```bash
sc --email <А> explain                                             # висит задание
sc --email <А> explain --reference tree_criteria                   # эталон занятия
sc --email <А> context --role novice    --text "дерево - это вопросы"
sc --email <А> context --role evaluator --text "дерево - это вопросы"
```

**Увидите:** задание висит, эталон занятия (идеи, обязательные, загвоздки) и две
проверки: «Эталона в сообщениях новичка нет: проверено», «Эталон в сообщениях оценщика:
есть».

**Нажать:**

1. Попробовать кнопку **Дальше** или вкладку **Повторение**: сервер отвечает 409
   «Сначала объясни новичку».
2. Объяснить новичку 2-4 репликами. Первую сделать **неполной** («дерево - это вопросы
   по признакам»), потом рассказать про энтропию и прирост информации.
3. Один раз задать вопрос **наставнику** в чате справа.
4. Когда сессия закончится: отчёт и **Продолжить**.

**В `watch` видно** (ответы новичка и наставника у модели свои):

```
explain student: дерево - это вопросы по признакам
explain novice:  ...            [установка ask]
explain_sessions #1: active · покрытие: tree_rules=partial
--------
explain student: вопрос в узле, ответ в листе ...
explain novice:  ...            [установка pitfall]     <- подброшенная загвоздка
explain_sessions #1: active · покрытие: tree_rules=correct
--------
explain student: Как дерево выбирает вопрос?            <- вопрос наставнику
explain mentor:  ...
explain_sessions #1: finished · покрытие: tree_rules=correct, split_criterion=correct
events  ... · explain · верно (result 1.0) · вес 0.30
```

**После отчёта:**

```bash
sc --email <А> explain
```

Покрытие идей с дословными цитатами, реплики с установками новичку, события с
`source = explain`.

**Сказать:** «Новичок физически не знает ответа: эталона в его сообщениях нет, это
проверяется тестом. Судит скрытый оценщик, но „верно“ засчитывается, только если его
цитата дословно есть в реплике ученика. Что сказать новичку на этот ход, выбирает код:
7 установок по приоритету, среди них подброшенная загвоздка. Это закрепление, не
экзамен: вес 0.3, занятие оно не закрывает и не переоткрывает. Ошибка в объяснении
отправляет занятие в повторение на завтра».

## Шаг 8. Повторение (аккаунт Б)

**Нажать (окно с аккаунтом Б):** вкладка **Повторение**. Блок **Срочное** показывает
занятия, у которых срок наступил (закрыты накануне). Ответить на вопрос **верно**, на
следующий, если есть, **неверно**.

**Терминал 1 переключить на Б:**

```bash
sc --email <Б> watch
sc --email <Б> review          # терминал 2: лестница и сроки
```

**Увидите:**

```
занятие                              лестница  ступень  интервал  срок
Дерево решений и критерии разбиения  ◉○○○○○    0        1 дн      ... (просрочено ...)

Что попадёт в повторение прямо сейчас
  1. Дерево решений и критерии разбиения  разминка · «Срочное»
```

В `watch` после верного ответа: `review_schedule ...: ступень 0 -> 1, срок через 3.0 дн`.
После неверного: `ступень 1 -> 0, срок через 1.0 дн` и `mastery ... оценка падает`.

Блок **Освежить** на той же вкладке: выбрать занятия, которые ещё не просрочены, и
повторить их сейчас. Верный ответ по непросроченной строке расписание не меняет:
освежить интервал не сокращает.

**Сказать:** «Лестница 1-3-7-14-30-60 дней. Верно в срок: ступень вверх. Ошибка: две
вниз и завтра. Ответ повторения это обычное свидетельство в журнале, поэтому забытое
занятие возвращается в маршрут само. Просрочка занятие не переоткрывает, переоткрывают
два провала. Разминка из 1-2 вопросов встаёт на границе занятий».

## Шаг 9. Проект (аккаунт Б)

Проект открывается, когда пройден весь курс. Описаний два (`data/demo/project.json`):
«Отток клиентов: дерево против леса» и «Своя задача для деревьев».

**Терминал 2:**

```bash
sc --email <Б> project             # проект доступен / уже начат, карточка, этапы
```

### Как устроена страница

```
 Заголовок проекта                                  [К проектам] [Начать заново]
 Идея | Данные и анализ | Базовая модель | Улучшения | Выводы      полоса этапов
 +-----------------------------------------+------------------------------------+
 | ЧАТ С НАСТАВНИКОМ (слева, около 62 %)    | СВОДКА (справа, около 38 %)         |
 | реплики; под репликой наставника        | Карточка проекта (текстом)          |
 | карточка предложения с кнопками         |   [Изменить] [Утвердить идею]       |
 | [Подвести итог этапа]                   | Сейчас: цель и чек-лист этапа       |
 | поле ввода                              |   [Записать итог самому]            |
 |                                         | Пройденные этапы (раскрываются)     |
 +-----------------------------------------+------------------------------------+
```

Формы по умолчанию нет: поля показываются только в двух окнах: «Изменить» (карточка) и
«Поправить» или «Записать итог самому» (итог этапа).

### Сценарий

| # | Нажать или написать | Что видно | Что сказать |
|---|---|---|---|
| 1 | **Проект** → выбрать «Отток клиентов: дерево против леса» | чат пуст, справа карточка с пустыми строками | выбор описания создаёт проект в статусе idea |
| 2 | Написать «Хочу про отток, но не знаю, с чего начать» | в чате карточка предложения: название, задача, данные, метрика | наставник предлагает формулировки, карточку меняет только ученик |
| 3 | **Взять в карточку**, затем справа **Утвердить идею** | полоса этапов: активен «Данные и анализ» | значения берутся из сохранённой реплики, а не из запроса браузера |
| 4 | Написать, что сделал, **с цифрами**; **Подвести итог этапа** | итог этапа его словами, кнопки **Подтвердить и дальше** и **Поправить** | итог - пересказ слов ученика, наставник заметок сам не пишет |
| 5 | **Подтвердить и дальше** | этап закрыт, полоса сдвинулась, итог ушёл в свёрнутый блок справа | заметки и переход этапа пишутся одним коммитом |
| 6 | В итоге следующего этапа попросить назвать цифру, которой ученик не говорил | поле с этой цифрой выброшено, **Подтвердить** открывает окно **Поправить** | страж чисел: модель не досочиняет метрику |
| 7 | Написать «Напиши мне весь код модели целиком» | отказ и предложение следующего шага | блок кода длиннее 8 строк отклоняется, повтор со строгой установкой, затем запасная реплика |

Модель отвечает по-разному: если в пункте 6 она не подсунула лишнюю цифру, пропустите
его и проговорите защиту словами.

**В `watch`:**

```
projects #1: idea  | этап None | карточка: нет
project mentor: ...  [предложение: title, problem, data, success]
projects #1: build | этап data | карточка: title, problem, data, success
project mentor: Вот итог этапа ...  [предложение: done, findings]
projects #1: build | этап baseline | выполнены ['data']
project student: Напиши мне весь код модели целиком
project mentor: Давай по шагам ... готового решения я не даю
```

**После сценария:**

```bash
sc --email <Б> project                     # карточка, этапы, обязательные заметки, чат
sc --email <Б> context --role project      # что видит наставник
```

### Если модель недоступна

Чат ответит ошибкой, но этап закрывается без модели: **Записать итог самому**,
заполнить обязательные поля, **Сохранить и дальше**. Проект не блокируется.

**Сказать в заключение:** «Это разговор, а не формы: наставник предлагает карточку и
итог каждого этапа, ученик подтверждает или правит. Готового решения наставник не
пишет: промпт просит, а держит код. Код и данные проекта живут вне платформы, в журнал
оценок проект не пишет. Защита у преподавателя и настройки проекта в админке:
следующий шаг».

## Шаг 10. Админка (аккаунт Б)

**Нажать:** войти под Б (он админ) и открыть `/admin/students/<id аккаунта А>` по
прямой ссылке (id из шага 1).

**Не открывайте** список `/admin/students` на проекторе: в нём все настоящие ученики.

**Сказать:** «Админка не считает ничего своего: прогресс и статусы это те же функции
ядра, ответы из журнала. Диалоги не показываются, сессии „Объясни новичку“ только если
ученик разрешил».

## Шпаргалка команд

Все команды только читают базы. Учеников несколько, поэтому всегда `--email`.
Курс по умолчанию `trees-demo`.

| Команда | Что показывает |
|---|---|
| `sc --email X watch` | живая лента: реплики, `events`, α/β, состояние, маршрут, расписание, explain, проект |
| `sc --email X context [--text …] [--full]` | контекст тьютора, разрезанный на блоки с размерами |
| `sc --email X context --role novice\|evaluator\|mentor` | что видят роли «Объясни новичку», есть ли эталон |
| `sc --email X context --role project` | что видит наставник проекта |
| `sc --email X mastery [--all]` | оценка, σ, режим планировщика, статус, ступень повторения |
| `sc --email X mastery --node ID` | пересчёт α/β занятия по журналу, событие за событием |
| `sc --email X review` | лестница, сроки и что повторять прямо сейчас |
| `sc --email X seed-review [--days N]` | завести расписание закрытым занятиям и сдвинуть сроки (пишет в базу, только для показа) |
| `sc --email X explain [--session N]` | задания, сессии, покрытие идей, установки новичку, события |
| `sc --email X explain --reference ID` | эталон занятия: идеи и загвоздки |
| `sc --email X project` | карточка, этапы, обязательные заметки, чат с предложениями |

Id занятий демо-курса: `tree_criteria`, `tree_building`, `tree_tuning`,
`bagging_basics`, `forest`. Цвета выключаются переменной `NO_COLOR=1`.

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `sc` пишет «Нет базы аккаунтов» | терминал открыт не в корне проекта или `.env` указывает не на те пути |
| `У … нет базы курса trees-demo` | ученик не записан на курс: записать в браузере |
| `watch` молчит | не тот `--email`, либо ход ещё не дошёл до сервера |
| Тьютор отвечает «не смог получить ответ» | нет ключа или сети; задания, повторение и закрытие занятий работают и без модели |
| Модель отвечает долго | 3-15 секунд нормально, «Объясни новичку» дольше; пока ждёте, показывайте `watch` |
| Код-задание «висит» | Pyodide не загрузился: проверить интернет и CDN, перезагрузить страницу |
| Урок не идёт, кнопки отвечают 409 | висит «Объясни новичку»: это и есть блокировка, объясните или нажмите «Продолжить» после отчёта |
| Вкладка «Повторение» пуста у Б | занятия закрыты меньше суток назад: используйте блок «Освежить» и скажите об этом вслух |
| Проект в замке | курс пройден не полностью: `sc --email <Б> project` покажет, сколько занятий закрыто |
| Сессии А и Б перепутались | Б откройте в другом окне браузера или в приватном |

## Чего не делать на показе

- Не запускать `sc students` и не открывать `/admin/students`: оба показывают
  настоящих учеников.
- `sc time-travel`, `sc seed-review` и `sc close-module` **пишут** в базу ученика (сдвигают
  сроки, заводят расписание, закрывают занятия без событий). Применяйте только на аккаунте
  для показа и говорите об этом вслух. Быстрый путь к повторению и «Объясни новичку»:
  `sc --email X close-module 1`, затем `sc --email X seed-review`.
- Не запускать `scripts/demo_students.py` и не менять `ACCOUNTS_DB_PATH` и `USERS_DIR`:
  этот сценарий идёт на настоящих базах.
- Не показывать `.env` и не светить ключ в терминале.

Остальные материалы показа: схемы `docs/demo/SCHEMES.html`, справочник докладчика и
запросы к базе `docs/demo/README.md`, прежний сценарий на заготовленных данных
`docs/demo/SHOWCASE.md`.
