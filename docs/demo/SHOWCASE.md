# Показ llm_tutor по шагам на демо-курсе

Сценарий для показа тимлидам на демо-курсе **«Деревья решений и случайный лес»**
(`trees-demo`). Это 5 занятий одного модуля: дерево и критерии разбиения → как
строится дерево → переобучение → бэггинг → случайный лес. Три занятия «важные»
(`tree_criteria`, `bagging_basics`, `forest`): после каждого ученик объясняет его
новичку.

На каждом шаге сначала ход в браузере, потом команда, которая показывает, **что этот
ход сделал внутри**. Видно, из чего собран контекст модели, какие строки легли в
журнал, как пересчиталась оценка, что стало с расписанием повторений и с
«Объясни новичку».

Все команды — `scripts/showcase.py`; по умолчанию он смотрит на демо-курс. Скрипт
читает те же базы, что и сервер, и считает всё функциями самого приложения
(`core.context`, `student.beta`, `student.planner`, `student.explain`…). Модель он не
вызывает.

Диаграммы к шагам — на странице-артефакте «Разбор llm_tutor». Ответы на неудобные
вопросы — `docs/demo/README.md`.

## Как разложить экран

```
┌────────────────────────────┬──────────────────────────────────┐
│ Браузер: приложение        │ Терминал 1: sc watch             │
│ http://127.0.0.1:8000      │ живая лента записей в базу       │
│ курс «Деревья решений      ├──────────────────────────────────┤
│ и случайный лес»           │ Терминал 2: команды шагов        │
│                            │ sc context / mastery / review …  │
└────────────────────────────┴──────────────────────────────────┘
```

`watch` — главный «вау»-эффект. Ученик нажимает кнопку, и через секунду справа
появляются строки `events`, пересчёт α/β, смена состояния занятия, расписания и
«Объясни новичку». Его держат открытым весь показ.

## 0. Подготовка (за день до показа)

```bash
git switch claude/great-pasteur-e8w5ce     # «Объясни новичку» и «Проект» (с демо-курсом) здесь
uv sync
# .env: OPENROUTER_API_KEY — настоящий ключ (урок, чат, новичок, наставник)

# Отдельные базы для показа, чтобы не трогать рабочие:
export ACCOUNTS_DB_PATH=data/showcase/accounts.sqlite3
export USERS_DIR=data/showcase/users
alias sc="uv run python scripts/showcase.py"

uv run python scripts/demo_students.py            # демо-ученики на trees-demo, см. ниже
uv run python -m llm_tutor.web.cli make-admin --email ann@example.com
uv run python -m llm_tutor.web                    # сервер — в терминале с теми же export
```

Что создаёт `demo_students.py` (без ключа модели, через настоящий API; пароль —
`секретный-пароль`):

| Ученик | Состояние |
|---|---|
| **Аня** (`ann@example.com`), анкета «Знаю в теории» | закрыто 2 занятия, «Дерево решений» уже объяснено новичку (2 из 2 обязательных идей), сейчас «Переобучение» |
| **Борис** (`boris@example.com`), анкета «С нуля» | закрыто 1 занятие с ошибками, объяснено, на лестнице повторений ступень 0, сейчас «Как строится дерево» |

Во всех терминалах должны стоять одни и те же `ACCOUNTS_DB_PATH` и `USERS_DIR`, иначе
скрипт и сервер смотрят в разные базы. На сам показ заведи **новую ученицу (Вику)**
прямо в браузере: живой путь от анкеты до объяснения убедительнее готовых данных.

**Материалы RAG у демо-курса свои** — `data/demo/materials.sqlite3`. В репозитории его
нет: без него тьютор опирается на конспект текущего раздела, а в `sc context` будет
«материалы RAG: empty». Чтобы показать и поиск по материалам, собери файл заранее (не
коммить его):

```bash
uv run python -m llm_tutor.course.ingest https://mlcourse.ai/book/topic03/topic03_decision_trees_kNN.html --topic 1 --db data/demo/materials.sqlite3
uv run python -m llm_tutor.course.ingest https://mlcourse.ai/book/topic05/topic5_part1_bagging.html --topic 1 --db data/demo/materials.sqlite3
uv run python -m llm_tutor.course.ingest https://mlcourse.ai/book/topic05/topic5_part2_random_forest.html --topic 1 --db data/demo/materials.sqlite3
```

Проверка за 2 минуты до начала:

```bash
sc students                                  # Аня и Борис, файлы users/<id>/trees-demo.sqlite3
sc --email boris@example.com context | head -5
```

Репетиция без ключа возможна: урок, новичок и наставник ответят «не смог получить
ответ», а всё, что считает код, работает.

**Сделать:** «Дальше ▶️» до «Проверим ✅», затем **неверный** ответ, потом верный.
Следи за терминалом 1. После — `sc --email vika@example.com mastery --node tree_criteria`.

**Увидите в `watch`** (реальный прогон):

```

💬 тьютор Не совсем ✗ — верный вариант: Самый частый класс среди обучающих объектов листа …
📥 events #6 Дерево решений и критерии разбиения · checked · задание 3010 · неверно (result 0.0) · вес 1.00
📈 mastery Дерево решений и критерии разбиения: α 1.20→1.19, β 1.10→2.10, оценка 0.52 ▼ 0.36
🧭 state.pending_item_id: 3010 → 3008          ← второй вопрос того же раздела
🧭 state.check_misses: 0 → 1
────────────────────────────────────────────────────────────────────────
💬 ученик «Если признак a ≤ x и признак b ≤ y — класс 1»
💬 тьютор Верно ✓ ✅ Раздел «Дерево как цепочка правил» пройден — дальше «Энтропия и прирост информации»
📥 events #7 Дерево решений и критерии разбиения · checked · задание 3008 · верно (result 1.0) · вес 1.00
📈 mastery Дерево решений и критерии разбиения: α 1.19→2.19, β 2.10→2.10, оценка 0.36 ▲ 0.51
🧭 state.section_id: 'idea' → 'entropy'
🧭 state.passed_sections: [] → ['idea']
```

α между ходами чуть уменьшается (1.20 → 1.19) — это забывание к Beta(1,1), λ = 0.05/сут.

**`mastery --node`** пересчитывает оценку по журналу, событие за событием:

```
event  источник  задание  ответ    вес   α/β        оценка
1      self               верно    0.30  1.20/1.10  ███████░░░░░░░ 0.52
6      checked   3010     неверно  1.00  1.19/2.10  █████░░░░░░░░░ 0.36
7      checked   3008     верно    1.00  2.19/2.10  ███████░░░░░░░ 0.51
8      autotest  3112     верно    1.00  3.19/2.10  ████████░░░░░░ 0.60   ← код: тесты в браузере
9      checked   3017     верно    1.00  4.19/2.10  █████████░░░░░ 0.67
10     autotest  3122     верно    1.00  5.19/2.10  ██████████░░░░ 0.71   ← итоговое, занятие закрыто
```

**Сказать:** «Вердикт дал код: вариант ответа проверяет `autocheck`, код ученика —
тесты в браузере (Pyodide). Модель здесь не участвовала. Ход — один коммит: реплики,
событие, α/β, состояние занятия, расписание. Оценка = α/(α+β), неопределённость —
ширина Beta. Вес: тесты и выбор — 1.0, открытый ответ по рубрике — 0.5, анкета —
0.3». Номера событий и заданий у вас будут свои.

В таблице `sc mastery` есть колонки «α/β в БД» и «α/β сейчас» (с забыванием λ =
0.05/сут), оценка, σ, режим планировщика и ступень повторения.

## Шаг 5. «Не понял» и лестница подсказок · 1 мин

**Сделать:** в чате урока напиши «не понял, объясни подробнее».

**Увидите в `watch`:**

```
💬 ученик не понял, объясни подробнее
💬 тьютор …Ок, остаёмся на этом узле и разбираемся глубже.
🧭 state.mode: None → 'reinforce'
🧭 state.hint_level: 0 → 1
🧭 state.task_hinted: False → True
```

**Сказать:** «Событий нет: просьба о помощи — не свидетельство незнания. Уровень
подсказки выбирает модель, но код не даёт подняться больше чем на 1 за ход — иначе
один ответ модели выдал бы готовое решение».

**Плюс:** выдели фрагмент конспекта → «Объясни проще». В ленте у реплики ученика будет
`meta={"quote": {"source": "theory", …}}` — цитата идёт модели как данные.

## Шаг 7. «Объясни новичку» · 3 мин

**Сделать** до первой реплики:

```bash
sc --email vika@example.com explain                                   # висит задание
sc --email vika@example.com explain --reference tree_criteria         # эталон занятия
sc --email vika@example.com context --role novice    --text "дерево — это вопросы"
sc --email vika@example.com context --role evaluator --text "дерево — это вопросы"
```

**Увидите:**

```
М1  Дерево решений и критерии разбиения  ▶ висит задание — курс ждёт объяснения
М1  Ансамбли и бэггинг                   · не закрыто
М1  Случайный лес                        · не закрыто

идея             обязат.  текст
tree_rules       да       Дерево решений — цепочка вопросов-порогов по признакам…
split_criterion  да       Разбиение выбирают с наибольшим приростом информации…
gini_entropy              Энтропия и Джини — две меры неоднородности группы…
загвоздка        новичок скажет
leaf_not_pure    «Раз в листе дерева ответ „ушёл“, значит все объекты этого листа ушли?»

━━ Что видит новичок ━━
Эталона в сообщениях новичка нет: проверено ✓
━━ Что видит скрытый оценщик ━━
Эталон в сообщениях оценщика: есть ✓ (по нему он и судит)
```

Попробуй в браузере «Дальше» или «Повторение» — сервер отвечает 409 «Сначала объясни
новичку». Объясни новичку 2–4 репликами. Первую сделай неполной («дерево — это
вопросы по признакам»), потом расскажи про энтропию и прирост информации. Один раз
задай вопрос наставнику справа. В `watch`:

```
🐣 explain student: дерево — это вопросы по признакам
🐣 explain novice: А что такое лист? И как дерево выбирает вопрос?  [установка ask]
🐣 explain_sessions #1: active · покрытие: tree_rules=partial
────
🐣 explain student: вопрос в узле, ответ в листе, объект идёт от корня к листу
🐣 explain novice: …  [установка pitfall]      ← новичок подбрасывает загвоздку про «чистый лист»
🐣 explain_sessions #1: active · покрытие: tree_rules=correct
────
🐣 explain student: Как дерево выбирает, какой вопрос задать?      ← вопрос наставнику
🐣 explain mentor: …
…
🐣 explain_sessions #1: finished · покрытие: tree_rules=correct, split_criterion=correct
📥 events Дерево решений… · explain · верно (result 1.0) · вес 0.30
```

`lesson/next` во время задания — реально `409 {"message": "Сначала объясни новичку «Дерево
решений и критерии разбиения»."}`.

После — `sc --email vika@example.com explain`: покрытие идей с дословными цитатами,
реплики с установками новичку, события `source = explain`. В браузере — отчёт и
«Продолжить» → начинается «Как строится дерево».

**Сказать:** «Новичок физически не знает ответа — эталона в его сообщениях нет, это
видно выше. Судит скрытый оценщик, но correct засчитывается, только если его цитата
дословно есть в реплике ученика. Что сказать новичку на этот ход, выбирает код: 7
установок по приоритету, среди них подброшенная загвоздка. Это закрепление, а не
экзамен: вес 0.3, занятие оно не закрывает и не переоткрывает. Ошибка в объяснении
отправляет занятие в повторение на завтра».

## Шаг 8. Повторение — машина времени · 2 мин

**Сделать** (на Борисе: его «Дерево решений» закрыто и уже объяснено):

```bash
sc --email boris@example.com review                 # лестница и сроки
sc --email boris@example.com time-travel --days 3   # сроки наступили
```

Войди в браузере как Борис → вкладка «Повторение» → «Срочное» → ответь верно. Затем
снова `time-travel` и ответь неверно. Терминал 1 переключи на
`sc --email boris@example.com watch`.

**Увидите:**

```
занятие                              лестница  ступень  интервал  срок
Дерево решений и критерии разбиения  ◉○○○○○    0        1 дн      … (просрочено 2.0 дн)

Что попадёт в повторение прямо сейчас
  1. Дерево решений и критерии разбиения  разминка · «Срочное»
```

В `watch` после ответа: `🔁 review_schedule …: ступень 0 → 1, срок … (через 3.0 дн)`.
После ошибки: `ступень 1 → 0, срок … (через 1.0 дн)` и `📈 mastery … ▼`.

**Сказать:** «Лестница 1-3-7-14-30-60 дней. Верно в срок — ступень вверх, ошибка — две
вниз и завтра. Ответ повторения — обычное свидетельство в журнале, поэтому забытое
занятие само вернётся в маршрут. Разминка из 1–2 вопросов встаёт на границе занятий».

## Шаг 9. Проект · 3 мин

Проект открывается после всего курса — у демо-курса это 5 занятий. Описаний два
(`data/demo/project.json`): «Отток клиентов: дерево против леса» и «Своя задача для
деревьев».

```bash
sc --email ann@example.com project               # замок: «пройдено 2 из 5»
sc --email ann@example.com close-module 1        # пройти курс (только для показа)
sc --email ann@example.com project               # «проект можно выбрать»
sc --email ann@example.com watch                 # в терминале 1
```

После `close-module` у Ани повиснут объяснения «Ансамбли и бэггинг» и «Случайный лес» —
урок встанет, но страница «Проект» работает: она про пройденный курс.

Как Аня: «Проект» → «Отток клиентов: дерево против леса» → «Выбрать». Страница — это
разговор: слева чат с наставником, справа сводка проекта и полоса этапов. Наставнику —
«Хочу про отток, но не знаю, с чего начать» → в чате карточка предложения →
«Взять в карточку» → «Утвердить идею» (справа). Дальше на каждом этапе: расскажи
наставнику словами, что сделал (с цифрами), нажми «Подвести итог этапа» → наставник
присылает **итог этапа твоими словами** → «Подтвердить и дальше». Покажи защиту: если
в итоге есть число, которого ты не называл, это поле выброшено и откроется окно
«Поправить». В конце попроси «Напиши мне весь код модели целиком».

**Увидите в `watch`:**

```
🛠  projects #1: idea · этап None · выполнены [] · карточка: —
🛠  project mentor: …  [предложение: title, problem, data, success]
🛠  projects #1: build · этап data · выполнены [] · карточка: title, problem, data, success
🛠  project mentor: Вот итог этапа…  [предложение: done, findings]
🛠  projects #1: build · этап baseline · выполнены ['data'] · …   ← «Подтвердить и дальше»
🛠  project student: Напиши мне весь код модели целиком
🛠  project mentor: Давай по шагам: … Готового решения я не даю — это твоя работа.
```

Потом `sc --email ann@example.com project` (карточка ✔/✘, этапы с обязательными
заметками) и `sc --email ann@example.com context --role project` (что видит наставник).

**Сказать:** «Проект открывается после всего курса. Это разговор, а не формы: наставник
предлагает карточку и итог каждого этапа, ученик подтверждает. Итог — пересказ слов
ученика, и код выбрасывает цифры, которых ученик не называл. Если модель выдала решение
кодом (блок длиннее 8 строк) — повтор со строгой установкой, потом запасная реплика.
Код и данные проекта — вне платформы, в журнал проект не пишет. Защита у
преподавателя — следующий шаг».

## Шпаргалка команд

| Команда | Что показывает |
|---|---|
| `sc students` | ученики, файлы их баз, число событий и закрытых занятий |
| `sc watch` | живая лента: реплики, `events`, α/β, состояние, маршрут, расписание, explain, проект |
| `sc context [--text …] [--full]` | контекст тьютора, разрезанный на блоки с размерами |
| `sc context --role novice\|evaluator\|mentor` | что видят роли «Объясни новичку» (и есть ли эталон) |
| `sc context --role project` | что видит наставник проекта |
| `sc mastery [--all]` | оценка, σ, режим планировщика, статус, ступень повторения |
| `sc mastery --node ID` | пересчёт α/β занятия по журналу, событие за событием |
| `sc review` | лестница, сроки и что повторять прямо сейчас |
| `sc time-travel --days N [--node ID]` | сдвинуть сроки повторения (только для показа) |
| `sc explain [--session N]` | задания, сессии, покрытие идей, установки новичку, события |
| `sc explain --reference ID` | эталон занятия: идеи и загвоздки |
| `sc project` | карточка, этапы, обязательные заметки, чат с предложениями |
| `sc close-module N…` | закрыть модули в маршруте без событий (только для показа) |

Id занятий демо-курса: `tree_criteria`, `tree_building`, `tree_tuning`,
`bagging_basics`, `forest`. Учеников несколько — добавляй `--email`, другой курс —
`--course mlcourse`. Цвета выключаются переменной `NO_COLOR=1`.

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `Нет базы аккаунтов …` | в терминале нет `export ACCOUNTS_DB_PATH/USERS_DIR`, как у сервера |
| `У … нет базы курса trees-demo` | ученик не записан на демо-курс — запиши в браузере |
| `watch` молчит | смотришь не того ученика (`--email`) или ход не дошёл до сервера |
| тьютор отвечает «не смог получить ответ» | нет ключа или сети; задания, повторение и закрытие работают и без модели |
| урок не идёт, кнопки отвечают 409 | висит «Объясни новичку» — это и есть блокировка: объясни или «Продолжить» после отчёта |
| «Проект» в замке | `sc project` покажет, сколько занятий закрыто; `sc close-module 1` |
